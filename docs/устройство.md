# Устройство Agent Panel

Подробности работы панели для тех, кто её дорабатывает: словарь терминов, правила
цикла рецензии, устройство адаптеров и проверенные основания решений. Краткое
руководство пользователя — в [README](../README.md), история исправлений — в
[история-изменений.md](история-изменений.md).

## Словарь

Одно слово — одно понятие. Эти же объяснения всплывают при наведении на
элементы панели.

| Слово | Что значит |
|---|---|
| **Задача** | сообщение, отправленное режимом «Задача с рецензией». С него начинается цикл |
| **Цикл рецензии** | Claude работает → Codex и Gemini проверяют пару, параллельно и независимо → при замечаниях снова Claude. Кончается принятием, остановкой или решением человека |
| **Проверка** | одна проверка — пара: Codex и, если подключён, Gemini отвечают на одну и ту же работу Claude. Точки справа от статуса — «проверок 1 из 3»: пара посмотрела работу один раз |
| **Пара** | Codex и Gemini одной проверки: получают одинаковый материал, но разные инструкции, и отвечают независимо друг от друга |
| **Сведение** | итог проверки пары — строже из двух вердиктов побеждает: решение человека сильнее замечаний, замечания сильнее приёмки |
| **Не проверял** | Gemini не дал проверки в этот раз: сбой (сетевой — и после повтора), квота, регион, срок ожидания (не уложился после замечаний Codex, замолчал, не закончил за предел, был занят другим ходом) или нет правил «только чтение». Итог проверки — по одному вердикту Codex |
| **Проверки рецензентов** | рецензенты проверяют свои утверждения командами и скриптами. Codex читает репозиторий всегда; с переключателем комнаты он пишет и запускает скрипты в своей папке проверок, а скрипты Gemini (блоки «проверка») выполняет панель |
| **Папка проверок** | папка рецензента вне проекта, `%LOCALAPPDATA%\agent-panel\review\…`: только в неё он может писать |
| **Стоп-сигнал** | команда Codex с запрещённым путём (данные, секреты проекта) в ходе проверки: панель прерывает его ход и останавливает проверку |
| **Предварительный вердикт** | вердикт Gemini в ответе со скриптами — до того, как он увидел их вывод. Итог Gemini в паре — вердикт ответа на вывод |
| **Предел** | сколько проверок разрешено на одну задачу (`agentPanel.maxAutoRounds`); проверка пары считается одной. Не даёт агентам спорить бесконечно за ваши деньги |
| **Вердикт** | итог ответа рецензента последней строкой: «принято», «есть замечания», «нужно решение человека»; «не вынесен» — решаете вы. Итог проверки пары — сведение по обоим вердиктам |
| **Автопересылка** | флажок под полем ввода. Включена — агенты передают работу друг другу сами. Выключена — каждую передачу подтверждаете вы |
| **Ждёт вашего решения** | панель остановила передачу и показывает над полем ввода причину с кнопкой. Ничего не теряется |
| **Режим разрешений** | «без вопросов» — Claude выполняет команды сам; «спрашивать» — действия, требующие согласия, приходят карточкой. Для папки, кнопка со щитом в поле ввода |
| **Запрос разрешения** | Claude хочет выполнить действие, требующее вашего согласия. В беседе появляется карточка с командой, ход стоит до вашего ответа |
| **В этой сессии** | больше не спрашивать про такую команду, пока процесс Claude не остановлен. В файлы настроек ничего не пишется |
| **Эстафета** | статус вверху: огонёк Claude слева, нить раздваивается на Codex и Gemini (если подключён), частицы бегут по ветке, где идёт работа; белый огонёк на стволе — ждут вас |
| **Дорожка цикла** | раскрывается по клику на статус: после каждого хода Claude — ромбы Codex и Gemini с отметкой вердикта (`!` замечания, `?` нужно решение, `✓` принято; пунктирное кольцо цвета Gemini — «не проверял»), пустые ромбы — оставшиеся проверки |
| **Отказ без запроса** | действие отклонено, а спросить вас было нельзя (например, режим `dontAsk`). Панель ждёт вашего решения |
| **Модель** | какая модель агента отвечает. Список берётся у самого агента; «по умолчанию» — выбор его CLI |
| **Уровень рассуждения** | сколько модель думает перед ответом: от «Низкого» до «Максимума», у Codex ещё «Ультра». Выше — дольше и дороже. Выбирается узлом на нити в «Моделях» |
| **Очередь** | сообщения, которые ждут, пока агент закончит текущий ход |
| **Ход** | один ответ агента от получения сообщения до конца, со всеми его действиями |
| **Прервать** | остановить текущий ход. Сессии сохраняются, следующее сообщение их продолжит |
| **Остановить** | завершить процессы всех агентов вместе с запущенными ими командами |
| **Сырой вывод** | точный текст, который вернули команды агента, без пересказа |
| **Диагностика** | служебные логи процессов агентов внизу панели. Не часть разговора |

## Как отправить сообщение

В поле ввода выбирается, **как** отправить: значки переключателя, а название
режима рядом открывает меню. На узкой панели остаётся только меню. Режимов
пять, «Только Gemini» видно, когда найден `agy`.

| Режим | Что происходит |
|---|---|
| **Задача с рецензией** | Claude выполняет, Codex и Gemini проверяют — параллельно и независимо, пара за парой, пока сведение не даст «принято» |
| **Спросить всех** | все агенты отвечают независимо, друг другу ничего не передаётся |
| **Только Claude** / **Только Codex** / **Только Gemini** | прямой вопрос одному, без пересылки |

Режимы разные по смыслу намеренно. В первой версии сообщение уходило обоим
сразу, ответы расходились по времени, и в живом прогоне Claude спорил с
замечанием, которое Codex уже отозвал за пять секунд до этого.

**Проверить коммит просят режимом «Задача с рецензией», а не «Только
Codex».** С 05.10 Codex читает репозиторий сам и `git show` выполнит, но
запусков Claude (тесты, расчёты) он не повторяет — их сырой вывод приносит
Claude. Gemini команд не запускает вовсе. Gemini не видит отзыва Codex: иначе
пропадает независимость второго взгляда.

### Цикл рецензии

```
Claude закончил ─► снимок A ─┬─► Codex:  код                ─┐
                             └─► Gemini: методология, факты  ─┴─► сведение ─► принято / Claude / вы
```

1. Claude получает задачу и работает.
2. Codex и Gemini получают **задачу человека, реплики Claude и сырой вывод его
   инструментов** — один снимок версии, но разные инструкции — и выносят
   вердикт параллельно и независимо. Это одна проверка — пара; счётчик
   проверок (`agentPanel.maxAutoRounds`) растёт на 1 за пару, не за агента.
   Сколько ждать Gemini после ответа Codex, зависит от вердикта Codex — см.
   «Срок ожидания» ниже; не дождались — исход «не проверял».
3. Сведение — строже побеждает:

   | Исход | Когда | Последствие |
   |---|---|---|
   | ждём человека | хоть один рецензент — «нужно решение человека» или без вердикта | панель ждёт вашего решения |
   | есть замечания | иначе хоть у одного — «есть замечания» | Claude получает оба отзыва одним сообщением |
   | принято | иначе | цикл завершён |

**Итог приёмки** (с 05.10). При «принято» Claude отдельного хода не
получает: он правил бы файлы мимо рецензии. Но прежде он не получал ничего —
по журналу 04–05.10 дважды записал ложную «историю приёмки» и потерял
неблокирующие пометки рецензентов. Теперь принятие (сведение пары и путь
одного Codex) запоминает номер проверки и исходы, и первое следующее
сообщение человека, которое уходит Claude (задача, «Только Claude», «Спросить
всех» — там блок получает только Claude), начинается блоком:

```
[итог прошлой проверки]
Проверка 2 принята: Codex — принято, Gemini — принято.
Отзывы рецензентов — пометки без требования исправлять; учти их в истории приёмки:
— Codex: …
— Gemini: …
```

Отзыв — до 4000 знаков, длиннее — начало и конец с пометкой. Gemini «не
проверял» — причина в строке итога, без отзыва. Блок уходит один раз и
забирается, когда сообщение действительно строится: сообщение, снятое новой
задачей, итог не съедает. Прямой вопрос Codex или Gemini его не забирает;
«Остановить» и новая сессия Claude сбрасывают. В ленте — «К сообщению Claude
приложен итог проверки N.»; в журнал человек записан своими словами.

**Исходы проверки Gemini:**

| Исход | Когда |
|---|---|
| вердикт | «принято», «есть замечания» или «нужно решение человека» последней строкой — участвует в сведении. С блоками «проверка» и включёнными проверками — вердикт его ответа на вывод скриптов (см. «Проверки рецензентов») |
| без вердикта | ответил, но последней строки-вердикта нет — ждём человека, как у Codex |
| не проверял | процесс упал, пустой ответ, прирост `denied_actions`, регион, квота, срок ожидания, нет правил «только чтение», сетевой сбой и после повтора — итог по одному вердикту Codex |

Без `agy` пара не собирается — проверяет один Codex, как и раньше.

Цикл кончается **по итогу, а не по счёту**. Предел проверок остаётся
ограничителем расходов.

### Как читается вердикт

Засчитывается только **последняя непустая строка** ответа рецензента, и только
если это ровно `ВЕРДИКТ: ПРИНЯТО`, `ВЕРДИКТ: ЕСТЬ ЗАМЕЧАНИЯ` или
`ВЕРДИКТ: НУЖНО РЕШЕНИЕ ЧЕЛОВЕКА`. Последний рецензент ставит, когда без
вашего решения или данных обмен бессмысленен: панель останавливается, а не
пересылает согласия до предела проверок, как было в прогоне 16 сентября. Допускается
жирный шрифт и точка в конце. Не засчитывается:

- вердикт в цитате (`> ВЕРДИКТ: ПРИНЯТО`) или в блоке кода;
- вердикт не последней строкой — например, «пример формата» посреди ответа;
- похожие слова: `НЕПРИНЯТО`, `ПРИНЯТО ЧАСТИЧНО`;
- вердикт с отступом в четыре пробела или табуляцию — в разметке это код;
- вердикт в обратных кавычках: `` `ВЕРДИКТ: ПРИНЯТО` `` — это пример.

Границы блока кода считаются по правилам разметки: ограда запоминается видом
и длиной, закрывает её только такая же не короче и без текста после. Иначе
пример формата закрывал бы цикл: блок, открытый четырьмя кавычками и
«закрытый» тремя, давал ложное «принято» — пять таких входов нашёл рецензент
в прогоне 16 сентября, и все они в тестах.

Всё это — «вердикт не вынесен», и решение за человеком. Прежний разбор искал
слово в любом месте текста и засчитывал приёмку там, где её не было.

### Когда панель ждёт вашего решения

Передача не уходит, но и не пропадает, если:

| Причина | Кнопка |
|---|---|
| Claude получил отказы без запроса — проверять нечего, работа не сделана | **Повторить Claude** |
| рецензент просит вашего решения | **Отправить Claude** |
| рецензент не вынес вердикт | **Отправить Claude** |
| достигнут предел проверок — работа Claude осталась непроверенной | **Отправить на проверку** (без Gemini — **Отправить Codex**) |
| автопересылка выключена | **Отправить** тому, кому предназначено |

Отказы не уходят на проверку намеренно: в живом прогоне три проверки
потратились на спор рецензента с разработчиком о том, почему заблокирована
команда, — хотя разрешить её мог только человек.

Когда решения просит один рецензент, причина называет исход второго: «Gemini
просит вашего решения; Codex решения не просит (вердикт: принято). Обмен
остановлен. Отзывы можно отправить Claude.» или «…; Codex: есть замечания. …».
Одна строка «Gemini просит вашего решения» не показывала, что Codex работу
принял, — разногласия рецензентов не было видно (журнал 04–05.10). Оба
просят — прежняя строка на двоих. Так и при сведении пары, и когда поздний
Gemini просит решения у удержанных замечаний.

Кнопка удержания («Отправить…», «Повторить Claude») и переключение
автопересылки — действия человека: они пишутся в журнал (см. «Журнал») и
видны в ленте строкой «Вы: …».

Новая задача отменяет пересылки прежней, и панель говорит, сколько
устаревшего не доставлено.

### Режим разрешений

По умолчанию Claude работает **без вопросов** (`bypassPermissions`). Кнопкой
со щитом в поле ввода режим переключается на **спрашивать** — тогда действия,
требующие согласия, приходят карточками. Выбор запоминается для папки.

Режим задаётся флагом запуска и действует со следующего хода. Кнопка
«Больше не спрашивать» на карточке и переключение посреди хода действуют и
сразу: до перезапуска открытые и новые запросы разрешает сама панель —
кроме тех, на которые должен ответить человек (см. «Вопрос Claude»). Так
сделано по пробе на Claude Code 2.1.220: ответ с `setMode bypassPermissions`
повторных запросов в идущей сессии не отключил. Режим `auto` через флаг не
включился — сессия сообщила `default`, — поэтому в переключателе его нет.

«В этой сессии» разрешает только **ту же команду целиком**: в
прогоне 16 сентября Claude Code предлагал правилом всю строку команды, без
`*`, и следующий `git show` другого файла снова спрашивал.

Codex режим не касается: его ветка работает в песочнице «только чтение», а с
проверками рецензентов Codex пишет только в свою папку проверок. Gemini режим
тоже не касается: запись файлов и команды ему запрещены правилами `agy`.

### Запрос разрешения

Когда Claude нужно ваше согласие, в беседе появляется карточка: инструмент,
команда целиком, описание и путь, а статус вверху — «Ждёт разрешения».

| Кнопка | Что уходит Claude |
|---|---|
| **Разрешить** | этот вызов, один раз |
| **В этой сессии** | этот вызов и правило команды (видно при наведении) до остановки Claude |
| **Больше не спрашивать** | этот вызов, и режим «без вопросов» для папки |
| **Отклонить** | отказ с пометкой, что отказал человек |

«В этой сессии» передаёт только правило команды. Claude предлагает записать
его в `.claude/settings.local.json` и заодно включить приёмку всех правок —
панель не делает ни того, ни другого.

Отказ, данный вами, — решение, а не блокировка: работа идёт дальше и
уходит на проверку как обычно. «Прервать» и «Остановить» закрывают открытые
карточки. Каждый запрос и решение записываются в журнал.

### Вопрос Claude

Claude Code спрашивает человека инструментом `AskUserQuestion`: CLI присылает
его запросом `can_use_tool` с `requires_user_interaction` — и в режиме
`bypassPermissions`. До 05.10 панель сама отвечала на него «разрешить» с
прежним вводом: Claude получал «The user did not answer the questions», а
человек вопроса не видел (журнал 04–05.10). Теперь:

- запросы, на которые должен ответить человек (`AskUserQuestion` и любой
  запрос с `requires_user_interaction`), режим не разрешает — ни флагом, ни
  переключением на «без вопросов» посреди хода;
- `AskUserQuestion` приходит карточкой «Claude спрашивает»: по каждому
  вопросу варианты (при `multiSelect` — флажки) и поле «Свой ответ», которое
  важнее вариантов (несколько выбранных — через «, »). «Ответить» доступна,
  когда ответ есть на каждый вопрос. Ответ уходит, как требует Agent SDK:
  `allow` с `updatedInput` — исходные `questions` и `answers` по исходному
  тексту вопроса (длинные строки в карточке обрезаются, ключ ответа — нет). В
  ленте решение — «ответ человека: <вопрос> — <ответ>»;
- «Не отвечать» — отказ «Человек не стал отвечать на вопрос в панели.»; это
  решение человека, а не отказ без запроса;
- «Разрешить» без ответов и пустой ответ у вопроса не принимаются ни
  адаптером, ни координатором — это и было «did not answer»;
- остальные запросы с `requires_user_interaction` — обычная карточка
  разрешения: `answers` понятны только `AskUserQuestion`. «Больше не
  спрашивать» на такой карточке сначала разрешает свой запрос, затем меняет
  режим — иначе карточка застывала, а ход ждал вечно;
- открытые вопросы координатор считает отдельно от разрешений, и «Эстафета»
  показывает «Ждёт ответа на вопрос»; «Прервать», «Остановить» и падение
  процесса закрывают карточку. Из журнала вопрос показывается текстом без
  кнопок: процесс уже другой, ответить нельзя.

### Ветка рецензента Codex

До 05.10 панель могла продолжать ветку вашего собственного чата Codex (поле
`codex_thread` таблицы `rooms`; проверено 25.09.2026 на ветке с недельной
историей). С 05.10 по решению владельца у рецензента своя ветка на комнату
(`codex_review_thread`, см. «Проверки рецензентов»): ваш чат панель не
продолжает ни при каком пути, а `codex_thread` остаётся в журнале историей.

**Какой codex запускается.** Если установлено расширение ChatGPT для VS Code,
панель берёт его `codex` — тот же, что в вашем чате, с теми же моделями.
CLI из npm может отставать: 25.09 у ветки была сохранена модель `gpt-6-sol`,
CLI 0.153.0 её не знал, и ход падал с «model is not supported when using
Codex with a ChatGPT account», а `codex` 0.155.0-alpha.16 из расширения ту же
ветку продолжил. Явный путь в `agentPanel.codexCommand` важнее.

**Какой claude запускается.** Так же: если установлено расширение Claude Code
для VS Code, панель берёт его `resources/native-binary/claude.exe` — ту же
версию, что у вашего чата; расширение обновляется само, и панель подхватывает
новую версию при следующем открытии комнаты. 28.09 claude 2.1.220 из npm не
принял сессию на `claude-opus-5-5` («API Error: 400 … does not support this
model; version 2.1.280»), а 2.1.280 из расширения — принял. Явный путь в
`agentPanel.claudeCommand` важнее; без расширения — `claude` из PATH.

Модель, выбранная в «Моделях», передаётся в каждый ход Codex и остаётся у
ветки.

### Память по теме

Если задана `agentPanel.memorySearchCommand`, к каждому сообщению человека
панель прикладывает заметки памяти проекта, найденные по его словам, — обоим
агентам и рецензенту вместе с задачей. В беседе появляется строка «Память: к
сообщению приложены заметки (N): …» — видно, что именно получили агенты.
Заметки идут после слов человека с пояснением «это не слова человека, а
справка». Сообщение ждёт поиска не дольше 10 с (обычно 1–3 с); сбой или срок
называются строкой «Поиск по памяти не удался», и сообщение уходит без
заметок. Если во время поиска нажать «Остановить», сообщение не уходит, и
панель это пишет. Вывод команды читается как UTF-8.

Протокол команды — как у хука `UserPromptSubmit` Claude Code: JSON `{cwd,
prompt}` на вход, `hookSpecificOutput.additionalContext` на выход. Поэтому
один поиск служит и вашим сессиям Claude, и панели; например
`python C:/Users/<вы>/.claude/hooks/memory_search.py` (qmd по основам слов, с
обновлением индекса перед поиском).

Зачем. Claude в панели запускается без ваших пользовательских настроек (см.
«Как устроено»), значит без ваших хуков памяти и MCP-серверов; у Codex их нет
вовсе. Проверено 28.09.2026: в `init` Claude панели только connector
claude.ai. Самому искать в памяти Claude панели можно дать через
`agentPanel.claudeMcpConfig` — JSON с сервером qmd, как у `claude --mcp-config`;
с ним в `init` появляется `qmd: connected` и инструменты `mcp__qmd__*`.

### Модель и уровень рассуждения

Кнопка **Модели** в поле ввода открывает одну карточку: строка на агента —
Claude, Codex и, если найден `agy`, Gemini. В строке: имя цветом агента,
модель — списком, уровень рассуждения — узлом на короткой нити. Название
уровня не подписано рядом — оно видно при наведении на узел; пояснений вида
«сколько уровней» в карточке нет. Сводка текущего выбора — в подсказке
кнопки и строки.

Нить показывает уровень формой, а не подписью; определения из документации
Anthropic и OpenAI — в подсказке каждого узла. Чем выше уровень, тем больше и
быстрее частицы; «Максимум» — нить толще и двойное кольцо (вся глубина в одном
рассуждении); «Ультра» у Codex — нить ветвится на три ветки с огоньками
субагентов. Чёрточка под узлом — умолчание модели, если его сообщил каталог.
Claude своего умолчания не сообщает, и тогда ни один узел не выбран: уровень
решает сам агент. Узел Ultracode не показывается: у `claude -p` (2.1.220)
флага для него нет, `--effort` принимает только low … max. У Gemini уровень
зашит в имя модели (`-low`, `-medium`, `-high`): у семейства Flash три узла, у
Pro — два; «Ультра» у Gemini нет. Кнопка сброса уровня к умолчанию (`↺`) — у
каждой строки своя.

Список берётся у самих агентов: Claude отдаёт его в
ответе на `initialize`, Codex — в `model/list`, Gemini — в `agy models`
(только модели `gemini-*`: модели Claude и GPT из каталога `agy` в карточку
Gemini не попадают). Для этого на пару секунд поднимается отдельный процесс;
рабочая сессия не создаётся, модель не вызывается. Запрашивается только при
первом открытии.

Выбор действует **со следующего хода** и запоминается для папки. Claude
перезапускается между ходами с `--resume --model --effort` — контекст сессии
сохраняется. Codex получает `model` и `effort` в `turn/start`; при возврате к
«по умолчанию» модель называется явно, иначе ветка осталась бы на прежней.
Gemini — как Claude: процесс перезапускается между ходами с `--model`.
Смена записывается в беседу и журнал: видно, какая модель дала какой ответ.

## Gemini (agy)

Второй рецензент в каждой проверке — параллельно с Codex и независимо от
него: проверяет методологию эксперимента чек-листом (утечки, разбиения,
регистрация, метрики и статистика, бейзлайн, сиды и разброс, обоснованность
выводов; у каждого пункта — «свидетельство», «пробел» или «не относится») и
факты вне репозитория по вебу, с адресом страницы и датой проверки у каждого
факта. Полного второго взгляда на код нет — это дублировало бы Codex и
тратило бы квоту без вопроса: Gemini читает только строки, от которых
зависит методология. Gemini не видит отзыва Codex: иначе пропадает
независимость.

**Протокол.** Один процесс на всю сессию комнаты, много ходов подряд:

```
agy -p="" --agent agent-panel-reviewer --input-format stream-json --output-format stream-json [--model M] [--conversation ID]
```

Ход — строка `{"event":"user","message":{"content":"…"}}` в stdin.

**Сообщение** (`formatForGemini`, `src/adapters/gemini.ts`) начинается
шапкой:

```
[материал проверки от панели]          (или [от человека], [от панели])
[папка проекта: … — ищи и читай файлы только в ней]
[правила проекта: GEMINI.md]           (иначе AGENTS.md; нет обоих — строки нет)
[дата: 2026-10-03]
[версия файлов: …]                     (если снят отпечаток)
```

Строка правил — в каждом сообщении, и в прямом вопросе: файл ищется в
корне папки проекта. 04.10 в продолженном разговоре Gemini не счёл прямое
сообщение «началом разговора» и `GEMINI.md` не открыл. Дата — по часам
машины (не UTC): из неё Gemini берёт дату проверки внешних
фактов. Без неё дату называла сама модель: в проверке Trading (20:02 UTC
02.10, по часам машины уже 03.10) — «проверено 2026-10-03» без источника в
сообщении. К материалу проверки координатор добавляет
`GEMINI_FOCUS` — короткое напоминание роли: открыть файл из строки
«[правила проекта: …]», если в этом разговоре он ещё не открыт, чек-лист,
бюджет веба, правило вердикта.

**Разбор потока** в общую модель событий панели (`src/adapters/types.ts`):

| `agy` | Событие панели |
|---|---|
| `init` | id разговора → журнал; модель и режим → диагностика |
| `step_update` `user_input` | `turn_started` |
| `agent_response` с `text_delta` | `text_delta`; на `DONE` — собранный текст |
| `tool` `ACTIVE` | `tool_call` / `tool_running` |
| `tool` `DONE` / `ERROR` | `tool_result` (у Gemini — краткая сводка, не сырой вывод); `ERROR` с «permission check failed» — отказ |
| `result` | `turn_completed`: расход — сумма `usage` шагов `agent_response` хода (не разность накопительного `usage` у `result` — он после `--conversation` включает расход прежнего процесса); `failed`, если статус не `SUCCESS` и ответа нет. Не `SUCCESS` при непустом ответе (04.10: `ERROR` «API error (attempt 2): … EOF» после полного ответа с вердиктом) — ход состоялся: реплика, ошибка — в диагностике («agy сообщил об ошибке после ответа: …»), в тексте конца хода и в отметке `lateError`; по ней лента показывает уведомление цвета «внимание», журнал хранит её в колонке `late_error` |
| пустой ответ (с приростом `denied_actions` или без него) | «проверка неполная» → исход «не проверял»; прирост `denied_actions` при непустом ответе сам по себе исход не меняет — отказы видны в `denials` (M8) |
| stderr `AGY_ERROR: {…}`, «Eligibility check failed», дневной предел | `error` с причиной словами |

**Только чтение.** Перед КАЖДЫМ ходом (не только перед первым запуском
процесса — I2, финальная рецензия 02.10: разговор возобновляемый, и правила
могли пропасть между ходами) панель читает общие настройки agy
(`~/.gemini/antigravity-cli/settings.json`):

```json
"permissions": { "allow": ["read_url(*)"], "deny": ["write_file(*)", "command(*)"] }
```

Правил нет (или JSON не разбирается) — Gemini не запускается (если процесс
уже был живым на прежнем ходу, он останавливается): исход «не проверял»,
цикл идёт с одним Codex, а над полем ввода — плашка «Gemini нужен режим
только чтения» с кнопкой «Добавить правила» (дописывает недостающее, сохраняя
остальное содержимое, без повторов; нестандартный `toolPermission`, если он
был, тоже снимается — иначе Gemini не смог бы читать файлы). Без нажатия
панель файл не меняет. Правила общие для всего `agy`, в том числе
интерактивного. Появление и исчезновение плашки видно без переоткрытия
панели: правила проверяются на каждом ходу, и смена состояния обновляет её
сама.

**`agent.md`.** Роль рецензента — системная инструкция в
`~/.gemini/config/agents/agent-panel-reviewer/agent.md`. Файл принадлежит
панели: она переписывает его перед запуском Gemini, если текст в коде
изменился. Тело роли (`reviewerAgentMarkdown`, `src/geminiSetup.ts`) — три
раздела:

- «Правила проекта»: файл правил — из строки «[правила проекта: …]» шапки
  (без неё — `GEMINI.md` из корня папки проекта, иначе `AGENTS.md`). Если в
  этом разговоре Gemini его ещё не открывал, он открывает его до ответа на
  любое сообщение — и на проверку, и на прямой вопрос человека: правило
  зависит от состояния разговора, а не от места в нём (04.10). Исследовательские
  правила `AGENTS.md` относятся к Gemini полностью, запись, запуск, коммиты и
  передача работы — нет; перечитать, если материал показывает, что файл
  изменился. С `excludeDefaultComponents: true` `agy` правил проекта сам не
  подаёт, а ключ `rules:` в `agent.md` молча игнорирует (проба 04.10),
  поэтому роль велит открыть их явно. При расхождении действует роль,
  запреты проекта соблюдаются. Читать только папку проекта
  и сохранённые копии своих страниц (`~/.gemini/antigravity-cli/brain/…`),
  секретов не открывать. Свидетельство — только из файла, открытого в этом
  ответе, или из материала.
- «Что проверяешь»: чек-лист и признаки ошибок, которые в Trading ловил
  Codex, — известность на дату решения, будущая информация в отборе, смещение
  выживших, план до расчёта, статистика записанной гипотезы, неизвестное ≠
  нуль, полнота отрицательного поиска, сценарии ≠ границы, совпадение ≠
  причина, косвенная мера ≠ механизм, вывод не шире измеренного, типы
  свидетельств. Полноту отрицательного поиска показывает разработчик
  (источники, даты, все страницы выдачи, цитата): проверки в коде
  подтверждают, что свидетельство есть и не изменилось, а не что поиск полон;
  не показано — пробел (04.10). Факты — первоисточник, только названные
  разработчиком, дата из шапки. Факт, на котором держится вывод, — тот, от
  которого зависят правило, окно дат, список источников, порог или вывод;
  список источников отрицательного поиска — всегда такой. Бюджет веба
  (`WEB_BUDGET`) счётный: 15 вызовов `search_web` и `read_url_content`,
  дальше «не проверено: бюджет исчерпан». С 05.10 в конце раздела — правило
  блока «проверка»: утверждение, которое проверяется вычислением над кодом,
  синтетикой или числами из материала, Gemini подкрепляет скриптом (не
  больше трёх блоков); данные проекта, секреты и сеть в скриптах запрещены.
  Если материал проверки говорит, что проверки рецензентов выключены, блоков
  он не пишет (см. «Проверки рецензентов»).
- «Как заканчиваешь»: правила вердикта — только к материалу проверки; на
  прямое сообщение человека — ответ на сам вопрос, без строки вердикта.
  Правило вердикта (I1), записанное в плане ограничение при оговорённом
  выводе — не пробел, последняя строка.

Тело идёт в каждый вызов модели, поэтому оно не длиннее 9 000 символов
(тест); сейчас ≈7 900.

Список `tools` заголовка YAML набор инструментов в `init` не
меняет (проба показала это), но, судя по пробе `--deny-check` (I4,
финальная рецензия 02.10), по-видимому влияет на то, что модель сама считает
себе доступным: и рецензент, и нейтральный пробный агент с теми же `tools`
не дошли до вызова `write_to_file`/`run_command`, на котором сработало бы
правило `deny`. Запрет на реальных прогонах держится на дисциплине роли и
списка `tools` — собственное срабатывание `deny` под настройкой панели не
наблюдалось; второй линией защиты оно показано только на голом `agy` без
агента панели.

**Срок ожидания** (с 03.10, см. историю изменений). Сколько ждать Gemini
после ответа Codex, зависит от вердикта Codex:

| Codex | Gemini ждём | Срок истёк |
|---|---|---|
| есть замечания | `agentPanel.geminiWaitMinutes` (по умолчанию 20 минут): Claude в это время простаивает | Claude получает замечания одного Codex, живой Gemini не останавливается. Его поздний отзыв добавляется к замечаниям этой проверки, если они ещё ждут вашего решения, иначе показывается в ленте |
| принято, нужно решение, без вердикта | пока он работает, но не дольше 45 минут после ответа Codex: итог без него был бы ложным «Цикл завершён» | процесс Gemini останавливается, итог по Codex |

При любом вердикте Codex Gemini, 6 минут не подававший признаков жизни,
считается зависшим: процесс останавливается («замолчал на 6 мин —
остановлен»), итог по Codex. При замечаниях Codex это случается раньше их
20-минутного срока. Шесть минут — с запасом к замерам 04.10: наибольшее
молчание хода — 34,6 с у Flash high и 23,4 с у Pro high; пока модель
рассуждает, `agy` ничего не пишет. Опоздавшего Gemini — он проверяет дальше после срока при
замечаниях, пара уже сведена по Codex — сторожат те же 6 минут молчания и
45 минут после ответа Codex: процесс останавливается без нового итога («его
отзыва не будет»), очередь (прямой вопрос человека) идёт дальше. Сторож
ставится в момент срока, не дожидаясь конца сведения (снимок версии,
отправка Claude); если он сработал, пока сведение ждёт снимок, остановку
объясняет строка итога («… процесс остановлен. Итог проверки N — по Codex»).
Предел в 45 минут действует и в первом ожидании при замечаниях, если
`agentPanel.geminiWaitMinutes` больше него.

Признак жизни — любая строка вывода процесса `agy` (stdout или stderr) или
событие Gemini, пока его ход — эта проверка. Сроки (20 и 45 минут) — от
ответа Codex, передача материала позже их не продлевает. Молчание — от
позднего из двух моментов: ответа Codex и передачи материала Gemini (материал
ждёт в очереди, пока Gemini отвечает на прямой вопрос). Если к сроку Gemini эту проверку так
и не начал — занят прямым вопросом, — его не останавливают: «был занят
другим ходом», материал проверки снимается из очереди. Новая проверка или
новая задача снимает идущую позднюю проверку Gemini (прямой вопрос — никогда),
иначе материал следующей ждал бы её конца. Расход снятого хода остаётся в
расходе задачи, а следующее сообщение Gemini начинается с пометки «[прошлый
ход прерван панелью — его материал устарел, проверяй только этот]»: `agy`
сохраняет в разговоре запрос снятого хода и завершённые шаги его
инструментов (проба 04.10), и без пометки модель продолжила бы прежний
материал. Пока Gemini ждут после ответа Codex, «Эстафета» показывает «срок
ЧЧ:ММ» — верхнюю границу ожидания.

**Повтор при сетевом сбое** (с 05.10). Журнал 05.10, 00:38: ход проверки
Gemini кончился Bad Gateway с пустым ответом, `agy` вышел кодом 3, и пара
записала «не проверял», а через 11 минут тот же Gemini отработал нормально.
Теперь провал хода проверки с пустым ответом и словом сетевого сбоя в тексте
конца хода (Bad Gateway, EOF, 502/503/504, unavailable, connection reset,
timeout; без учёта регистра, коды и EOF — отдельными словами, «15020» не
сбой) исхода не даёт: через минуту (`GEMINI_RETRY_MS`) Gemini получает тот же
материал, в ленте «Gemini: сбой сети (Bad Gateway) — повтор через 1 мин.».
Повтор один на проверку; провал повтора (сбой, пустой ответ, отказ запуска,
падение процесса) — «не проверял: … (повтор тоже не удался)». Пока ждём
повтора, ход Gemini — эта проверка: часы не пишут «был занят другим ходом»,
молчание его не снимает, выход `agy` кодом 3 проверку не срывает, прямые
сообщения ему ждут в очереди. Предел безопасности (45 минут) действует как
обычно. «Прервать», «Остановить», новая задача, новая проверка и новая сессия
Gemini повтор снимают. Если срок при замечаниях Codex истёк во время
ожидания, повтор всё равно уходит, и его ответ — поздний отзыв. Поздний ход
(после срока) не повторяется. Причину сбоя адаптер берёт из `short_error`
строки `AGY_ERROR`: у настоящей строки нет `message`, и прежде причиной
становилась вся строка.

**Квота** (`src/geminiUsage.ts`) — `agy -p "/usage" --output-format json`
после ходов Gemini и при открытии, не чаще раза в 5 минут; запрос не тратит
расхода. Новой доли при этом нет — прежняя остаётся со временем сведения,
нулём не становится.

## Проверки рецензентов

С 05.10 рецензенты проверяют свои утверждения сами — командами и скриптами,
не трогая проект и данные (спецификация
[2026-10-05-проверки-рецензентов](specs/2026-10-05-проверки-рецензентов.md)).
Зачем: за 61 ход в комнате Trading 04–05.10 Codex не открыл ни одного файла и
не запустил ни одной команды — роль это запрещала, — и целые проверки уходили
на просьбы к Claude «пересчитайте» там, где хватило бы маленького скрипта.

| Ступень | Что | Когда работает |
|---|---|---|
| 1 | своя ветка рецензента Codex; Codex читает репозиторий командами | всегда |
| 2 | папка проверок Codex: он пишет и запускает свои скрипты | включены настройка `agentPanel.reviewerChecks` и переключатель комнаты |
| 3 | скрипты Gemini (блоки «проверка») выполняет панель | то же |

Каждая ступень работает без следующих. Механизмы ступеней 2–3 — по пробе
песочницы Codex 05.10 (`scripts/codex-sandbox-probe.mjs`,
[проба](research/2026-10-05-проба-песочницы-codex.md)).

### Ступень 1: ветка рецензента Codex

Панель заводит ветку Codex на комнату (`thread/start`, рабочая папка —
проект) и хранит её номер в `rooms.codex_review_thread`. Прежняя привязка
`rooms.codex_thread` — чат владельца — не продолжается ни при каком пути:
обычный запуск, перезапуск после сбоя, смена модели и повторное открытие
комнаты берут ветку только из `codex_review_thread` (`src/codexOptions.ts`,
вынесен из `extension.ts`, чтобы это проверялось тестом без VS Code).
«Новая сессия Codex» забывает обе привязки; прежней сессией она называет
только ветку рецензента.

Роль (`reviewerRole`, `src/adapters/codex.ts`) разрешает читать репозиторий:
`rg`, `git log/show/diff`, `python -c` над кодом. Сырой вывод Claude остаётся
главным свидетельством о запусках, которых рецензент не повторяет. Роль
запрещает изменения в проекте, сеть, долгие и фоновые процессы и пути из
`agentPanel.reviewerForbidden` («Не открывай и не читай пути: .env; от корня
проекта: data/»; для фрагмента от корня роль добавляет, что одноимённые папки
глубже корня, например пакет кода, под запрет не попадают).
Права ветки — прежние: `sandbox: "read-only"`, `approvalPolicy: "never"`.

**Запрещённые пути** — настройка папки проекта, по умолчанию `[".env"]`; для
Trading — `["./data/", ".env"]`. Тот же список получают роль Codex,
стоп-сигнал и проверка скриптов Gemini (`src/forbiddenPaths.ts`). Пустые
строки отбрасываются. Испорченное значение (не массив) — тоже `[".env"]`, а
не пустой список: ошибка в настройке не должна молча снять запрет секретов.
Явный пустой список (или список из одних пустых строк) снимает запрет
целиком: роль не называет путей, стоп-сигнал и проверка скриптов Gemini
молчат. Так задумано настройкой; для проекта с секретами так не делайте.
Смена настройки при открытой комнате действует сразу: стоп-сигнал и скрипты
Gemini — со следующей команды, роль Codex — со следующего хода (процесс
перезапускается с той же веткой, как при переключении проверок). Прежде
список читался один раз при открытии комнаты.

**Стоп-сигнал.** Координатор смотрит начало каждой команды Codex
(`tool_call` `commandExecution`, строка `raw.command`). Сравнение без учёта
регистра, `\` и `/` одинаковы, по границам имён. Фрагментов два вида.

- **Где угодно в пути** (`data/`, `.env`, `/secrets`): слева — начало строки
  или знак вне имени (пробел, кавычка, `/`, `=`…), справа — конец строки или
  знак, который не буква, не цифра и не `_`; косая черта на краю фрагмента
  сама граница. `cat .env`, `.env.local`, `C:\p\.env`, `open('data/x')`,
  `DATA\x` ловятся; `process.env`, `os.environ`, `metadata/`, `sample_data\` —
  нет (простое вхождение останавливало обычное чтение кода с `process.env`).
- **От корня проекта** (`./data/` или `.\data\`): в начале относительного
  пути (начало команды, пробел, кавычка, `=`, `(`, знаки оболочки; `./` перед
  ним не мешает) или сразу после `<проект>/` — папки комнаты. Папка без
  косой черты на конце ловится, когда это явно путь: после `<проект>/` или
  `./`, в кавычках (`Path('data')`), последним словом команды или перед её
  разделителем (`rg x data`, `cd data; …`). Пакет кода `tradingbot/data/`,
  его файлы по относительному и абсолютному пути, `data = …` и `print(data)`
  в коде — не папка данных. Итоговая рецензия ветки 05.10: у Trading был
  список `data/`, и чтение пакета `tradingbot/data/` останавливало проверку,
  а `Get-ChildItem …\Trading\data` и `Path('data')` проходили.

Шаблон секрета — `.env.example`, `.env.sample`, `.env.template` — не секрет:
Trading хранит `.env.example` в репозитории; `.env` рядом с ним в той же
команде ловится.

- В ходе проверки текущей пары цель, буфер и пара снимаются сразу, цикл
  останавливается, ход Codex прерывается; в ленте — «Codex обратился к
  запрещённому пути «data/» — проверка остановлена, решите, как
  продолжить.» Снимать всё нужно до прерывания: адаптер глотает поздний
  конец прерванного хода, `turn_completed` не придёт, и оставшаяся цель
  досталась бы следующему ходу Codex, а цикл висел бы в «проверяют».
- Сервер не принял `turn/interrupt` — адаптер останавливает процесс Codex
  (в диагностике «Codex не принял прерывание хода (…) — процесс
  остановлен»); следующая отправка продолжит ветку. Иначе ход мог идти
  дальше, а его элементы адаптер уже отбрасывает — команды пропали бы из
  ленты и журнала.
- В любом другом ходе (прямой вопрос, устаревший ход) — только строка «…
  вне проверки — ход не прерван.»
- Gemini при стоп-сигнале не снимается, как и при сбое хода Codex: его отзыв
  виден в ленте человеку, который решает, как продолжить, но в итог не идёт —
  цикл остановлен. «Прервать» или новая задача снимают его.
- Путь, который прочитал код проекта, а не сама команда (импорт), и путь,
  собранный из частей (`f"{ROOT}/data"`, `$root\data`), стоп-сигнал не
  видит. Расход прерванного хода Codex теряется, как при «Прервать».
- Обратная сторона: стоп-сигнал смотрит текст команды, а не то, что она
  открывает. Кавычка — граница имени, поэтому поиск строки в коде
  (`rg -n "data/" src`) останавливает проверку так же, как `cat data/x`; у
  фрагмента от корня — и `"data"` в кавычках (`df["data"]`), и `data`
  последним словом команды. Скрипт Gemini проверяется по всему тексту блока:
  `data/` в комментарии или строке — и скрипт не запускается. Деление
  `data/2` в коде — тоже совпадение.

### Ступень 2: папка проверок Codex

**Папка** — `%LOCALAPPDATA%\agent-panel\review\<комната>\codex\` и в ней
`tmp\`; `<комната>` — последняя часть пути проекта в нижнем регистре и 8
знаков хеша полного пути (`src/reviewFolder.ts`): две папки Trading в разных
местах не делят одну папку проверок. Вне репозитория: не попадает в
`git status`, `git add -A` у Claude, pytest и линтеры проекта. Панель создаёт
её до запуска процесса Codex (корень записи учитывается, только если папка
существует) и не чистит. Больше 500 МБ — строка в ленте при запуске процесса
(`oversizeNote`; обход папки останавливается, как только сумма превысила
предел: он идёт синхронно в процессе расширения). Папка Gemini проверяется
так же — перед его скриптами, строкой один раз на прогон. Команды очистки нет:
старое удаляет владелец.
Ссылка «Папка проверок» под полем ввода открывает её в проводнике.

**Профиль прав** — в `config` при каждом `thread/start` и `thread/resume`,
без поля `sandbox`, с `approvalPolicy: "never"`:

```jsonc
{
  "default_permissions": "agent-panel-review",
  "permissions": {
    "agent-panel-review": {
      "filesystem": { ":root": "read", "<папка codex>": "write" },
      "network": { "enabled": false }
    }
  },
  "shell_environment_policy": {
    "set": { "TEMP": "<папка codex>\\tmp", "TMP": "<папка codex>\\tmp",
             "PYTHONDONTWRITEBYTECODE": "1", "MPLCONFIGDIR": "<папка codex>\\tmp\\mpl" }
  }
}
```

Без `config` продолжение теряет профиль: ветка возвращается в read-only
(проба). Рабочая папка ветки — сама папка проверок, а не проект: под
песочницей unelevated (обычная установка Codex на Windows) с рабочей
папкой-проектом Codex отвергает под этим профилем любую команду ещё до
запуска («split writable root sets»). Поэтому роль ступени 2 называет папку
и проект, велит работать с проектом по абсолютным путям (`rg … <проект>`,
`git -C <проект> …`) и прочитать `<проект>\AGENTS.md`. Ещё в роли: скрипты и
их выводы — только в папке; в замечании — путь скрипта и строки вывода;
работать на синтетике и числах из материала, данные проекта не читать ни
напрямую, ни через импорт кода проекта; бюджет — не больше 20 команд и 10
минут счёта за проверку.

**Принят ли профиль** — по ответу `thread/start`/`thread/resume`: рабочая
папка — папка проверок, `sandbox.type` — `workspaceWrite`, сеть выключена,
`excludeTmpdirEnvVar`, корни записи — только папка, `activePermissionProfile`
— `agent-panel-review`. `command/exec` этот отказ не видит: он проверяет
политику процесса, а не связку профиля и рабочей папки ветки. Пока ответ
сверяется, номер ветки в журнал не пишется. Если ответ не тот, ветка уже
загружена с чужими правами — панель снимает этот процесс и открывает ветку
«только чтение» в новом.

**Самопроверка** — перед каждым запуском процесса Codex, без хода модели,
через `command/exec` со строгой политикой `{type: "workspaceWrite",
writableRoots: [<папка>], networkAccess: false, excludeTmpdirEnvVar: true,
excludeSlashTmp: true}`:

1. `python -c` пишет `<папка>\probe.txt` — должно пройти, файл на диске;
2. так же `<проект>\.agent-panel-probe` — песочница должна отказать (ошибка
   JSON-RPC «sandbox denied» или ненулевой код), файла быть не должно.

Пробы убираются. Без флагов `exclude…` корнем записи стал бы `%TEMP%`
пользователя. Процесс `app-server` при этом запущен в папке проверок, а не в
проекте: рабочая папка процесса для `command/exec` — тоже корень записи,
что бы ни называл запрос. Живой цикл 05.10 (вечер) шёл с процессом в
проекте. Самопроверка записала в проект и откатила проверку на «только
чтение», а unelevated-песочница навсегда дала Trading право записи (запись в
ACL папки) — см. историю изменений. Команду `codex` для такого процесса
панель ищет сама, от проекта (`locateCommand`, `src/adapters/process.ts`):
относительный путь — от проекта, голое имя — в проекте, затем по `PATH`.
Windows иначе искала бы голое имя сначала в рабочей папке процесса, а папка
проверок открыта рецензенту на запись — его `codex.bat` запустился бы без
песочницы. Так же — у исполнителя скриптов Gemini. Пишет `python` с путём в аргументе, а не `cmd /c echo`: `cmd`
не переносит путь с пробелами через кавычки аргументов, и сбой разбора
выглядел бы отказом песочницы. Проверка — при каждом запуске, потому что
Codex обновляется вместе с расширением ChatGPT (0.153 → 0.159 за три
недели).

**Откат.** Любое расхождение — запись в папку не прошла, в проект прошла
или не проверена, профиль не принят, ответ на профиль не тот — и ветка
открывается «только чтение» с рабочей папкой-проектом и ролью ступени 1. В
ленте строка «Песочница Codex не прошла проверку (<что>): проверка идёт в
режиме «только чтение».», подробности — в «Диагностике». Ход не считается
проваленным, цикл рецензии идёт дальше.

**Переключатель.** Ступени 2–3 работают, только когда включены и общая
настройка `agentPanel.reviewerChecks` (по умолчанию `false`), и переключатель
комнаты «Проверки рецензентов» под полем ввода (`rooms.reviewer_checks`).
Без настройки переключатель недоступен, а пришедшее от webview не
применяется. Смена переключателя или настройки при открытой комнате
действует для Codex со следующего хода (процесс перезапускается, ветка
продолжается с новыми правами), для скриптов Gemini — со следующего его
ответа. О смене переключателя в ленте строка.

### Ступень 3: скрипты Gemini через панель

Gemini команд не запускает: их запрещает правило `deny` agy, а разрешить
agy запись только в одну папку внутри проекта нельзя — его правила общие для
всех запусков. Поэтому утверждение, которое проверяется вычислением над
кодом, синтетикой или числами из материала, он подкрепляет скриптом в ответе:

````
```проверка python
# имя: просадка на отрезке [-0.2, 0]
…код…
```
````

Разбор (`src/checkBlocks.ts`) строгий, потому что решает, какой код будет
запущен: только заголовок «проверка python», только закрытый блок, не внутри
другого блока кода (пример формата в разметке — не поручение), не больше
трёх — лишние называются числом. Ограда — как в `verdict.ts`. Имя — из строки
`# имя: …`, без неё «проверка N».

Порядок:

0. Проверки выключены (по умолчанию) — материал проверки Gemini несёт строку
   между напоминанием о полосах (`GEMINI_FOCUS`) и просьбой о вердикте:
   «Проверки рецензентов в этой комнате выключены: блоков «проверка» не
   пиши — панель их не выполнит; вердикт этого ответа окончательный.» Роль
   `agent.md` пишется для всех комнат и без неё обещала бы выполнить блоки
   (итоговая рецензия ветки 05.10).
1. Ход проверки Gemini закончился ответом (не сбоем), в ответе есть блоки.
   Проверки выключены — строка в ленте, вердикт окончательный. Включены —
   вердикт предварительный, в ленте «Gemini прислал скрипты проверки (N) — панель
   выполняет их в песочнице Codex; его вердикт пока предварительный.» Перед
   скриптами — строка, если папка проверок Gemini больше 500 МБ.
2. Каждый скрипт до запуска проходит стоп-сигнал по своему коду (весь текст
   блока, с комментариями; фрагмент от корня — и после пути проекта): с
   запрещённым фрагментом он не запускается — «не запущено: обращается к
   ./data/».
3. Скрипт пишется файлом `<ГГГГММДД-ЧЧММСС>-<имя>.py` в папку проверок
   Gemini (`…\<комната>\gemini\`) и выполняется отдельным коротким процессом
   `codex app-server` (`src/checkRunner.ts`) через `command/exec`: рабочая
   папка и единственный корень записи — папка Gemini, строгая политика,
   `TEMP`/`TMP` — в её `tmp\`, без `__pycache__`, вывод в UTF-8. Python — из
   `.venv` проекта, если он есть, иначе `python`. Перед скриптом — та же
   самопроверка, что у Codex (проба в проекте — `.agent-panel-probe-gemini`).
   Срок — `agentPanel.reviewerCheckSeconds` (60 с); вывод (stdout и stderr) —
   до 20 000 знаков, начало и конец. После — снятие процесса деревом и
   процессов Python (`python*.exe`, `py.exe` или сам интерпретатор скрипта),
   начатых не раньше скрипта, в командной строке которых есть путь папки
   Gemini: фоновые процессы переживают и команду, и остановку app-server
   (проба). Редактор, в котором владелец открыл скрипт из папки, не
   задевается.
4. Каждый скрипт виден в ленте и журнале событиями инструмента «проверка»
   Gemini: код и вывод.
5. Тем же разговором Gemini получает сообщение «[вывод твоих проверок]»: по
   каждому скрипту имя, «код выхода N», «превышено время», «не запущено: …»
   или «проверки недоступны: …» и вывод — с просьбой дать окончательный отзыв
   целиком: Claude получит только его, а не прежний ответ. Вердикт этого хода
   — исход Gemini в паре.
6. Круг один: новые блоки во втором ответе не выполняются, в ленте строка.
   Свой выполненный скрипт, повторённый в окончательном отзыве, — не новый
   блок.

Исходы `command/exec` (проба 05.10): ответ `{exitCode, stdout, stderr}`;
отказ песочницы — ошибка JSON-RPC «sandbox denied exec error, exit code: N,
stdout: …, stderr: …» (код и вывод берутся из текста, вывод — с пометкой
«[песочница отказала скрипту в действии]»); превышение срока — ошибка
«command timed out» ровно по сроку, без кода и вывода.

**Сроки.** Пока идут скрипты, у Gemini нет цели, но его ход считается этой
проверкой — тот же признак, что у ожидания повтора: часы не пишут «был занят
другим ходом», детектор молчания не срабатывает, прямой вопрос человека ждёт
в очереди до конца второго хода. Общие сроки прежние: 20 минут после ответа
Codex при его замечаниях (истекли во время скриптов — вывод всё равно уходит
Gemini, его ответ — поздний отзыв), иначе предел 45 минут.

**Сбои.**

- Исполнитель не запустился или самопроверка не прошла — оставшиеся скрипты
  не выполняются, Gemini получает «проверки недоступны: <причина>», в ленте
  «Проверки Gemini недоступны: … Gemini выносит вердикт без них.»
- Второй ход сорвался (ошибка, сетевой сбой — без повтора, молчание,
  падение процесса, вывод не ушёл) — исход Gemini — предварительный вердикт,
  в ленте «Gemini не ответил на вывод проверок — взят предварительный
  вердикт. Причина: …». Предел безопасности или молчание сняли прогон —
  «Проверки Gemini не закончились (…) — взят предварительный вердикт.»
  Проверку Gemini дал, поэтому не «не проверял». Свидетельство копится после
  каждого скрипта: уже выполненные скрипты идут Claude и при снятом прогоне.
- Срок при замечаниях Codex истёк, пара сведена, а опоздавший Gemini
  сорвался (вывод проверок или повтор не ушёл, процесс упал) — в ленте
  «Gemini так и не дал проверки N: <причина>.», как при сбое его позднего
  хода. Прежде такой срыв в ленте не назывался.
- «Прервать», «Остановить», новая задача и новая сессия Gemini отменяют
  прогон; вывод тогда не уходит.
- Блоки в позднем первом ответе (после срока при замечаниях Codex) не
  выполняются: проверка уже сведена, в ленте строка.
- Блоки в ответе на прямой вопрос человека не выполняются: скрипты — только
  в ходе проверки.

### Свидетельство Claude

Команды Codex (`commandExecution`) и скрипты Gemini («проверка») с их
выводами Claude получает вместе с замечаниями — в сообщении пары и в комнате
без Gemini — блоком после отзыва рецензента:

```
— Команды и скрипты рецензента Codex (свидетельство к замечаниям; не запускай их) —
$ python C:\…\codex\dd.py
max_dd -0.2
```

Ненулевой код выхода — строкой `[код выхода N]`, пустой вывод — «(вывода
нет)». Каждый вывод — до 4000 знаков (начало и конец), весь блок — до 20 000
с пометкой об обрезке: выводы делят место поровну, а если тесно и так,
ранние команды уступают поздним — Codex сначала читает код, а скрипты, на
которых стоит вердикт, запускает потом. Поздний отзыв Gemini, пересобирая
удержанные замечания, блок Codex сохраняет. Прежде команды Codex копились в
материале его хода, но при разборе отзыва выбрасывались, и Claude получал
«пересчитайте» без самого пересчёта. В ленте вывод инструмента рецензента
подписан «вывод проверки рецензента», а не «передаётся рецензенту как есть».

В блок входят все команды Codex, и команды чтения (`rg`, `Get-Content`) тоже:
их вывод — файлы, которые у Claude уже есть, и это расход токенов в каждом
раунде. Поэтому шапка называет «команды и скрипты», а не «скрипты»
(итоговая рецензия 05.10). Оставлять ли в ступени 2 только команды с папкой
проверок — решение владельца.

Блоки «проверка» в отзыве Gemini, которые панель не выполняла (проверки
выключены, поздний первый ответ, новые блоки во втором ответе, прогон снят
до первого вывода), Claude получает с пометкой перед отзывом — и в
замечаниях, и в итоге приёмки:

```
— Gemini — методология и факты —
[блоки «проверка» в этом отзыве не выполнялись — не запускай их]
…отзыв…
```

Без неё скрипты рецензента приходили Claude без единого слова о том, что с
ними делать (спецификация 05.10, решение 5).

### Что гарантировано

- **ОС гарантирует** (песочница Codex): запись рецензентов — только в их
  папки проверок; одобрений нет, запрещённое действие сразу возвращается
  отказом.
- **Без усиленной песочницы Codex не гарантировано**: чтение — команда
  читает всё, что читает пользователь, включая `.env` (маркер в пробе
  прочитан); сеть — `urllib` упирается в прокси `127.0.0.1:9`, но сырой сокет
  выходит.
- **Закрываем иначе**: правило «без данных» в ролях, стоп-сигнал, журнал всех
  команд, шапка «не запускай их» в свидетельстве Claude, папки вне
  репозитория, самопроверка с откатом, выключатели (по умолчанию выключены).
- **Фоновые процессы** переживают команду и остановку app-server (проба).
  После скриптов Gemini панель снимает процессы с путём его папки в командной
  строке; после хода Codex — нет, остаётся правило роли.

## Что видно в панели

Облик — «язык нитей» (макеты в `docs/design/`): участники — огоньки своего
цвета (Claude тёплый, Codex холодный, Gemini фиолетовый, вы — белый), связи —
нити, работа — частицы на нити. Интерфейс почти серый: цвет только у агентов,
внимания, ошибок и уровня рассуждения. Фон и текст берутся из темы VS Code,
тёмной и светлой. Анимации выключаются системной настройкой «уменьшить
движение».

- **Статус «Эстафета»** вверху: огонёк Claude слева, нить раздваивается на
  Codex (сверху) и Gemini (снизу, если подключён) — вилка; частицы бегут по
  ветке, где идёт работа, закончивший тускнеет с отметкой своего вердикта.
  Рядом — точки проверок, очередь, «Прервать» и «Остановить» значками, текущая
  задача тихой строкой. По клику — **дорожка цикла**.
- **Беседа** на всю ширину: ваши сообщения справа, реплики агентов без рамок,
  над ними имя и версия файлов; имя Gemini в этой строке не окрашено и
  подзаголовка вида «проверка N · методология и факты» у него нет — автор
  подписан так же, как у остальных агентов. Это известное отступление от
  спецификации (`docs/specs/2026-10-02-gemini-рецензент.md`, строка «Реплики
  Gemini подписаны его цветом: «Gemini · проверка N · методология и факты ·
  версия …»»): цвет и подзаголовок реализованы не были, их нет и в
  `media/panel.js`. Вердикт рецензента (Codex или Gemini) — значком и
  словами, под ними исходная строка `ВЕРДИКТ: …`.
- **Действия хода** — одна свёрнутая строка: слева бусина на каждый вызов
  (квадрат — команда, кольцо — чтение и поиск, ромб — правка, точка — прочее;
  пустая — готовится, белая пульсирует — выполняется, цвета агента — готово,
  красная — отказано), справа счётчики по видам и «выполняется: …». Подробности
  и сырой вывод по клику. Вывод инструмента Claude подписан «сырой вывод —
  передаётся рецензенту как есть», вывод инструмента рецензента — «вывод
  проверки рецензента». Скрипты Gemini — его инструмент «проверка».
- **Вопрос Claude** — карточка «Claude спрашивает»: варианты, «Свой ответ»,
  «Ответить» и «Не отвечать».
- **Ваши действия** — отправка удержанного и переключение автопересылки —
  строкой «Вы: …».
- **Под полем ввода** — «Автопересылка», переключатель «Проверки
  рецензентов» (доступен с настройкой `agentPanel.reviewerChecks`) и, когда
  он включён, ссылка «Папка проверок»; строка переносится на узкой панели.
- **Ждёт вашего решения** — плашка над полем ввода с причиной и кнопкой;
  «Gemini нужен режим только чтения» — такая же по виду плашка с кнопкой
  «Добавить правила», но цикл она не держит.
- **Модели** — одна карточка, строка на агента (Claude, Codex, Gemini): имя
  цветом агента, модель пилюлей-списком, короткая нить уровня; название
  уровня — при наведении на узел; у каждой строки своя кнопка сброса к
  умолчанию (`↺`).
- **Реплики агентов — Markdown с формулами**: заголовки, списки, таблицы,
  код, `$…$` в строке и `$$…$$` отдельным блоком. «Стоит $5 и $10» формулой
  не станет. Ваши сообщения и вывод команд показываются как есть — логи не
  превращаются в разметку. Ссылки открываются в браузере.
- **Сообщения панели** подписаны «Панель», а не «Вы».
- **Диагностика** — кнопкой под полем ввода, свёрнута.

Состояния вызова инструмента различаются бусиной и меткой в списке:
«готовится», «выполняется», «готово», «отказано». Завершение генерации
аргументов — ещё не выполнение.

## Как устроено

Панель **владеет** всеми сессиями: подписка на поток уже работающей вкладки
по идентификатору не гарантирована, а у истории должен быть один управляющий
процесс. Штатное расширение Claude остаётся для одиночной работы.

```
┌──────────────────────────────────────────────────────┐
│ Панель VS Code (webview)                             │
│   состояние · беседа · диагностика                   │
├──────────────────────────────────────────────────────┤
│ Координатор                                          │
│   маршруты, цикл рецензии, сведение пары,            │
│   удержание, очередь, снимки версий                  │
├─────────────────┬─────────────────┬──────────────────┤
│ Адаптер Claude  │ Адаптер Codex   │ Адаптер Gemini   │
│ CLI stream-json │ app-server      │ agy stream-json  │
│                 │ JSON-RPC        │                  │
├─────────────────┴─────────────────┴──────────────────┤
│ Процессы: запуск и остановка всем деревом            │
└──────────────────────────────────────────────────────┘
```

Журнал — SQLite через встроенный `node:sqlite`, нативная сборка не нужна
(что в нём хранится — «Журнал» ниже).

**Markdown и формулы без интернета.** markdown-it 15 не поставляет сборку
для браузера без модулей, поэтому `npm run build` собирает esbuild'ом
markdown-it, KaTeX и правило формул в `media/vendor/markdown.js` и копирует
стили и шрифты KaTeX; лицензии — в `media/vendor/LICENSES.txt`. Текст пишет
агент, а вставляется HTML, поэтому: сырой HTML экранируется, ссылки
`javascript:` не проходят, KaTeX без `trust` выводит `\href` текстом, CSP
разрешает скрипты только с nonce. Встроенные стили разрешены ради KaTeX —
высоту дробей он задаёт атрибутом `style`.

**Агенты запускаются при первом сообщении**, а не при открытии панели. В
живом прогоне сессия Claude создавалась просто оттого, что панель открыли в
другой папке.

**Claude запускается без ваших пользовательских настроек**
(`--setting-sources project,local`). Иначе в его сессии срабатывают ваши
глобальные хуки: в тестовом прогоне Stop-хук памяти пришёл как реплика, и
панель записала две заметки в хранилище, о которых никто не просил.
`--bare` не годится — он не читает OAuth.

Встроенную автопамять Claude этот флаг **не выключает**: в прогоне
15 сентября сессия панели сама записала заметку в
`~/.claude/projects/<проект>/memory/`. Это не хук, а поведение самого Claude.

**«Будь честен в своём ответе.»** получают все агенты (просьба владельца
05.10):
- Codex — первой строкой роли;
- Gemini — в начале роли `agent.md`;
- Claude — флагом `--append-system-prompt` при каждом запуске CLI (через
  `cmd.exe` — в кавычках) и строкой «[Будь честен в своём ответе.]» в шапке
  каждого сообщения.

Флага одного мало. Claude Code 2.1.287 записывает системный промпт на первом
запросе разговора и при каждом возобновлении повторяет запись как есть, даже
если новый запуск передал другой текст, — до сжатия контекста
(`--system-prompt-snapshot`, по умолчанию `on`). Сессия комнаты, начатая до
флага, его не видит до сжатия или «Новой сессии агента»: у сессии Trading
последняя запись промпта сделана до 05.10, и строки в ней нет. Шапка
сообщения доходит с ближайшего хода.

### Новая сессия агента

Каждый ход Claude возобновляет сессию комнаты целиком, и длинная сессия
дорожает с каждым ходом. «Новая сессия» — ссылка «новая сессия…» в карточке
«Модели» (она спрашивает, для какого агента) или команды «Agent Panel: новая
сессия Claude/Codex/Gemini для комнаты» — после подтверждения останавливает
процесс агента и забывает привязку комнаты: следующий ход начнёт свежую
сессию. Прежняя остаётся в истории агента, беседа в панели — на месте. Если
агент был занят ходом, цикл рецензии останавливается.

Строка в ленте называет прежнюю сессию, а если её не было, так и говорит:
«Новая сессия Gemini: прежней не было — следующий ход начнёт новую.» Прежде
она и тогда сообщала, что прежняя «сохранена в истории». Прежняя берётся у
адаптера, а если он её ещё не знает, — из привязки комнаты: Codex поднимает
ветку только при первой отправке, и до неё «прежней не было» было бы новой
неправдой. У Codex «новая сессия» забывает и ветку рецензента, и прежний чат
владельца, а прежней называет только ветку рецензента.

### Расход и лимиты

В раскрытой дорожке цикла — строка расхода: токены Claude, Codex и, если
подключён, Gemini с начала текущей задачи (вход вместе с кешем и выход; в
скобках — сколько из кеша) и последние сведения о лимитах. Codex сообщает
долю недельного окна (`account/rateLimits/updated`, например «неделя 8%»).
Gemini — свою долю из `agy -p "/usage" --output-format json` («Gemini:
неделя N%, окно 5 ч M%»). У Claude в потоке только
статус пятичасового окна (`rate_limit_event`), поэтому панель спрашивает
`claude -p /usage` — при открытии и после ходов Claude, не чаще раза в 5
минут — и показывает «Claude: неделя 5%, окно 5 ч 31%»; статус окна
добавляется, когда он не «в норме». Запрос не тратит токенов (≈4 с, замер
28.09) и с `--no-session-persistence` не оставляет файла сессии. Он идёт из
пустого временного каталога, а не из проекта: замер показал, что `/usage`
запускает хук `SessionStart` настроек проекта. Незнакомый ответ `/usage` —
доли нет, а не ноль; если новый запрос не удался, прежняя доля остаётся со
временем сведения («неделя 5% (на 05:14)»), как и доля старше 10 минут.
Выключается `agentPanel.claudeWeeklyUsage`.
Токены Claude — сумма `usage` всех `result` хода, Codex — разность
накопительного итога ветки (`thread/tokenUsage/updated`) до и после хода,
Gemini — сумма `usage` шагов `agent_response` хода, а не разность
накопительного `usage` у `result`: он после `--conversation` включает расход
прежнего процесса целиком (проба 02.10 — 119 580 токенов на ходу, стоившем
~14 000), так что разность была бы не расходом хода, а расходом с начала
прежнего процесса. С
`agentPanel.taskTokenLimit` передача рецензентам или разработчику ждёт
решения человека, когда расход задачи (всех трёх агентов) достиг предела.

### Журнал

`src/journal.ts`, файл `agent-panel.sqlite` в хранилище расширения. Таблица
`rooms` — привязки комнаты: `claude_session`, `codex_review_thread`, прежний
`codex_thread` (история), `gemini_conversation` и переключатель
`reviewer_checks`. Таблица `events` — все события комнаты. Новые колонки
переносятся в прежнюю базу при открытии.

С 05.10 по журналу можно восстановить ход проверки — журнал 04–05.10 этого не
давал: не было видно, что человек сам отправил удержанное, сколько стоил
каждый ход, когда Claude начал работу и что именно получил рецензент.

- **Действия человека** (`kind = action`, `agent = human`): «Отправлено
  Claude вручную: <причина удержания>» (для пары — «Отправлено Codex и Gemini
  вручную: …») с ушедшим текстом в `raw`; «Автопересылка выключена» и
  «Автопересылка включена» — только при смене. Лента показывает их строкой «Вы:
  …». Смена режима разрешений и модели пишется строкой панели, как и раньше.
- **Материал рецензенту** (`kind = material`, `agent` — рецензент, которому
  он ушёл): полный текст сообщения панели в момент отправки (в том числе из
  очереди), версия проверки — в `snapshot`. Только журнал: в ленту и при
  восстановлении истории в webview не идёт — это сотни тысяч символов на
  проверку. `history()` его и не читает (иначе материал занимал бы окно
  последних 2000 строк ленты); читает `materials()`.
- **Расход хода** — колонка `usage` (JSON); испорченная запись читается как
  ход без расхода.
- **Начало хода Claude** — `turn_started` с момента отправки, как
  `turn/started` у Codex; ходы, начатые самим Claude, по-прежнему помечены
  `unsolicited`.
- Команды рецензентов и события «проверка» Gemini — как инструменты агента.

### Субагенты Claude

Инструмент Agent в Claude Code 2.1.220 по умолчанию запускает субагента **в
фоне**, и в режиме панели `result` приходит раньше, чем субагент закончил;
итог Claude присылает отдельным, незапрошенным ходом (живая трасса 28.09 —
`docs/research/2026-09-28-трасса-фонового-субагента.md`). Прежде панель
отдала бы рецензенту «агент запущен, жду», а итог никто бы не проверил.
Теперь ход Claude кончается только после субагентов и итогового ответа; в
диагностике — «ход продолжается: Claude ждёт субагентов». Фоновые Bash ход не
держат. Действия и реплики субагента помечены: бусина в ободке, метка
«субагент», приглушённый блок «Субагент», у рецензента — «субагент вызова X».

### Субагенты Codex

Codex может запустить субагентов в их собственных ветках. В живом цикле
05.10 (вечер) GPT-6.1-Sol xhigh запустил двух без просьбы. Их `turn/*`,
`item/*` и расход приходят по тому же соединению `app-server` со своим
`threadId`. Элемента `collabAgentToolCall` в том цикле не было. Прежде
адаптер ветки не различал, и конец хода первого субагента («ВЕРДИКТ:
ПРИНЯТО») стал отзывом Codex. Сейчас ход ведёт только своя ветка
(`src/adapters/codex.ts`):

- **начало и конец хода субагента** — строки «Codex запустил субагента
  <ветка>» (первый `turn/started` ветки; следующий — «субагент <ветка>
  продолжил») и «субагент <ветка> закончил» в «Диагностике». Занятость и ход
  Codex они не трогают. Имя ветки — 13 знаков: первые 8 знаков UUIDv7 —
  время, у веток одного хода они совпадают;
- **команды и правки субагента** — инструменты хода Codex: лента, журнал (в
  `raw` — `threadId` субагента), блок «Команды и скрипты рецензента»,
  стоп-сигнал. В ленте они пока не помечены как действия субагента;
- **реплика субагента** — строка «субагент Codex: …» в «Диагностике», до
  2000 знаков; целиком она в `raw` журнала. В отзыв и вердикт она не входит.
  Итог Codex — ответ его ветки, которая сама сводит выводы субагентов;
- **дельты** текста, рассуждений и вывода команд субагента в поток ответа не
  идут;
- **расход субагента** прибавляется к расходу хода, пока ход идёт;
- **субагент, работавший на кончившийся или прерванный ход**, виден в ленте
  и журнале. Его команды идут без хода и не попадают в материал следующей
  проверки. Стоп-сигнал их по-прежнему видит;
- **`thread/started` ветки субагента** (с `parentThreadId` или с чужим
  номером) не становится веткой рецензента комнаты.

«Прервать» и стоп-сигнал прерывают ход своей ветки и каждый идущий ход
субагента — своим `turn/interrupt`: снимает ли `app-server` субагентов
вместе с основной веткой, не проверено. Сервер не принял прерывание
субагента или номер его хода неизвестен — процесс Codex снимается, как при
отказе в прерывании основной ветки; следующая отправка продолжает ветку.

### Claude продолжил сам

Фоновые команды (Bash с `run_in_background`) ход не держат: сервер, запущенный
в фоне, не дал бы ему кончиться никогда. Но когда такая команда кончается, CLI
сам начинает новый ход — `init`, реплика, `result` без сообщения панели
(живая трасса 28.09, `scripts/e2e-probe.mjs --background-bash`). Если этот
ход идёт, пока Claude отвечает на замечания, CLI дожидается конца ответа и
начинает свой следом. Прежде координатор принимал такой ход за ответ на
следующее сообщение: итог работы уходил бы рецензенту не тот, а настоящий
терялся. Теперь адаптер помечает его «самостоятельным»: панель пишет «Claude
продолжил сам (фоновая задача закончилась: …)», ход не занимает цель
задачи, не идёт рецензенту и не входит в расход задачи; сообщения Claude на
это время ждут в очереди. Реплики такого хода подписаны «Claude · сам»; отметка
хранится в журнале и видна и после повторного открытия панели. Гонку — сообщение панели ушло, когда CLI уже начал
свой ход, но его `init` ещё не дошёл, — адаптер различает по эху: Claude
запускается с `--replay-user-messages` и повторяет сообщение внутри его
запроса; запрос без эха при ждущем сообщении — ход самого CLI. Проверено
живьём с посредником, растягивающим окно (`scripts/race-probe.mjs`). Если
CLI эха не присылает (старые версии), различения нет.

### Каждый ход знает, зачем он

Цель хода — работа в цикле, проверка в цикле или прямой вопрос —
записывается **до** отправки и снимается при завершении. Иначе ответ на
мимоходный вопрос ушёл бы рецензенту как работа по задаче, а быстро
завершившийся ход — остался бы без цели.

### Устаревшее не доставляется

У каждой задачи свой номер цикла. После каждого ожидания — снимка версии,
отправки — координатор проверяет, что цикл всё ещё текущий. Если человек за
это время дал новую задачу или нажал «Прервать», продолжение прежнего цикла
отбрасывается, а его пересылки убираются из очереди.

### Остановка

На Windows агенты запускаются через оболочку (`claude` и `codex` — это
`.cmd`-обёртки), и обычный `kill` завершает только `cmd.exe`: сам агент и его
команды продолжали работать. Поэтому остановка — `taskkill /PID … /T /F`,
всем деревом, с ожиданием, пока процесс действительно завершится. Проверено
тестом: фальшивый агент запускает долгую команду, после «Остановить» не
остаётся ни агента, ни команды.

«Прервать» останавливает текущие ходы и цикл рецензии. Сообщения человека,
ждавшие в очереди конца хода, при этом **не отправляются** — панель пишет,
сколько их снято: отправить их сразу значило бы решить за человека, который
мог прервать именно чтобы передумать. Сообщение, которое ещё готовилось
(снимок файлов, поиск по памяти), тоже не уходит. Написанное уже после
нажатия, пока агенты прерывались, уходит сразу после прерывания: это новое
намерение. Поздние события прерванного хода Codex или Gemini (элементы и
конец хода) панель отбрасывает — в ответ нового хода они не попадают.
«Остановить агентов» — то же и завершение процессов всех агентов.

### Привязка к версии файлов

Каждое событие помечается отпечатком рабочего дерева: коммит, хеш diff
отслеживаемых файлов и хеши **содержимого** неотслеживаемых. Снимок закреплён
за ходом агента, поэтому чужая реплика посреди проверки не переписывает
версию идущего хода.

Замечания рецензента подписываются версией, которую он **проверял**. Если
файлы изменились за время проверки, Claude получает это отдельной строкой:
«замечания относятся к версии A, сейчас B».

### Усечение вывода

В беседе вывод одного инструмента длиннее 64 000 символов показывается
усечённым с пометкой «… обрезано N символов». **Рецензенту уходит полный**:
адаптер сохраняет полный текст рядом с показанным, в журнал он не пишется
(там есть `raw`), в webview не передаётся.

У каждого вывода в материале проверки заголовок с источником и полнотой:
инструмент, id вызова, время и «полный, N символов» или «неполный: показано
X из N». Все выводы одной проверки вместе ограничены бюджетом
`agentPanel.reviewEvidenceChars` (240 000 символов): короткие идут целиком,
остаток делится поровну между длинными, у них показаны начало и конец и
назван пропущенный диапазон. Так было не всегда: до 28.09.2026 рецензенту
уходил текст, обрезанный для показа, а пометка «сырой вывод» завышала
полноту переданного (исследование Codex 27.09).

|---|---|
| Формат потока Claude | запуск `claude -p --output-format stream-json` и разбор наблюдённых записей |
| Отказы в разрешениях | живой прогон: `result.permission_denials` при `is_error: false` |
| Запрос разрешения | проба `--permission-prompt-tool stdio`: `control_request` с подтипом `can_use_tool`; ответ-отказ дошёл до модели как `tool_result` |
| Многоходовость через stdin | две реплики подряд, вторая вспомнила число из первой |
| Протокол Codex | `codex app-server generate-json-schema --out DIR`; оттуда `thread.id`, `turn.status`, `agentMessage.text`, `item/agentMessage/delta` |
| Хуки в дочерней сессии | запуск с `--setting-sources project,local` и без |
| Обрыв канала на Windows | замер: запись в процесс, закрывший stdin, проходит молча; `EPIPE` — только через ~60 с, когда заполнится буфер |
| Протокол agy | запуск `agy -p="" --input-format stream-json --output-format stream-json` и разбор наблюдённых событий (`docs/research/2026-10-02-проба-agy.md`) |
| Расход по шагам | `usage` у `step_update` — один вызов модели; у `result` — накопительно за весь процесс (там же) |
| Мягкий отказ | действию нужно согласие, спросить некого: ход кончается `status: SUCCESS` с пустым ответом, отказ виден только в `denied_actions` и в stderr (там же) |
| Правила `deny` | `permissions.deny` в `settings.json` — шаг `ERROR` с «permission check failed», в `denied_actions` такой отказ не попадает (там же) |

| Профиль прав Codex | проба 05.10 на одноразовой ветке во временной папке, четыре хода модели (`scripts/codex-sandbox-probe.mjs`, `docs/research/2026-10-05-проба-песочницы-codex.md`): профиль принимают `thread/start` и `thread/resume`, команды под ним идут только при рабочей папке ветки = папке проверок, без `config` продолжение теряет профиль |

| Форма `AskUserQuestion` | журнал панели 04–05.10: `can_use_tool` с `requires_user_interaction` и в `bypassPermissions`; форма ответа (`answers`) — по документации Agent SDK, живьём не проверена |

## Разделение ролей: что обеспечено и что нет

**Codex: запись файлов запрещена, и это проверяемо.** Ветка Codex
создаётся с `sandbox: "read-only"` и `approvalPolicy: "never"`, а на любой
запрос одобрения панель отвечает отказом — это проверено тестом на
фальшивом сервере. С проверками рецензентов запись разрешена только в папку
проверок профилем прав; что запись в проект отклонена, панель проверяет
самопроверкой перед каждым запуском процесса и откатывается в read-only,
если это не так.

**Codex: команды чтения разрешены, а чтение и сеть песочница не
ограничивает.** С 05.10 роль разрешает рецензенту читать репозиторий
командами. Read-only (и профиль прав под unelevated) запрещает запись, но не
чтение и не выход в сеть сырым сокетом. Запрет данных, секретов, сети, долгих
и фоновых процессов — правило роли; запрещённый путь в самой команде ловит
стоп-сигнал, путь, прочитанный кодом проекта, — нет (см. «Проверки
рецензентов», «Что гарантировано»).

**Скрипты Gemini выполняет панель в песочнице Codex**: запись — только в
папку проверок Gemini, та же самопроверка, тот же стоп-сигнал по коду
скрипта до запуска. Чтение и сеть не закрыты так же, как у Codex.

**Gemini: запись и команды запрещены правилами `agy`, но правило `deny`
под собственной настройкой агента панели само срабатывающим не увидено**
(`docs/research/2026-10-02-проба-agy.md`): на просьбу записать файл и
выполнить команду снимок рабочего дерева до и после проверки совпал — но оба
раза по разным причинам, не относящимся к самому `deny`. В пробе адаптера
панели рецензент сам не пытался писать — ответил «принято» без единого
вызова инструмента, как требует его роль. В пробе `--deny-check` (I4,
финальная рецензия 02.10) пробный агент с ТЕМИ ЖЕ `tools` и
`excludeDefaultComponents`, что у рецензента панели, но с нейтральной ролью
без запрета писать, тоже не вызвал ни одного инструмента — отказался сам,
сославшись на отсутствие доступа к файлам и командам. Явную ошибку
«permission check failed» от `permissions.deny` панель видела только на
голом `agy` БЕЗ агента панели (раздел «Разрешения» в пробе) — под своей
настройкой `agent.md` она остаётся второй линией защиты, чьё собственное
срабатывание не наблюдалось: список `tools` в `agent.md` не меняет набор
инструментов в `init` (проба показала это раньше), но, судя по всему,
всё же формирует для модели описание того, что ей «доступно», и этого
достаточно, чтобы она не пыталась писать, не дойдя до самого правила.

## Ограничения

**«Разрешить в этой сессии» не снимает вопрос о перенаправлении в файл.**
Живая проба 28.09 (`scripts/permission-probe.mjs`, CLI 2.1.220, вне VS Code):
«разрешить» у настоящего Claude работает (Write создал файл); после «в этой
сессии» те же `python -c "print(2+2)"` и `mkdir -p probe-dir` второй раз не
спрашиваются. Но команду вида `echo one > файл` CLI спрашивает снова — и с
правилом `Bash(echo one *)`, и с добавленной папкой из его же подсказки
`addDirectories` (проверено временной правкой адаптера; три прогона, одна форма
команды). Панель передаёт ровно то, что написано на кнопке; повторный вопрос
здесь — решение CLI. Подсказку `setMode acceptEdits` (все правки файлов на
сессию) панель не предлагает: она шире того, что видно на кнопке.

**Живой проверки новой версии в окне VS Code не было.** Адаптеры проверены на
фальшивых процессах, координатор — на заглушках, интерфейс — в безголовом
браузере. Живьём вне VS Code 28.09 прошли: каталоги моделей, ход и
возобновление (`scripts/live-probe.mjs`), полный цикл рецензии с настоящими
Claude и Codex, в том числе с фоновым субагентом и «Памятью по теме»
(`scripts/e2e-probe.mjs`). 02.10 живьём вне VS Code прошли и Gemini: ход,
продолжение разговора, `/usage` и правила «только чтение» на настоящем
адаптере панели (`scripts/gemini-probe.mjs`, с `--deny-check` — проба самого
правила `deny`) и полный цикл пары рецензентов на ML-задаче с утечкой
(`scripts/e2e-probe.mjs --gemini`); `scripts/live-probe.mjs` Gemini не
касается, каталог моделей (`agy models`) проверен живьём только в первой
пробе, без адаптера панели — подробности в
`docs/research/2026-10-02-проба-agy.md`. Окно VS Code с подключённым Gemini
живьём не проверялось — до проверки владельцем; расширение в окне с этими
изменениями не запускалось вовсе.

**Фоновые субагенты проверены живьём в двух случаях**: один субагент и два
сразу, из них один заметно дольше (`scripts/e2e-probe.mjs --two-subagents`,
28.09: «ждёт субагентов (2)», ход держался до обоих итогов). Субагент,
запустивший свою команду в фоне, считается закончившим, когда сам ответил, —
Claude в той пробе проверил файл раньше, чем команда его создала. Вложенные
субагенты Claude живой трассой не проверены. Субагенты Codex видны в журнале
живого цикла 05.10: два субагента, уведомления их веток по тому же
соединению. Обработка, исправленная после этого цикла, проверена только на
фальшивом Codex.

**Недельная доля Claude — разбор английского текста `/usage`** (CLI 2.1.220):
если CLI изменит формулировку, доля пропадёт (не станет нулём). Панель её
не проверяет против вашей границы — только показывает.

**На Windows обрыв канала к агенту не виден сразу.** Если агент перестал
читать ввод, но не завершился, запись проходит без ошибки, и панель узнаёт о
сбое только после выхода процесса. Проверка на обрыв канала на Windows
пропускается с этой причиной.

**Остановка группой процессов на Linux и macOS не проверена** — написана, но
на этой машине не запускалась.

**Проверки рецензентов живьём в панели запускались один раз** — цикл в
Trading 05.10 вечером. Самопроверка Codex нашла запись в проект: процесс
`app-server` был запущен в проекте. Проверка пошла «только чтение», так что
на настоящем Codex прошёл только откат. Gemini блоков «проверка» не писал.
После исправления (процесс в папке проверок) живьём проверен только
`command/exec` вне панели; ступень 2 в панели живьём не шла. Других живых
ходов моделей при разработке проверок не было, кроме пробы 05.10 (четыре
хода Codex вне панели). Адаптер, исполнитель и координатор проверены на фальшивом Codex
с формами ответов из пробы. Не проверены на настоящем Codex: запуск файла
`python <скрипт>.py` под строгой политикой; переменные `PYTHONUTF8` и
`PYTHONIOENCODING` в `env`; дополняет ли `env` унаследованное окружение или
заменяет его (если заменяет, `python` по имени и код, которому нужен `PATH`,
могут не найтись); возврат ветки от рабочей папки проверок к проекту в
read-only; сверка ответа на профиль на настоящих ответах 0.159. Усиленная
песочница не проверялась вовсе.

**Цена скриптов Gemini.** Перед каждым скриптом — две команды самопроверки:
запись в папку проверок, которая должна пройти, и попытка записи
`.agent-panel-probe-gemini` в корень проекта, которую песочница должна
отклонить. Сама панель в проект не пишет: она удаляет этот файл, только если
песочница его пропустила (тогда самопроверка не прошла), или если это
остаток прежнего запуска. После скрипта — поиск оставшихся процессов
PowerShell'ом; в сумме на этой машине около 1–3 с на скрипт.
Две комнаты одного проекта делят папку проверок, и снятие процессов после
скрипта одной может задеть скрипт другой.

**Фоновые процессы Codex панель не ищет.** Процесс, оставленный командой
Codex, переживает и ход, и остановку app-server; снимаются только процессы
скриптов Gemini (Python, начатые не раньше скрипта, по пути папки в
командной строке). Процесс без пути папки в командной строке или не Python
так не найти.

ожидания Gemini** — видно только по строке ленты. Повтор уходит в тот же
разговор `agy`: сорванный ход мог в нём остаться, и Gemini увидит материал
дважды.

(`updatedInput.answers`); как настоящий CLI передаёт его модели, не
наблюдалось. Метка варианта длиннее 500 символов уходит обрезанной.
