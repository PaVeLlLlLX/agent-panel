# Устройство Agent Panel

Подробности работы панели для тех, кто её дорабатывает: словарь терминов, правила
цикла рецензии, устройство адаптеров и проверенные основания решений. Краткое
руководство пользователя — в [README](../README.md), история исправлений — в
[история-изменений.md](история-изменений.md).

## Словарь

Одно слово — одно понятие. Эти же объяснения всплывают при наведении на
элементы панели.

| Слово | Что значит |
|---|---|
| **Задача** | сообщение, отправленное режимом «Задача с рецензией». С него начинается цикл |
| **Цикл рецензии** | Claude работает → Codex и Gemini проверяют пару, параллельно и независимо → при замечаниях снова Claude. Кончается принятием, остановкой или решением человека |
| **Проверка** | одна проверка — пара: Codex и, если подключён, Gemini отвечают на одну и ту же работу Claude. Точки справа от статуса — «проверок 1 из 3»: пара посмотрела работу один раз |
| **Пара** | Codex и Gemini одной проверки: получают одинаковый материал, но разные инструкции, и отвечают независимо друг от друга |
| **Сведение** | итог проверки пары — строже из двух вердиктов побеждает: решение человека сильнее замечаний, замечания сильнее приёмки |
| **Не проверял** | Gemini не дал проверки в этот раз: сбой, квота, регион, истёк срок ожидания или нет правил «только чтение». Итог проверки — по одному вердикту Codex |
| **Предел** | сколько проверок разрешено на одну задачу (`agentPanel.maxAutoRounds`); проверка пары считается одной. Не даёт агентам спорить бесконечно за ваши деньги |
| **Вердикт** | итог ответа рецензента последней строкой: «принято», «есть замечания», «нужно решение человека»; «не вынесен» — решаете вы. Итог проверки пары — сведение по обоим вердиктам |
| **Автопересылка** | флажок под полем ввода. Включена — агенты передают работу друг другу сами. Выключена — каждую передачу подтверждаете вы |
| **Ждёт вашего решения** | панель остановила передачу и показывает над полем ввода причину с кнопкой. Ничего не теряется |
| **Режим разрешений** | «без вопросов» — Claude выполняет команды сам; «спрашивать» — действия, требующие согласия, приходят карточкой. Для папки, кнопка со щитом в поле ввода |
| **Запрос разрешения** | Claude хочет выполнить действие, требующее вашего согласия. В беседе появляется карточка с командой, ход стоит до вашего ответа |
| **В этой сессии** | больше не спрашивать про такую команду, пока процесс Claude не остановлен. В файлы настроек ничего не пишется |
| **Эстафета** | статус вверху: огонёк Claude слева, нить раздваивается на Codex и Gemini (если подключён), частицы бегут по ветке, где идёт работа; белый огонёк на стволе — ждут вас |
| **Дорожка цикла** | раскрывается по клику на статус: после каждого хода Claude — ромбы Codex и Gemini с отметкой вердикта (`!` замечания, `?` нужно решение, `✓` принято; пунктирное кольцо цвета Gemini — «не проверял»), пустые ромбы — оставшиеся проверки |
| **Отказ без запроса** | действие отклонено, а спросить вас было нельзя (например, режим `dontAsk`). Панель ждёт вашего решения |
| **Модель** | какая модель агента отвечает. Список берётся у самого агента; «по умолчанию» — выбор его CLI |
| **Уровень рассуждения** | сколько модель думает перед ответом: от «Низкого» до «Максимума», у Codex ещё «Ультра». Выше — дольше и дороже. Выбирается узлом на нити в «Моделях» |
| **Очередь** | сообщения, которые ждут, пока агент закончит текущий ход |
| **Ход** | один ответ агента от получения сообщения до конца, со всеми его действиями |
| **Прервать** | остановить текущий ход. Сессии сохраняются, следующее сообщение их продолжит |
| **Остановить** | завершить процессы всех агентов вместе с запущенными ими командами |
| **Сырой вывод** | точный текст, который вернули команды агента, без пересказа |
| **Диагностика** | служебные логи процессов агентов внизу панели. Не часть разговора |

## Как отправить сообщение

В поле ввода выбирается, **как** отправить: значки переключателя, а название
режима рядом открывает меню. На узкой панели остаётся только меню. Режимов
пять, «Только Gemini» видно, когда найден `agy`.

| Режим | Что происходит |
|---|---|
| **Задача с рецензией** | Claude выполняет, Codex и Gemini проверяют — параллельно и независимо, пара за парой, пока сведение не даст «принято» |
| **Спросить всех** | все агенты отвечают независимо, друг другу ничего не передаётся |
| **Только Claude** / **Только Codex** / **Только Gemini** | прямой вопрос одному, без пересылки |

Режимы разные по смыслу намеренно. В первой версии сообщение уходило обоим
сразу, ответы расходились по времени, и в живом прогоне Claude спорил с
замечанием, которое Codex уже отозвал за пять секунд до этого.

**Проверить коммит просят режимом «Задача с рецензией», а не «Только
Codex».** Рецензенты не запускают команды и не увидят `git show`; сырой вывод
им приносит Claude. Gemini не видит отзыва Codex: иначе пропадает
независимость второго взгляда.

### Цикл рецензии

```
Claude закончил ─► снимок A ─┬─► Codex:  код                ─┐
                             └─► Gemini: методология, факты  ─┴─► сведение ─► принято / Claude / вы
```

1. Claude получает задачу и работает.
2. Codex и Gemini получают **задачу человека, реплики Claude и сырой вывод его
   инструментов** — один снимок версии, но разные инструкции — и выносят
   вердикт параллельно и независимо. Это одна проверка — пара; счётчик
   проверок (`agentPanel.maxAutoRounds`) растёт на 1 за пару, не за агента.
   Gemini ждём не дольше `agentPanel.geminiWaitMinutes` после ответа Codex —
   не успел, исход «не проверял».
3. Сведение — строже побеждает:

   | Исход | Когда | Последствие |
   |---|---|---|
   | ждём человека | хоть один рецензент — «нужно решение человека» или без вердикта | панель ждёт вашего решения |
   | есть замечания | иначе хоть у одного — «есть замечания» | Claude получает оба отзыва одним сообщением |
   | принято | иначе | цикл завершён |

**Исходы проверки Gemini:**

| Исход | Когда |
|---|---|
| вердикт | «принято», «есть замечания» или «нужно решение человека» последней строкой — участвует в сведении |
| без вердикта | ответил, но последней строки-вердикта нет — ждём человека, как у Codex |
| не проверял | процесс упал, пустой ответ, прирост `denied_actions`, регион, квота, не успел в срок, нет правил «только чтение» — итог по одному вердикту Codex |

Без `agy` пара не собирается — проверяет один Codex, как и раньше.

Цикл кончается **по итогу, а не по счёту**. Предел проверок остаётся
ограничителем расходов.

### Как читается вердикт

Засчитывается только **последняя непустая строка** ответа рецензента, и только
если это ровно `ВЕРДИКТ: ПРИНЯТО`, `ВЕРДИКТ: ЕСТЬ ЗАМЕЧАНИЯ` или
`ВЕРДИКТ: НУЖНО РЕШЕНИЕ ЧЕЛОВЕКА`. Последний рецензент ставит, когда без
вашего решения или данных обмен бессмысленен: панель останавливается, а не
пересылает согласия до предела проверок, как было в прогоне 16 сентября. Допускается
жирный шрифт и точка в конце. Не засчитывается:

- вердикт в цитате (`> ВЕРДИКТ: ПРИНЯТО`) или в блоке кода;
- вердикт не последней строкой — например, «пример формата» посреди ответа;
- похожие слова: `НЕПРИНЯТО`, `ПРИНЯТО ЧАСТИЧНО`;
- вердикт с отступом в четыре пробела или табуляцию — в разметке это код;
- вердикт в обратных кавычках: `` `ВЕРДИКТ: ПРИНЯТО` `` — это пример.

Границы блока кода считаются по правилам разметки: ограда запоминается видом
и длиной, закрывает её только такая же не короче и без текста после. Иначе
пример формата закрывал бы цикл: блок, открытый четырьмя кавычками и
«закрытый» тремя, давал ложное «принято» — пять таких входов нашёл рецензент
в прогоне 16 сентября, и все они в тестах.

Всё это — «вердикт не вынесен», и решение за человеком. Прежний разбор искал
слово в любом месте текста и засчитывал приёмку там, где её не было.

### Когда панель ждёт вашего решения

Передача не уходит, но и не пропадает, если:

| Причина | Кнопка |
|---|---|
| Claude получил отказы без запроса — проверять нечего, работа не сделана | **Повторить Claude** |
| рецензент просит вашего решения | **Отправить Claude** |
| рецензент не вынес вердикт | **Отправить Claude** |
| достигнут предел проверок — работа Claude осталась непроверенной | **Отправить на проверку** (без Gemini — **Отправить Codex**) |
| автопересылка выключена | **Отправить** тому, кому предназначено |

Отказы не уходят на проверку намеренно: в живом прогоне три проверки
потратились на спор рецензента с разработчиком о том, почему заблокирована
команда, — хотя разрешить её мог только человек.

Новая задача отменяет пересылки прежней, и панель говорит, сколько
устаревшего не доставлено.

### Режим разрешений

По умолчанию Claude работает **без вопросов** (`bypassPermissions`). Кнопкой
со щитом в поле ввода режим переключается на **спрашивать** — тогда действия,
требующие согласия, приходят карточками. Выбор запоминается для папки.

Режим задаётся флагом запуска и действует со следующего хода. Кнопка
«Больше не спрашивать» на карточке и переключение посреди хода действуют и
сразу: до перезапуска открытые и новые запросы разрешает сама панель. Так
сделано по пробе на Claude Code 2.1.220: ответ с `setMode bypassPermissions`
повторных запросов в идущей сессии не отключил. Режим `auto` через флаг не
включился — сессия сообщила `default`, — поэтому в переключателе его нет.

«В этой сессии» разрешает только **ту же команду целиком**: в
прогоне 16 сентября Claude Code предлагал правилом всю строку команды, без
`*`, и следующий `git show` другого файла снова спрашивал.

Codex режим не касается: он работает в песочнице только для чтения. Gemini
режим тоже не касается: запись файлов и команды ему запрещены правилами
`agy`.

### Запрос разрешения

Когда Claude нужно ваше согласие, в беседе появляется карточка: инструмент,
команда целиком, описание и путь, а статус вверху — «Ждёт разрешения».

| Кнопка | Что уходит Claude |
|---|---|
| **Разрешить** | этот вызов, один раз |
| **В этой сессии** | этот вызов и правило команды (видно при наведении) до остановки Claude |
| **Больше не спрашивать** | этот вызов, и режим «без вопросов» для папки |
| **Отклонить** | отказ с пометкой, что отказал человек |

«В этой сессии» передаёт только правило команды. Claude предлагает записать
его в `.claude/settings.local.json` и заодно включить приёмку всех правок —
панель не делает ни того, ни другого.

Отказ, данный вами, — решение, а не блокировка: работа идёт дальше и
уходит на проверку как обычно. «Прервать» и «Остановить» закрывают открытые
карточки. Каждый запрос и решение записываются в журнал.

### Ваш чат Codex в панели

Панель может продолжить ветку вашего собственного чата Codex, а не заводить
свою: тогда рецензент приходит в комнату со всей историей работы. Для этого
идентификатор ветки ставится в привязку комнаты (таблица `rooms`, поле
`codex_thread` в журнале панели), а чат закрывается в приложении Codex.
Проверено 25.09.2026 на ветке с недельной историей: панель её возобновила,
и Codex ответил как рецензент — роль панель передаёт и при возобновлении.

**Какой codex запускается.** Если установлено расширение ChatGPT для VS Code,
панель берёт его `codex` — тот же, что в вашем чате, с теми же моделями.
CLI из npm может отставать: 25.09 у ветки была сохранена модель `gpt-6-sol`,
CLI 0.153.0 её не знал, и ход падал с «model is not supported when using
Codex with a ChatGPT account», а `codex` 0.155.0-alpha.16 из расширения ту же
ветку продолжил. Явный путь в `agentPanel.codexCommand` важнее.

**Какой claude запускается.** Так же: если установлено расширение Claude Code
для VS Code, панель берёт его `resources/native-binary/claude.exe` — ту же
версию, что у вашего чата; расширение обновляется само, и панель подхватывает
новую версию при следующем открытии комнаты. 28.09 claude 2.1.220 из npm не
принял сессию на `claude-opus-5-5` («API Error: 400 … does not support this
model; version 2.1.280»), а 2.1.280 из расширения — принял. Явный путь в
`agentPanel.claudeCommand` важнее; без расширения — `claude` из PATH.

В «Модели» стоит выбрать модель вашей ветки: модель, переданная панелью в
ход, остаётся у ветки и в приложении.

### Память по теме

Если задана `agentPanel.memorySearchCommand`, к каждому сообщению человека
панель прикладывает заметки памяти проекта, найденные по его словам, — обоим
агентам и рецензенту вместе с задачей. В беседе появляется строка «Память: к
сообщению приложены заметки (N): …» — видно, что именно получили агенты.
Заметки идут после слов человека с пояснением «это не слова человека, а
справка». Сообщение ждёт поиска не дольше 10 с (обычно 1–3 с); сбой или срок
называются строкой «Поиск по памяти не удался», и сообщение уходит без
заметок. Если во время поиска нажать «Остановить», сообщение не уходит, и
панель это пишет. Вывод команды читается как UTF-8.

Протокол команды — как у хука `UserPromptSubmit` Claude Code: JSON `{cwd,
prompt}` на вход, `hookSpecificOutput.additionalContext` на выход. Поэтому
один поиск служит и вашим сессиям Claude, и панели; например
`python C:/Users/<вы>/.claude/hooks/memory_search.py` (qmd по основам слов, с
обновлением индекса перед поиском).

Зачем. Claude в панели запускается без ваших пользовательских настроек (см.
«Как устроено»), значит без ваших хуков памяти и MCP-серверов; у Codex их нет
вовсе. Проверено 28.09.2026: в `init` Claude панели только connector
claude.ai. Самому искать в памяти Claude панели можно дать через
`agentPanel.claudeMcpConfig` — JSON с сервером qmd, как у `claude --mcp-config`;
с ним в `init` появляется `qmd: connected` и инструменты `mcp__qmd__*`.

### Модель и уровень рассуждения

Кнопка **Модели** в поле ввода открывает одну карточку: строка на агента —
Claude, Codex и, если найден `agy`, Gemini. В строке: имя цветом агента,
модель — списком, уровень рассуждения — узлом на короткой нити. Название
уровня не подписано рядом — оно видно при наведении на узел; пояснений вида
«сколько уровней» в карточке нет. Сводка текущего выбора — в подсказке
кнопки и строки.

Нить показывает уровень формой, а не подписью; определения из документации
Anthropic и OpenAI — в подсказке каждого узла. Чем выше уровень, тем больше и
быстрее частицы; «Максимум» — нить толще и двойное кольцо (вся глубина в одном
рассуждении); «Ультра» у Codex — нить ветвится на три ветки с огоньками
субагентов. Чёрточка под узлом — умолчание модели, если его сообщил каталог.
Claude своего умолчания не сообщает, и тогда ни один узел не выбран: уровень
решает сам агент. Узел Ultracode не показывается: у `claude -p` (2.1.220)
флага для него нет, `--effort` принимает только low … max. У Gemini уровень
зашит в имя модели (`-low`, `-medium`, `-high`): у семейства Flash три узла, у
Pro — два; «Ультра» у Gemini нет. Кнопка сброса уровня к умолчанию (`↺`) — у
каждой строки своя.

Список берётся у самих агентов: Claude отдаёт его в
ответе на `initialize`, Codex — в `model/list`, Gemini — в `agy models`
(только модели `gemini-*`: модели Claude и GPT из каталога `agy` в карточку
Gemini не попадают). Для этого на пару секунд поднимается отдельный процесс;
рабочая сессия не создаётся, модель не вызывается. Запрашивается только при
первом открытии.

Выбор действует **со следующего хода** и запоминается для папки. Claude
перезапускается между ходами с `--resume --model --effort` — контекст сессии
сохраняется. Codex получает `model` и `effort` в `turn/start`; при возврате к
«по умолчанию» модель называется явно, иначе ветка осталась бы на прежней.
Gemini — как Claude: процесс перезапускается между ходами с `--model`.
Смена записывается в беседу и журнал: видно, какая модель дала какой ответ.

## Gemini (agy)

Второй рецензент в каждой проверке — параллельно с Codex и независимо от
него: проверяет методологию эксперимента чек-листом (утечки, разбиения,
метрики, бейзлайн, сиды и разброс, обоснованность выводов) и факты вне
репозитория по вебу, с адресом страницы и датой проверки у каждого факта.
Полного второго взгляда на код нет — это дублировало бы Codex и тратило бы
квоту без вопроса. Gemini не видит отзыва Codex: иначе пропадает
независимость.

**Протокол.** Один процесс на всю сессию комнаты, много ходов подряд:

```
agy -p="" --agent agent-panel-reviewer --input-format stream-json --output-format stream-json [--model M] [--conversation ID]
```

Ход — строка `{"event":"user","message":{"content":"…"}}` в stdin.

**Разбор потока** в общую модель событий панели (`src/adapters/types.ts`):

| `agy` | Событие панели |
|---|---|
| `init` | id разговора → журнал; модель и режим → диагностика |
| `step_update` `user_input` | `turn_started` |
| `agent_response` с `text_delta` | `text_delta`; на `DONE` — собранный текст |
| `tool` `ACTIVE` | `tool_call` / `tool_running` |
| `tool` `DONE` / `ERROR` | `tool_result` (у Gemini — краткая сводка, не сырой вывод); `ERROR` с «permission check failed» — отказ |
| `result` | `turn_completed`: расход — разность накопительного `usage`; `failed`, если статус не `SUCCESS` |
| пустой ответ, прирост `denied_actions` | «проверка неполная» → исход «не проверял» |
| stderr `AGY_ERROR: {…}`, «Eligibility check failed», дневной предел | `error` с причиной словами |

**Только чтение.** Перед запуском процесса панель читает общие настройки agy
(`~/.gemini/antigravity-cli/settings.json`):

```json
"permissions": { "allow": ["read_url(*)"], "deny": ["write_file(*)", "command(*)"] }
```

Правил нет (или JSON не разбирается) — Gemini не запускается: исход «не
проверял», цикл идёт с одним Codex, а над полем ввода — плашка «Gemini нужен
режим только чтения» с кнопкой «Добавить правила» (дописывает недостающее,
сохраняя остальное содержимое, без повторов). Без нажатия панель файл не
меняет. Правила общие для всего `agy`, в том числе интерактивного.

**`agent.md`.** Роль рецензента — системная инструкция в
`~/.gemini/config/agents/agent-panel-reviewer/agent.md`. Файл принадлежит
панели: она переписывает его перед запуском Gemini, если текст в коде
изменился. Список `tools` заголовка YAML гарантией не служит — проба
показала, что набор инструментов в `init` от него не меняется; запрет держится
на правилах `deny` и, как показала та же проба, на дисциплине самой роли —
рецензент на реальных прогонах не пытался писать и без запрета.

**Срок ожидания.** Gemini ждём не дольше `agentPanel.geminiWaitMinutes` (по
умолчанию 10 минут) после ответа Codex. Не успел — «не проверял», итог по
Codex; поздний ответ виден в ленте, но в проверку не входит.

**Квота** (`src/geminiUsage.ts`) — `agy -p "/usage" --output-format json`
после ходов Gemini и при открытии, не чаще раза в 5 минут; запрос не тратит
расхода. Новой доли при этом нет — прежняя остаётся со временем сведения,
нулём не становится.

## Что видно в панели

Облик — «язык нитей» (макеты в `docs/design/`): участники — огоньки своего
цвета (Claude тёплый, Codex холодный, Gemini фиолетовый, вы — белый), связи —
нити, работа — частицы на нити. Интерфейс почти серый: цвет только у агентов,
внимания, ошибок и уровня рассуждения. Фон и текст берутся из темы VS Code,
тёмной и светлой. Анимации выключаются системной настройкой «уменьшить
движение».

- **Статус «Эстафета»** вверху: огонёк Claude слева, нить раздваивается на
  Codex (сверху) и Gemini (снизу, если подключён) — вилка; частицы бегут по
  ветке, где идёт работа, закончивший тускнеет с отметкой своего вердикта.
  Рядом — точки проверок, очередь, «Прервать» и «Остановить» значками, текущая
  задача тихой строкой. По клику — **дорожка цикла**.
- **Беседа** на всю ширину: ваши сообщения справа, реплики агентов без рамок,
  над ними имя и версия файлов; имя Gemini в этой строке не окрашено и
  подзаголовка вида «проверка N · методология и факты» у него нет — автор
  подписан так же, как у остальных агентов. Вердикт рецензента (Codex или
  Gemini) — значком и словами, под ними исходная строка `ВЕРДИКТ: …`.
- **Действия хода** — одна свёрнутая строка: слева бусина на каждый вызов
  (квадрат — команда, кольцо — чтение и поиск, ромб — правка, точка — прочее;
  пустая — готовится, белая пульсирует — выполняется, цвета агента — готово,
  красная — отказано), справа счётчики по видам и «выполняется: …». Подробности
  и сырой вывод по клику.
- **Ждёт вашего решения** — плашка над полем ввода с причиной и кнопкой;
  «Gemini нужен режим только чтения» — такая же по виду плашка с кнопкой
  «Добавить правила», но цикл она не держит.
- **Модели** — одна карточка, строка на агента (Claude, Codex, Gemini): имя
  цветом агента, модель пилюлей-списком, короткая нить уровня; название
  уровня — при наведении на узел; у каждой строки своя кнопка сброса к
  умолчанию (`↺`).
- **Реплики агентов — Markdown с формулами**: заголовки, списки, таблицы,
  код, `$…$` в строке и `$$…$$` отдельным блоком. «Стоит $5 и $10» формулой
  не станет. Ваши сообщения и вывод команд показываются как есть — логи не
  превращаются в разметку. Ссылки открываются в браузере.
- **Сообщения панели** подписаны «Панель», а не «Вы».
- **Диагностика** — кнопкой под полем ввода, свёрнута.

Состояния вызова инструмента различаются бусиной и меткой в списке:
«готовится», «выполняется», «готово», «отказано». Завершение генерации
аргументов — ещё не выполнение.

## Как устроено

Панель **владеет** всеми сессиями: подписка на поток уже работающей вкладки
по идентификатору не гарантирована, а у истории должен быть один управляющий
процесс. Штатное расширение Claude остаётся для одиночной работы.

```
┌──────────────────────────────────────────────────────┐
│ Панель VS Code (webview)                             │
│   состояние · беседа · диагностика                   │
├──────────────────────────────────────────────────────┤
│ Координатор                                          │
│   маршруты, цикл рецензии, сведение пары,            │
│   удержание, очередь, снимки версий                  │
├─────────────────┬─────────────────┬──────────────────┤
│ Адаптер Claude  │ Адаптер Codex   │ Адаптер Gemini   │
│ CLI stream-json │ app-server      │ agy stream-json  │
│                 │ JSON-RPC        │                  │
├─────────────────┴─────────────────┴──────────────────┤
│ Процессы: запуск и остановка всем деревом            │
└──────────────────────────────────────────────────────┘
```

Журнал — SQLite через встроенный `node:sqlite`, нативная сборка не нужна.

**Markdown и формулы без интернета.** markdown-it 15 не поставляет сборку
для браузера без модулей, поэтому `npm run build` собирает esbuild'ом
markdown-it, KaTeX и правило формул в `media/vendor/markdown.js` и копирует
стили и шрифты KaTeX; лицензии — в `media/vendor/LICENSES.txt`. Текст пишет
агент, а вставляется HTML, поэтому: сырой HTML экранируется, ссылки
`javascript:` не проходят, KaTeX без `trust` выводит `\href` текстом, CSP
разрешает скрипты только с nonce. Встроенные стили разрешены ради KaTeX —
высоту дробей он задаёт атрибутом `style`.

**Агенты запускаются при первом сообщении**, а не при открытии панели. В
живом прогоне сессия Claude создавалась просто оттого, что панель открыли в
другой папке.

**Claude запускается без ваших пользовательских настроек**
(`--setting-sources project,local`). Иначе в его сессии срабатывают ваши
глобальные хуки: в тестовом прогоне Stop-хук памяти пришёл как реплика, и
панель записала две заметки в хранилище, о которых никто не просил.
`--bare` не годится — он не читает OAuth.

Встроенную автопамять Claude этот флаг **не выключает**: в прогоне
15 сентября сессия панели сама записала заметку в
`~/.claude/projects/<проект>/memory/`. Это не хук, а поведение самого Claude.

### Новая сессия агента

Каждый ход Claude возобновляет сессию комнаты целиком, и длинная сессия
дорожает с каждым ходом. «Новая сессия» — ссылка «новая сессия…» в карточке
«Модели» (она спрашивает, для какого агента) или команды «Agent Panel: новая
сессия Claude/Codex/Gemini для комнаты» — после подтверждения останавливает
процесс агента и забывает привязку комнаты: следующий ход начнёт свежую
сессию. Прежняя остаётся в истории агента, беседа в панели — на месте. Если
агент был занят ходом, цикл рецензии останавливается.

### Расход и лимиты

В раскрытой дорожке цикла — строка расхода: токены Claude, Codex и, если
подключён, Gemini с начала текущей задачи (вход вместе с кешем и выход; в
скобках — сколько из кеша) и последние сведения о лимитах. Codex сообщает
долю недельного окна (`account/rateLimits/updated`, например «неделя 8%»).
Gemini — свою долю из `agy -p "/usage" --output-format json` («Gemini:
неделя N%, окно 5 ч M%»). У Claude в потоке только
статус пятичасового окна (`rate_limit_event`), поэтому панель спрашивает
`claude -p /usage` — при открытии и после ходов Claude, не чаще раза в 5
минут — и показывает «Claude: неделя 5%, окно 5 ч 31%»; статус окна
добавляется, когда он не «в норме». Запрос не тратит токенов (≈4 с, замер
28.09) и с `--no-session-persistence` не оставляет файла сессии. Он идёт из
пустого временного каталога, а не из проекта: замер показал, что `/usage`
запускает хук `SessionStart` настроек проекта. Незнакомый ответ `/usage` —
доли нет, а не ноль; если новый запрос не удался, прежняя доля остаётся со
временем сведения («неделя 5% (на 05:14)»), как и доля старше 10 минут.
Выключается `agentPanel.claudeWeeklyUsage`.
Токены Claude — сумма `usage` всех `result` хода, Codex — разность
накопительного итога ветки (`thread/tokenUsage/updated`) до и после хода,
Gemini — разность накопительного `usage` процесса до и после хода. С
`agentPanel.taskTokenLimit` передача рецензентам или разработчику ждёт
решения человека, когда расход задачи (всех трёх агентов) достиг предела.

### Субагенты Claude

Инструмент Agent в Claude Code 2.1.220 по умолчанию запускает субагента **в
фоне**, и в режиме панели `result` приходит раньше, чем субагент закончил;
итог Claude присылает отдельным, незапрошенным ходом (живая трасса 28.09 —
`docs/research/2026-09-28-трасса-фонового-субагента.md`). Прежде панель
отдала бы рецензенту «агент запущен, жду», а итог никто бы не проверил.
Теперь ход Claude кончается только после субагентов и итогового ответа; в
диагностике — «ход продолжается: Claude ждёт субагентов». Фоновые Bash ход не
держат. Действия и реплики субагента помечены: бусина в ободке, метка
«субагент», приглушённый блок «Субагент», у рецензента — «субагент вызова X».

### Claude продолжил сам

Фоновые команды (Bash с `run_in_background`) ход не держат: сервер, запущенный
в фоне, не дал бы ему кончиться никогда. Но когда такая команда кончается, CLI
сам начинает новый ход — `init`, реплика, `result` без сообщения панели
(живая трасса 28.09, `scripts/e2e-probe.mjs --background-bash`). Если этот
ход идёт, пока Claude отвечает на замечания, CLI дожидается конца ответа и
начинает свой следом. Прежде координатор принимал такой ход за ответ на
следующее сообщение: итог работы уходил бы рецензенту не тот, а настоящий
терялся. Теперь адаптер помечает его «самостоятельным»: панель пишет «Claude
продолжил сам (фоновая задача закончилась: …)», ход не занимает цель
задачи, не идёт рецензенту и не входит в расход задачи; сообщения Claude на
это время ждут в очереди. Реплики такого хода подписаны «Claude · сам»; отметка
хранится в журнале и видна и после повторного открытия панели. Гонку — сообщение панели ушло, когда CLI уже начал
свой ход, но его `init` ещё не дошёл, — адаптер различает по эху: Claude
запускается с `--replay-user-messages` и повторяет сообщение внутри его
запроса; запрос без эха при ждущем сообщении — ход самого CLI. Проверено
живьём с посредником, растягивающим окно (`scripts/race-probe.mjs`). Если
CLI эха не присылает (старые версии), различения нет.

### Каждый ход знает, зачем он

Цель хода — работа в цикле, проверка в цикле или прямой вопрос —
записывается **до** отправки и снимается при завершении. Иначе ответ на
мимоходный вопрос ушёл бы рецензенту как работа по задаче, а быстро
завершившийся ход — остался бы без цели.

### Устаревшее не доставляется

У каждой задачи свой номер цикла. После каждого ожидания — снимка версии,
отправки — координатор проверяет, что цикл всё ещё текущий. Если человек за
это время дал новую задачу или нажал «Прервать», продолжение прежнего цикла
отбрасывается, а его пересылки убираются из очереди.

### Остановка

На Windows агенты запускаются через оболочку (`claude` и `codex` — это
`.cmd`-обёртки), и обычный `kill` завершает только `cmd.exe`: сам агент и его
команды продолжали работать. Поэтому остановка — `taskkill /PID … /T /F`,
всем деревом, с ожиданием, пока процесс действительно завершится. Проверено
тестом: фальшивый агент запускает долгую команду, после «Остановить» не
остаётся ни агента, ни команды.

«Прервать» останавливает текущие ходы и цикл рецензии. Сообщения человека,
ждавшие в очереди конца хода, при этом **не отправляются** — панель пишет,
сколько их снято: отправить их сразу значило бы решить за человека, который
мог прервать именно чтобы передумать. Сообщение, которое ещё готовилось
(снимок файлов, поиск по памяти), тоже не уходит. Написанное уже после
нажатия, пока агенты прерывались, уходит сразу после прерывания: это новое
намерение. Поздние события прерванного хода Codex или Gemini (элементы и
конец хода) панель отбрасывает — в ответ нового хода они не попадают.
«Остановить агентов» — то же и завершение процессов всех агентов.

### Привязка к версии файлов

Каждое событие помечается отпечатком рабочего дерева: коммит, хеш diff
отслеживаемых файлов и хеши **содержимого** неотслеживаемых. Снимок закреплён
за ходом агента, поэтому чужая реплика посреди проверки не переписывает
версию идущего хода.

Замечания рецензента подписываются версией, которую он **проверял**. Если
файлы изменились за время проверки, Claude получает это отдельной строкой:
«замечания относятся к версии A, сейчас B».

### Усечение вывода

В беседе вывод одного инструмента длиннее 64 000 символов показывается
усечённым с пометкой «… обрезано N символов». **Рецензенту уходит полный**:
адаптер сохраняет полный текст рядом с показанным, в журнал он не пишется
(там есть `raw`), в webview не передаётся.

У каждого вывода в материале проверки заголовок с источником и полнотой:
инструмент, id вызова, время и «полный, N символов» или «неполный: показано
X из N». Все выводы одной проверки вместе ограничены бюджетом
`agentPanel.reviewEvidenceChars` (240 000 символов): короткие идут целиком,
остаток делится поровну между длинными, у них показаны начало и конец и
назван пропущенный диапазон. Так было не всегда: до 28.09.2026 рецензенту
уходил текст, обрезанный для показа, а пометка «сырой вывод» завышала
полноту переданного (исследование Codex 27.09).

### Проверенные основания, а не предположения

| Что | Как установлено |
|---|---|
| Формат потока Claude | запуск `claude -p --output-format stream-json` и разбор наблюдённых записей |
| Отказы в разрешениях | живой прогон: `result.permission_denials` при `is_error: false` |
| Запрос разрешения | проба `--permission-prompt-tool stdio`: `control_request` с подтипом `can_use_tool`; ответ-отказ дошёл до модели как `tool_result` |
| Многоходовость через stdin | две реплики подряд, вторая вспомнила число из первой |
| Протокол Codex | `codex app-server generate-json-schema --out DIR`; оттуда `thread.id`, `turn.status`, `agentMessage.text`, `item/agentMessage/delta` |
| Хуки в дочерней сессии | запуск с `--setting-sources project,local` и без |
| Обрыв канала на Windows | замер: запись в процесс, закрывший stdin, проходит молча; `EPIPE` — только через ~60 с, когда заполнится буфер |
| Протокол agy | запуск `agy -p="" --input-format stream-json --output-format stream-json` и разбор наблюдённых событий (`docs/research/2026-10-02-проба-agy.md`) |
| Расход по шагам | `usage` у `step_update` — один вызов модели; у `result` — накопительно за весь процесс (там же) |
| Мягкий отказ | действию нужно согласие, спросить некого: ход кончается `status: SUCCESS` с пустым ответом, отказ виден только в `denied_actions` и в stderr (там же) |
| Правила `deny` | `permissions.deny` в `settings.json` — шаг `ERROR` с «permission check failed», в `denied_actions` такой отказ не попадает (там же) |
| `strict` слепит | `toolPermission: "strict"` — мягкий отказ даже на чтение файла проекта; `allow read_file(*)` сверху не помогает (там же) |

## Разделение ролей: что обеспечено и что нет

**Codex: запись файлов запрещена, и это проверяемо.** Ветка Codex
создаётся с `sandbox: "read-only"` и `approvalPolicy: "never"`, а на любой
запрос одобрения панель отвечает отказом — это проверено тестом на
фальшивом сервере.

**Codex: запрет запуска команд технически НЕ обеспечен.** Read-only сам по
себе выполнение не запрещает, а инструкция рецензенту — просьба, не гарантия.

**Gemini: запись и команды запрещены правилами `agy` и это проверено пробой**
(`docs/research/2026-10-02-проба-agy.md`): на просьбу записать файл и
выполнить команду снимок рабочего дерева до и после проверки совпал. В пробе
рецензент сам не пытался писать — ответил «принято» без единого вызова
инструмента, как требует его роль, — а правило `permissions.deny` в общих
настройках `agy` остаётся второй линией защиты: отдельно показано, что на
настоящей попытке `write_file`/`command` оно даёт явную ошибку «permission
check failed», и модель получает отказ. Список `tools` в `agent.md`
гарантией не служит — проба показала, что он набор инструментов в `init` не
ограничивает.

## Ограничения

**«Разрешить в этой сессии» не снимает вопрос о перенаправлении в файл.**
Живая проба 28.09 (`scripts/permission-probe.mjs`, CLI 2.1.220, вне VS Code):
«разрешить» у настоящего Claude работает (Write создал файл); после «в этой
сессии» те же `python -c "print(2+2)"` и `mkdir -p probe-dir` второй раз не
спрашиваются. Но команду вида `echo one > файл` CLI спрашивает снова — и с
правилом `Bash(echo one *)`, и с добавленной папкой из его же подсказки
`addDirectories` (проверено временной правкой адаптера; три прогона, одна форма
команды). Панель передаёт ровно то, что написано на кнопке; повторный вопрос
здесь — решение CLI. Подсказку `setMode acceptEdits` (все правки файлов на
сессию) панель не предлагает: она шире того, что видно на кнопке.

**Живой проверки новой версии в окне VS Code не было.** Адаптеры проверены на
фальшивых процессах, координатор — на заглушках, интерфейс — в безголовом
браузере. Живьём вне VS Code 28.09 прошли: каталоги моделей, ход и
возобновление (`scripts/live-probe.mjs`), полный цикл рецензии с настоящими
Claude и Codex, в том числе с фоновым субагентом и «Памятью по теме»
(`scripts/e2e-probe.mjs`). 02.10 живьём вне VS Code прошли и Gemini: каталог
моделей, ход, продолжение и `/usage` (`scripts/live-probe.mjs`), правила
«только чтение» на настоящем адаптере панели (`scripts/gemini-probe.mjs`) и
полный цикл пары рецензентов на ML-задаче с утечкой
(`scripts/e2e-probe.mjs --gemini`) — подробности в
`docs/research/2026-10-02-проба-agy.md`. Окно VS Code с подключённым Gemini
живьём не проверялось — до проверки владельцем; расширение в окне с этими
изменениями не запускалось вовсе.

**Фоновые субагенты проверены живьём в двух случаях**: один субагент и два
сразу, из них один заметно дольше (`scripts/e2e-probe.mjs --two-subagents`,
28.09: «ждёт субагентов (2)», ход держался до обоих итогов). Субагент,
запустивший свою команду в фоне, считается закончившим, когда сам ответил, —
Claude в той пробе проверил файл раньше, чем команда его создала. Вложенные
субагенты и субагенты Codex (collab) живой трассой не проверены.

**Недельная доля Claude — разбор английского текста `/usage`** (CLI 2.1.220):
если CLI изменит формулировку, доля пропадёт (не станет нулём). Панель её
не проверяет против вашей границы — только показывает.

**На Windows обрыв канала к агенту не виден сразу.** Если агент перестал
читать ввод, но не завершился, запись проходит без ошибки, и панель узнаёт о
сбое только после выхода процесса. Проверка на обрыв канала на Windows
пропускается с этой причиной.

**Остановка группой процессов на Linux и macOS не проверена** — написана, но
на этой машине не запускалась.

Кроме этого: одна комната на окно.
