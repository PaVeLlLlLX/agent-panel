# Трасса фонового субагента Claude Code (28.09.2026)

Измерено Claude Code в ночной смене. `claude` 2.1.220, модель haiku, временная
папка с файлом `a.txt`, `--permission-mode bypassPermissions`. Задание: запустить
одного субагента (Agent, general-purpose), чтобы он выполнил `sleep` и прочитал
файл; самому ничего не делать.

## Что установлено

1. **Agent по умолчанию запускает субагента в фоне.** Результат вызова приходит
   сразу: «Async agent launched successfully»; появляется `system/task_started`
   с `task_type: "local_agent"`. Главный агент отвечает «Агент запущен… жду».
2. **В режиме панели (ввод stream-json) `result` приходит раньше, чем субагент
   закончил** (13,4 с против 28 с), а после `task_notification` Claude сам
   начинает итоговый запрос: новый `system/init`, реплика, свой `result`. На одно
   сообщение — два `result`, и второй — незапрошенный ход.
3. **В режиме `-p` с одним запросом оба `result` приходят в конце** (27,8 с), после
   повторного `init`.
4. Записи субагента несут `parent_tool_use_id` вызова Agent. **Его реплики
   приходят в поток и без `--forward-subagent-text`** (проверено адаптером
   панели, где флаг не передаётся).
5. `system/init` приходит на каждое сообщение в режиме stream-json.

## Что из этого сделано в панели

Адаптер Claude держит ход, пока идут субагенты (`local_agent`), открыт запрос
модели или ждётся итоговый запрос после окончания субагента; фоновые Bash ход
не держат. Если продолжения нет — ход закрывается через
`backgroundGraceMs` (60 с). Действия и реплики субагента помечены
`parentCallId`; рецензент видит «субагент вызова X», интерфейс — бусину в
ободке, метку «субагент» и приглушённый блок «Субагент». Живая проверка через
адаптер: один `turn_completed` после итоговой реплики, Claude занят всё время
работы субагента.
