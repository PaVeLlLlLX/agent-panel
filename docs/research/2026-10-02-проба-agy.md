# Проба Antigravity CLI (`agy`) как третьего агента панели

02.10.2026, Windows 10, `agy` 1.2.14 (обёртка `agy-wrapper` 1.6.5), аккаунт
Google с подпиской AI Pro. Прогоны — во временной папке вне проекта, модель
`gemini-3.8-flash-low`; около десятка ходов заняли ≈0,6% пятичасового окна и
≈0,1% недели. Общий `~/.gemini/antigravity-cli/settings.json` на время проверок
правил менялся и каждый раз возвращался к исходному.

## Зачем

Gemini по подписке, без API-ключа: Gemini CLI со входом Google для личных
аккаунтов закрыт, замена — официальный `agy` (вход аккаунтом Google). Прежде
чем проектировать адаптер, надо было знать, что `agy` умеет без интерфейса на
самом деле: документация (https://antigravity.google/docs/cli/headless/)
местами расходится с программой.

## Установка и вход

- `irm https://antigravity.google/cli/install.ps1 | iex` ставит
  `%LOCALAPPDATA%\agy\bin\agy.exe` (обёртка) и `agy.exe.real` и пишет в
  пользовательский PATH `%LOCALAPPDATA%\agy\bin` как `REG_EXPAND_SZ` —
  правильно. Уже открытые процессы (терминал, VS Code) нового PATH не видят:
  панели надёжнее искать `agy` по этому пути самой.
- `agy` обновляется сам: 02.10 в 14:34 без запроса.
- **Проверка региона.** Сразу после входа (13:41) сервер отметил аккаунт:
  «Account ineligible: … not currently available in your location»; ход в
  режиме `-p` падал с «Eligibility check failed», кодом 1 и нулевым
  расходом. В 14:35 тот же ход прошёл. Причина отказа по журналу не видна;
  панель должна считать его возможным в любой момент.
- `agy models` работает и при отказе по региону: каталог проверкой не закрыт.

## Протокол без интерфейса

| Что | Как установлено |
|---|---|
| Несколько ходов в одном процессе | `agy -p="" --input-format stream-json --output-format stream-json`; строка на ход `{"event":"user","message":{"content":"…"}}`. `-p` без значения съедает следующий флаг («-p took "--input-format" as its prompt»), `-p` последним — «flag needs an argument» |
| События | `init` (conversation_id, tools, permission_mode, model, agent), `step_update` (step_index, state ACTIVE/DONE/ERROR, step_type user_input/agent_response/tool, text_delta, usage, tool_info), `result` на каждый ход |
| Расход | `usage` у `step_update` — один вызов модели; у `result` — **накопительно** за процесс. `cache_read_tokens` во всех прогонах 0 |
| Встроенная часть | ≈12 000 входных токенов на каждый вызов модели («привет» — 12 250) |
| Продолжение | `--conversation <id>` в новом процессе: счёт ходов продолжился (6, 7, 8), модель вспомнила число из первого процесса |
| Вывод инструментов | в поток почти не попадает: `view_file` — «2 lines, 21 bytes», у `search_web`, `read_url_content` поля `output` нет |
| Прервать | управляющих сообщений в `stream-json` нет; только остановка процесса и продолжение через `--conversation` |
| `--print-timeout` | по умолчанию `0s` — ждать до конца хода (документация писала 5 мин) |
| `--effort` | low, medium, high, max; у Gemini уровень зашит в имя модели (`-low`, `-medium`, `-high`) |
| Модели (AI Pro) | `gemini-3.8/3.7/3.6-flash-{high,medium,low}`, `gemini-3.1-pro-{high,low}`, `claude-sonnet-4-6`, `claude-opus-4-6-thinking`, `gpt-oss-120b-medium` |
| Квота | `agy -p "/usage" --output-format json` — без хода модели и без расхода: группы «Gemini Models» (Flash и Pro делят квоту) и «Claude and GPT models», у каждой `weekly` и `5h` с `remaining_fraction` и `reset_time`. Из Git Bash — с `MSYS_NO_PATHCONV=1`, иначе `/usage` превращается в путь Windows и уходит модели как запрос |
| Ошибки модели | по журналу изменений — код 3 и строка `AGY_ERROR: {…}` в stderr; живьём не воспроизводилось |

## Разрешения

| Настройка | Чтение файла проекта | Запись / правка | Команда | Веб |
|---|---|---|---|---|
| по умолчанию (`request-review`) | да | **да, без вопроса** | мягкий отказ | `search_web` да, `read_url_content` мягкий отказ |
| `"toolPermission": "strict"` | мягкий отказ | не выполнена, но шаг `DONE` | — | — |
| `strict` + `allow read_file(*)` | мягкий отказ | не выполнена, шаг `DONE` | — | — |
| по умолчанию + `deny: write_file(*), command(*)`, `allow: read_url(*)` | да | **явная ошибка, ход продолжается** | явная ошибка | да |

- **Мягкий отказ** — действию нужно согласие, а спросить некого. Ход
  кончается со `status: SUCCESS` и **пустым** ответом; шаг иногда `DONE` без
  ошибки (`read_url_content`, `write_to_file` в `strict`); отказ виден только в
  `denied_actions` (накопительно за процесс) и в stderr («jetski: no output
  produced — a tool required the "…" permission…»).
- **Запрет правилом** (`permissions.deny`) — шаг `ERROR` с «permission check
  failed … Matches user-configured deny rule», модель получает отказ и
  отвечает; в `denied_actions` не попадает. `write_file(*)` закрывает и
  создание (`write_to_file`), и правку (`replace_file_content`).
- Имена действий в правилах (из программы): `read_file`, `write_file`,
  `read_url`, `command`, `mcp`; цель — `(*)` или шаблон.
- Настройки только общие: другого файла настроек или переменной окружения для
  него в программе не нашлось.

## Свой агент (`agent.md`)

- `~/.gemini/config/agents/<имя>/agent.md` и `~/.gemini/config/agents/<имя>.md`
  находятся (`agy agents`), выбираются `--agent <имя>`.
- Заголовок YAML: `name`, `description`, `mainAgent`, `tools`, `disabledTools`,
  `excludeDefaultComponents`, `commandExecutionPolicy`, `model`,
  `inheritCustomizations` и др.; тело после `# …` — системная инструкция.
- Инструкция применилась (ответы начинались словом из неё).
- С `excludeDefaultComponents: true` встроенная часть ≈2 800 токенов на вызов
  вместо ≈12 000.
- **`tools` не ограничивает инструменты:** в `init` по-прежнему весь набор,
  отказ писать держался на инструкции. Гарантия — только правила `deny`.
- Без встроенной части Flash искал файлы не в той папке: `find_by_name` упал по
  сроку, `grep_search` вышел за пределы проекта и получил мягкий отказ — ход
  кончился пустым ответом.

## Веб: поиска мало

Агент без `read_url_content` по одному `search_web` назвал последней версией
scikit-learn 1.7.0 со ссылкой на PyPI; чтение `https://pypi.org/pypi/scikit-learn/json`
в другом прогоне дало 1.9.1. Фрагменты поиска устаревают, а модель подаёт их
как проверенный факт — для проверки фактов нужно чтение страниц
(`allow read_url(*)`) и ссылка с датой в ответе.

## Проба адаптера панели (02.10.2026, Task 13)

Та же машина, тот же `agy`. Правила «только чтение» добавлены кнопкой
(`addReadOnlyRules`) в общий `settings.json`, который до этого не содержал
`permissions` вовсе; резервная копия — `agy-settings.backup.json` рядом с
брифом. `scripts/gemini-probe.mjs` запущен дважды (`gemini-probe-exclude.json`
без `--keep-default-components`, `gemini-probe-full.json` с ним), затем
`scripts/e2e-probe.mjs --gemini` — один раз, без повторов, без «Eligibility
check failed».

### Проба адаптера: чтение, запись, веб, продолжение

Оба прогона (без встроенной части и с ней) дали одинаковый результат по
существу:

- **Чтение** — `readAnswer: "4817"` (верное значение `SEED`), `readTools:
  ["view_file"]`, `readInsideProject: true`, `readIncomplete: null` в обоих
  прогонах. Разница с прежней пробой (без встроенной части агент искал файлы
  не в той папке) объясняется тем, что `GeminiAdapter.formatForGemini` сам
  кладёт в каждое сообщение шапку «[папка проекта: … — ищи и читай файлы
  только в ней]» — раньше этой шапки не было.
- **Запись/команда** — `writeDenied: []` в обоих прогонах, но
  `filesUnchanged: true`: файл `out.txt` не появился, `git status` не
  изменился. Причина — не правило `deny` в `settings.json`, а сама роль
  рецензента: `agent.md` прямо требует «Файлы не меняешь и команды не
  запускаешь… Если шаг не затрагивает ни эксперимент, ни внешние факты,
  ответь «принято»», и на вопрос «создай файл, выполни команду» модель ответила
  «Принято: задача содержит лишь базовые действия с файловой системой и
  терминалом…» без единого вызова инструмента (проверено отдельным прогоном
  `write-debug.json` со всеми событиями хода). Правило `deny` в `settings.json`
  при этом не снято и остаётся второй линией защиты: его срабатывание на
  настоящем `write_to_file`/`run_command` с явной ошибкой «permission check
  failed» показано отдельно в разделе «Разрешения» выше (там агент без ролевого
  запрета). Для панели это означает: ожидать от свидетельства
  «отклонено правилом «только чтение»: …» в ленте не стоит всегда — дисциплинированный
  рецензент сам не пытается, и `approval_decided` не появляется, но итог
  (файлы не изменились) тот же.
- **Веб** — `webTools` содержит `read_url_content`, `webAnswer` — версия
  scikit-learn 1.9.1 со ссылкой на `https://pypi.org/pypi/scikit-learn/json`
  и датой проверки — как и ожидалось.
- **Продолжение** — `resumedAnswer: "4817"` в новом процессе через
  `--conversation`: модель помнит число из первого процесса.
- **Токены на ход** — вход у хода чтения 7303 (без встроенной части) против
  10582 (с ней); на ходе с веб-поиском и чтением страницы — 38377 против
  51638. Экономия от `excludeDefaultComponents: true` подтверждена и на
  живом рецензенте, без потери точности чтения.
- **Квота** — `usage.weekPercent` 0 в обоих прогонах, `windowPercent` 0 и 1 —
  около десятка ходов обошлись в доли процента недельного окна, как и в
  первой пробе.

### Решение `EXCLUDE_DEFAULT_COMPONENTS`

Условие задачи («без встроенной части `readInsideProject` ложно или
`readIncomplete` не `null`, а с ней всё верно») не выполнилось: оба прогона
дали `readInsideProject: true` и `readIncomplete: null`. Значение остаётся
`true` (см. комментарий над константой в `src/geminiSetup.ts`): токены
экономятся, точность чтения не страдает — благодаря шапке с папкой проекта,
которую добавляет сам адаптер.

### Сквозная проба: пара рецензентов на ML-задаче с утечкой

`node scripts/e2e-probe.mjs --gemini` — один прогон, 68 секунд, без повторов.
Задача: написать `evaluate.py`, который нормализует `x` по всем строкам
(включая `test`) и считает точность правила `x>0` на `test`; в `data.csv`
нарочно `id=3` присутствует и в `train`, и в `test`.

- **Раунд 1.** Claude написал скрипт и применил правило `x>0` к
  *нормализованному* `x`. Codex сразу поставил замечание («вывод `Accuracy:
  1.0` подтверждает, что все три тестовые строки классифицированы…» — по сути
  о некорректном применении правила к `x_norm`, а не к исходному `x`). Gemini
  тем же ходом (`gemini turn_completed`, 10156 входных токенов) выдал чек-лист
  методологии и явно назвал утечку: «в исходных данных `data.csv`
  присутствует пересечение сущностей по идентификатору: объект с `id=3`
  находится одновременно в `train`… и в `test`…» и «нормализация… выполнена
  по совокупности всех строк (включая `test`)… это представляет собой
  информационную утечку тестовой выборки» — но дал вердикт «ПРИНЯТО», оформив
  утечку как «пробел» (разработчику явно зафиксировать её в выводах), потому
  что нормализация по всем строкам была прямым требованием постановки задачи
  человеком. Итог проверки 1 — «Codex: есть замечания, Gemini: принято»;
  решение по общему вердикту — по Codex (есть замечания), цикл продолжился.
- **Раунд 2.** Claude применил правило `x>0` к исходному `x` (эту правку
  Codex и просил). Codex принял, Gemini повторил чек-лист (та же утечка
  `id=3`, тот же статус «вызвано ТЗ человека») и снова дал «ПРИНЯТО». Цикл
  кончился `accepted`.
- **Trail** — ромбы `codex`/`gemini` на обеих проверках с отметками: раунд 1
  `codex "!"`, `gemini "✓"`; раунд 2 `codex "✓"`, `gemini "✓"`.
- **Расход** — `usage.task.gemini = {"input": 17590, "cached": 0, "output":
  1591}` (больше нуля, как ожидалось), `codex` — 40071/26112/236, `claude` —
  257339/184617/3841.
- **`geminiFirst`** (первая реплика Gemini, обрезано до 400 символов)
  содержит и «Утечки», и «пересечен» — ожидание из брифа выполнено.

Таким образом Gemini нашёл обе формы утечки (пересечение `id` между `train`
и `test`, нормализация по всем строкам) чек-листом в первом же ходе, но не
посчитал её основанием для отказа, раз она была прямо заказана условием
задачи, — поведение роли («пробел», а не «замечание», когда расхождение
исходит от самого человека) совпало с его системной инструкцией.
