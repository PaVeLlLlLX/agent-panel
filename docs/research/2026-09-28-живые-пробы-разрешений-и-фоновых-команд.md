# Живые пробы: разрешения, два субагента, фоновая команда

Дата: 2026-09-28, 04:25–04:45 (UTC+7). Claude Code 2.1.220, haiku; Codex
0.155.0-alpha.16 из расширения ChatGPT (gpt-6-luna, low). Всё — во временных
папках, вне VS Code, комнаты и ветки владельца не затронуты.

## 1. Ответ «разрешить» настоящему Claude

`scripts/permission-probe.mjs`, режим `default`, панель отвечает сразу.

| Шаг | Запрос | Подсказки CLI (`permission_suggestions`) | Ответ панели | Итог |
|---|---|---|---|---|
| Write `amber.txt` | да | `setMode acceptEdits` (сессия) | разрешить | файл создан, «янтарь» |
| `echo one > bash-one.txt` | да, `blocked_path` = файл | `addRules Bash(echo one *)` (localSettings), `addDirectories` папки (сессия) | в этой сессии: `Bash(echo one *)` | выполнено |
| та же команда | **снова да** | те же | отклонить | отклонено |
| `python -c "print(2+2)"` | да | `addRules` (localSettings) | в этой сессии | выполнено |
| та же команда | **нет** | — | — | выполнено без вопроса |
| `mkdir -p probe-dir` | да, `blocked_path` | `addRules`, `addDirectories`, `setMode acceptEdits` | в этой сессии | выполнено |
| та же команда | **нет** | — | — | выполнено без вопроса |

Повтор с перенаправлением проверен трижды, в том числе с временной правкой
адаптера, передававшей и `addDirectories`: вопрос остаётся. Значит, дело не в
том, что панель передаёт только правила: вопрос о записи перенаправлением CLI
задаёт независимо от правила на команду. `node --version` вопроса не вызывает
вовсе (список команд только для чтения).

**Вывод.** «Разрешить» и «в этой сессии» работают живьём. Кнопка «в этой
сессии» для команды с `>` в файл вопроса не снимает — это поведение CLI, в
README записано как ограничение. Одна форма команды; другие виды записи
(`tee`, `>>`) не проверялись.

## 2. Два фоновых субагента сразу

`scripts/e2e-probe.mjs --two-subagents`: первый создаёт файл, второй сначала
`sleep 25`.

- Панель: «ход продолжается: Claude ждёт субагентов (2)», ход держался до
  обоих итогов (44 с), действия двух субагентов с двумя разными
  `parentCallId`, рецензия началась после.
- Второй субагент сам запустил свою команду **в фоне** (PowerShell) и ответил
  «команда выполняется в фоне». Субагент закончился, команда — нет; Claude
  проверил файл раньше, чем он появился, и доложил, что файла нет. Рецензент
  (без вердикта) отметил невыполненное требование. Панель тут ни при чём:
  фоновые команды ход не держат намеренно.

## 3. Фоновая команда кончается после хода

Сырая трасса (`night-shift/bg-bash-trace.txt`, прямой запуск CLI):

```
7.0s  assistant  tool_use:Bash {"command":"sleep 20; echo поздно > late.txt", …, "run_in_background": true}
7.7s  system     background_tasks_changed [{task_type: local_bash, …}]
7.7s  system     task_started {task_type: local_bash}
12.0s assistant  text «Запущено.»
12.0s result     success
27.9s system     background_tasks_changed []
27.9s system     task_updated {status: completed}
27.9s system     task_notification {summary: "Background command \"…\" completed (exit code 0)"}
27.9s system     init                       ← без сообщения панели
32.8s assistant  text «Команда завершена успешно.»
32.8s result     success
```

Между ними — десятки записей `system/thinking_tokens` (адаптер их не
показывает). Без сообщения CLI ничего не пишет: 12 с после запуска — ни одной
записи, `init` приходит только с работой.

**Дефект и исправление (2f04ee8).** Координатор снимал для такого хода цель из
очереди и мог принять его за ответ на следующее сообщение. Теперь адаптер
помечает ход «самостоятельным» (`unsolicited`), координатор сообщает человеку
«Claude продолжил сам (фоновая задача закончилась: …)», не передаёт ход
рецензенту и не считает в расход задачи.

Проверка живьём (`e2e-probe.mjs --background-bash`, `sleep 15`): рецензент
сделал замечание, Claude ответил (27,5 с); команда кончилась, пока он отвечал,
и CLI **дождался конца ответа**, а свой ход начал следом. Ответ на замечание
ушёл на вторую проверку, цикл принят; самостоятельный ход пришёл после и на
цикл не повлиял.

## 4. Гонка и эхо сообщений

Рецензия Codex (`2026-09-28-рецензия-codex-самостоятельного-хода.md`): если
сообщение панели ушло, когда CLI уже начал свой запрос, а `init` ещё в пути,
по занятости адаптера их не различить.

- С `--replay-user-messages` CLI повторяет сообщение записью `user` с
  `"isReplay": true` — после `init` своего запроса, перед ответом модели.
  Второе сообщение, посланное через 0,1 с во время первого хода, повторено
  через 9,7 с — в своём запросе, а не при получении.
- В самостоятельном запросе эха нет.
- `scripts/race-probe.mjs`: посредник придерживает строки CLI 2 с после
  `task_notification`, проба в это окно шлёт сообщение. Итог: ход CLI
  («Завершено.») выдан `unsolicited`, адаптер остаётся занятым; ответ на
  сообщение («Второе.») — обычным концом хода.
- После включения эха живые `live-probe` (ход и возобновление) и
  `e2e-probe` (цикл рецензии принят за 19 с) прошли.
