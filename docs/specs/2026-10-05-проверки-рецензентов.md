# Проверки рецензентов: свои скрипты в песочнице

Спецификация, 05.10.2026. Согласована с владельцем по разделам в беседе 05.10.

## Зачем

Codex и Gemini проверяют работу Claude только по тому, что Claude напечатал. За 61 ход
в комнате Trading (04–05.10) Codex не открыл ни одного файла и не запустил ни одной
команды: его роль прямо говорит «команды не запускай» (`src/adapters/codex.ts`). Из-за
этого целые проверки уходили на просьбы «пересчитайте» и «есть ли такие случаи» —
утверждения, которые проверяются маленьким скриптом: формула просадки на отрезке,
`fillna(0.0)` вместо «неизвестное не равно нулю», мощность на синтетике. Gemini в той же
версии написал «неизвестные не заменяются нулями», а Codex нашёл `fillna(0.0)`.

Цель — рецензенты сами проверяют свои утверждения скриптами, не трогая проект и данные.
Успех: в проверках появляются выводы скриптов рецензентов как свидетельства, просьб
«пересчитайте» к Claude становится меньше, а запись вне папки рецензента и чтение данных
проекта не происходят.

## Решения владельца (05.10)

1. **Данные.** Скрипты рецензентов не читают данные проекта: только код, синтетические
   данные и числа из материала Claude. `data/` и `.env` закрыты.
2. **Защита.** Сначала проба песочницы на одноразовой ветке; по её итогам владелец
   выбирает между усиленной песочницей Codex и ролью с журналом и стоп-сигналом.
3. **Ветка Codex.** У рецензента своя ветка на комнату; чат владельца панель больше не
   продолжает.
4. **Gemini.** Gemini приводит скрипт в ответе, панель выполняет его в песочнице Codex и
   возвращает вывод.
5. **Claude.** Скрипты рецензентов Claude только читает вместе с выводом и не запускает.
6. **Подход.** Codex пишет и запускает скрипты сам; за Gemini запускает панель.

## Что установлено о песочницах (05.10, без хода модели)

Источник — исходники Codex `rust-v0.159.0-alpha.12` (та же версия, что `codex.exe`
расширения ChatGPT), схема протокола `codex app-server generate-json-schema`, журналы
песочницы в `~/.codex`, документация agy.

- **Codex, песочница на этой машине — «unelevated»** (`[windows] sandbox="unelevated"`):
  ограниченный токен `WRITE_RESTRICTED`. Запись — только в корни, на которые Codex
  дописал разрешение в ACL. **Чтение не ограничено**: команда читает всё, что читает
  пользователь, включая `Trading/.env`. **Сеть** режется только переменными окружения
  (прокси `127.0.0.1:9`, заглушки ssh); сырой сокет и `aiohttp` их обходят.
- **«Писать только в одну папку, остальное читать» — достижимо** профилем прав,
  переданным в `config` при `thread/start`/`thread/resume` (`default_permissions` +
  таблица `permissions`, поле `sandbox` при этом не передаётся). Устаревший
  `sandboxPolicy: workspaceWrite` не годится: рабочая папка всегда становится корнем
  записи.
- **Команды без одобрений**: `approvalPolicy: "never"` — запрещённое действие сразу
  возвращается модели отказом.
- **`command/exec`** выполняет команду в песочнице сервера без ветки и хода модели —
  на этом держатся самопроверка и запуск скриптов Gemini.
- **Усиленная песочница** («elevated», разовая установка с правами администратора):
  отдельный пользователь, брандмауэр, запрет чтения по путям. Можно ли включить её
  только для ветки панели — не проверено.
- **agy**: писать в одну папку внутри проекта нельзя, правила общие для всех запусков,
  песочница командной строки на Windows не задокументирована. Поэтому Gemini скрипты
  сам не запускает.

## Ступени

Каждая ступень работает без следующих.

0. **Проба** (раздел «Проба»). До неё ступени 2–3 не включаются.
1. **Своя ветка рецензента Codex; Codex читает репозиторий командами.**
2. **Папка для скриптов Codex.**
3. **Проверки Gemini через панель.**

## Ступень 1. Ветка рецензента Codex

- Панель заводит ветку Codex на комнату: `thread/start`, рабочая папка — проект, роль —
  рецензент. Номер хранится в новой колонке журнала `rooms.codex_review_thread`.
  Прежняя `rooms.codex_thread` (чат владельца, `01a09f7b…` у Trading) больше не
  продолжается и остаётся в журнале как история.
- Команда «Agent Panel: новая сессия Codex для комнаты» сбрасывает
  `codex_review_thread`; следующая проверка заводит новую ветку.
- Модель и уровень выбираются как сейчас.
- Роль Codex (`REVIEWER_INSTRUCTIONS`):
  - можно читать репозиторий командами: `rg`, `git log`/`show`/`diff`, `python -c` над
    кодом;
  - нельзя: файлы и каталоги из запрещённого списка (`data/`, `.env` для Trading — см.
    «Настройки»), сеть, любые изменения в проекте, долгие и фоновые процессы;
  - правила вердикта не меняются.
- Права ветки на этой ступени — прежние: `sandbox: "read-only"`, `approvalPolicy: "never"`.

## Ступень 2. Папка для скриптов Codex

**Папка**: `%LOCALAPPDATA%\agent-panel\review\<комната>\codex\` и в ней `tmp\`. Вне
репозитория: не попадает в `git status`, `git add -A` у Claude, pytest и линтеры
проекта. Создаётся панелью до запуска процесса (корень записи учитывается, только если
существует). Хранится между проверками. В комнате — ссылка «Папка проверок»; очистка —
только командой владельца. Больше 500 МБ — предупреждение в ленте.

**Профиль прав** — в `config` при `thread/start` и `thread/resume`, без поля `sandbox`:

```jsonc
{
  "approvalPolicy": "never",
  "config": {
    "default_permissions": "agent-panel-review",
    "permissions": {
      "agent-panel-review": {
        "filesystem": { ":root": "read", "<папка codex>": "write" },
        "network": { "enabled": false }
      }
    },
    "shell_environment_policy": {
      "set": { "TEMP": "<папка codex>\\tmp", "TMP": "<папка codex>\\tmp",
               "PYTHONDONTWRITEBYTECODE": "1", "MPLCONFIGDIR": "<папка codex>\\tmp\\mpl" }
    }
  }
}
```

Точная форма — по итогам пробы (п. 1–2): принимает ли `thread/resume` профиль и
сохраняет ли его ветка.

**Роль Codex дополняется**: скрипты и их выводы — только в своей папке; в замечании —
путь скрипта и строки вывода; бюджет — не больше 20 команд и 10 минут счёта за
проверку; данные проекта не читать даже через импорт кода проекта, работать на
синтетике и числах из материала.

**Самопроверка** — перед каждым запуском процесса Codex, без хода модели, через
`command/exec` с той же политикой:
1. запись `<папка codex>\probe.txt` — должна пройти;
2. запись в проект — должна быть отклонена;
3. при усиленной песочнице — чтение файла из запрещённого списка и выход в сеть тоже
   должны быть отклонены.

Любое расхождение, а также отказ app-server принять профиль — ветка запускается
«только чтение» (ступень 1), в ленте строка «Песочница Codex не прошла проверку: …»,
подробности — в диагностике. Проверка при каждом запуске, потому что Codex обновляется
вместе с расширением (0.153 → 0.159 за три недели).

**Стоп-сигнал.** Команды Codex приходят панели событием начала команды. Если команда
содержит фрагмент из запрещённого списка, панель прерывает ход Codex, пишет в ленте
«Codex обратился к запрещённому пути: <фрагмент> — проверка остановлена» и считает ход
сорвавшимся: дальше решает владелец. Скрипт, читающий данные через импорт кода
проекта, стоп-сигнал не ловит — это остаточный риск без усиленной песочницы.

## Ступень 3. Проверки Gemini через панель

**Формат в ответе Gemini** — не больше трёх блоков:

````
```проверка python
# имя: просадка на отрезке [-0.2, 0]
…код…
```
````

Только Python. Роль Gemini (`reviewerAgentMarkdown`) и `GEMINI.md` Trading получают
правило: блок «проверка» — для утверждения, которое проверяется вычислением над кодом,
синтетикой или числами из материала; данные проекта, `.env` и сеть запрещены.

**Порядок**:
1. Ход Gemini закончился. Если в ответе есть блоки «проверка» и проверки включены, его
   вердикт — предварительный.
2. Каждый скрипт проходит стоп-сигнал до запуска: скрипт с фрагментом из запрещённого
   списка не запускается, в выводе — «не запущено: обращается к <фрагмент>».
3. Панель пишет файл в `%LOCALAPPDATA%\agent-panel\review\<комната>\gemini\` и выполняет
   его отдельным коротким процессом `codex app-server` (как `listModels`) через
   `command/exec`: рабочая папка — папка Gemini, запись только в неё, сеть выключена,
   Python — из `.venv` проекта, если есть, иначе `python`. 60 секунд на скрипт; по
   истечении — снятие дерева процесса и «превышено время». Вывод обрезается до 20 000
   знаков.
4. Тем же разговором Gemini получает сообщение «[вывод твоих проверок]»: по каждому
   скрипту имя, код выхода и вывод, с просьбой дать окончательный вердикт. Вердикт этого
   хода — исход Gemini в паре.
5. Круг один: новые блоки во втором ответе не выполняются, в ленте об этом строка.

**Сроки.** Время прогона скриптов — признак жизни Gemini: детектор молчания на это
время не срабатывает. Общий срок проверки прежний: 20 минут после ответа Codex при его
замечаниях, иначе предел 45 минут.

**Сбои.** Исполнитель не запустился или его самопроверка не прошла — скрипты не
выполняются, Gemini получает «проверки недоступны: <причина>» и выносит вердикт без
них. Второй ход сорвался — берётся предварительный вердикт с пометкой в ленте.

## Решения пробы

Проба прошла 05.10 (`scripts/codex-sandbox-probe.mjs`; подробности, сырые
ответы и источники — `docs/research/2026-10-05-проба-песочницы-codex.md`):
`codex-cli 0.159.0-alpha.12.1` из расширения ChatGPT, песочница unelevated,
новая одноразовая ветка, временная папка-проект с маркером вместо `.env`,
четыре коротких хода модели. Чат владельца, Trading и `~/.codex/config.toml`
не тронуты. П. 5 не выполнялся: усиленная песочница требует установки с
правами администратора и отдельного решения владельца.

| Пункт | Итог |
|---|---|
| 1. Новая ветка с профилем, рабочая папка — проект | профиль принят (`sandbox: workspaceWrite`, `activePermissionProfile: agent-panel-review`), но **все команды отвергнуты до запуска**: unelevated не запускает команд под профилем, в корнях записи которого нет рабочей папки («split writable root sets») |
| 2. Продолжение с `config`, рабочая папка — папка рецензента (проверки п. 1 повторены здесь) | профиль принят. Запись в папку прошла, в проект — отклонена; маркер **прочитан**; `urllib` упёрся в прокси `127.0.0.1:9`, **сырой сокет вышел в сеть**; фоновый python **пережил** и команду, и остановку app-server |
| 2. Продолжение без `config` | профиль **не сохранился**: `readOnly`, запись отклонена везде |
| 3. Самопроверка через `command/exec` | те же исходы записи, но только со строгой политикой (`excludeTmpdirEnvVar`, `excludeSlashTmp`): без неё корнем записи становится `%TEMP%` пользователя. Отказ песочницы и превышение срока — ошибка JSON-RPC, а не код выхода |
| 4. Python из `.venv` под профилем | работает и в ходе модели, и через `command/exec`; импорт кода проекта не оставляет `__pycache__`; `TEMP`/`TMP`/`MPLCONFIGDIR` из `shell_environment_policy.set` доходят до команд модели |
| 5. Усиленная песочница | не проверялась |

Что это меняет (так и реализовано):

- **Ступень 2: рабочая папка ветки — папка Codex, а не проект.** Проект
  рецензент читает по абсолютным путям (`rg … <проект>`, `git -C <проект>`);
  роль велит прочитать `<проект>\AGENTS.md`. Ступень 1 — по-прежнему с
  рабочей папкой-проектом.
- **`config` с профилем — при каждом `thread/start` и `thread/resume`**, в том
  числе при перезапуске после сбоя и смене модели.
- **Принятие профиля — по ответу** `thread/start`/`thread/resume`: рабочая
  папка, `sandbox`, `activePermissionProfile`. `command/exec` отказ «split
  writable root sets» не видит. Расхождение — откат в «только чтение».
- **`command/exec` — только со строгой политикой**; скрипты Gemini — ещё и с
  `env` (`TEMP`/`TMP` в папке: `shell_environment_policy` к `command/exec`
  не относится). Самопроверка: запись в папку — код 0 и файл на диске; запись
  в проект — отказ (ошибка «sandbox denied» или ненулевой код) и файла нет.
  Пишет `python -c` с путём в аргументе, а не `cmd /c echo`: путь с
  пробелами `cmd` через кавычки аргументов не переносит.
- **Исполнитель скриптов Gemini** разбирает три исхода: ответ `{exitCode,
  stdout, stderr}`; ошибку «sandbox denied exec error, exit code: N, stdout:
  …, stderr: …» (код и вывод — из текста); ошибку «command timed out» —
  «превышено время» без вывода.
- **Фоновые процессы** после скриптов Gemini панель снимает сама — по пути
  папки в командной строке; процесс без этого пути так не найти (остаточный
  риск). После хода Codex такого поиска нет: остаётся правило роли.
- **Самопроверка при усиленной песочнице** (чтение запрещённого файла, выход
  в сеть) не реализована: усиленная песочница не проверялась.

**Защита.** Выбор между усиленной песочницей Codex и ролью с журналом и
стоп-сигналом остаётся за владельцем. Реализован второй путь: unelevated,
правила ролей, стоп-сигнал, журнал команд, самопроверка с откатом. Ступени
2–3 по умолчанию выключены (`agentPanel.reviewerChecks: false`) и
включаются владельцем. «Гарантии» ниже не меняются: проба подтвердила
живьём, что чтение данных и сеть без усиленной песочницы не закрыты.

## Гарантии

- **ОС гарантирует**: запись рецензентов только в их папки; никаких одобрений.
- **Без усиленной песочницы не гарантировано**: чтение `data/` и `.env`, выход в сеть.
- **Закрываем**: правило «без данных» в ролях, стоп-сигнал, журнал всех команд, запрет
  Claude запускать скрипты рецензентов, папки вне репозитория, самопроверка с откатом,
  выключатели.

## Тесты

Фальшивый Codex (`fixtures/fake-codex.mjs`) учится: принимать профиль в `config`
`thread/start`/`thread/resume` и отказывать в нём по управляющему слову; выполнять
`command/exec` с исходами по управляющим словам (запись прошла/отклонена, превышено
время); присылать `commandExecution` с запрещённым фрагментом.

- **Адаптер Codex**: параметры ветки с профилем; без профиля — `read-only`; провал
  самопроверки и отказ в профиле — откат в «только чтение»; привязка
  `codex_review_thread`, прежний `codex_thread` не продолжается.
- **Координатор**: стоп-сигнал на команде Codex прерывает ход; разбор блоков
  «проверка»; скрипт с `data/` не запускается; второй ход Gemini и вердикт из него;
  откат на предварительный вердикт; детектор молчания на время прогона; блок «Проверки
  рецензента» в сообщении Claude.
- **Журнал**: колонки `codex_review_thread`, `reviewer_checks` с переносом прежней базы.
