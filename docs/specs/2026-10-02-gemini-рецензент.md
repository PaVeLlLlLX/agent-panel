# Gemini — второй рецензент: методология и факты

Согласовано с владельцем 02.10.2026 по разделам: роль, пара рецензентов в
цикле, адаптер и подготовка `agy`, интерфейс, проверки. Факты об `agy` — из
живой пробы: `docs/research/2026-10-02-проба-agy.md`. Макеты выбранных
вариантов — `docs/design/gemini/`. Критика первой версии роли — Codex, 02.10.

## Зачем

Владелец — MLE/DS, всегда работает режимом «Задача с рецензией» и хочет
использовать в нём Gemini по максимуму. Gemini даёт то, чего нет у пары
Claude ↔ Codex: модель другого семейства (ошибки рецензентов меньше
совпадают), отдельную квоту и проверку фактов по вебу.

## Ограничения

- **Только подписка Google AI Pro, без API-ключа.** Агент — официальный
  Antigravity CLI `agy` со входом аккаунтом Google. Сторонние обёртки,
  подставляющие вход по подписке в чужие программы, не используются.
- **`agy` нужен только панели** (владелец, 02.10): правила «только чтение» в
  общих настройках `agy` допустимы.
- **Доступ может пропасть.** 02.10 сервер отказал по региону («Eligibility
  check failed»), через час пропустил. Сбой Gemini никогда не блокирует цикл.
- **Пишет файлы по-прежнему один Claude.** Gemini — только чтение.

## Роль

| | Codex | Gemini |
|---|---|---|
| Место | главный арбитр по коду | второй рецензент в **каждой** проверке, параллельно и независимо |
| Что проверяет | правильность кода, соответствие задаче, сырой вывод команд | **1)** методологию эксперимента — чек-листом; **2)** факты вне репозитория по вебу |
| Доступ | песочница только для чтения | правила `agy`: запись и команды запрещены, чтение файлов и страниц разрешено |
| Вердикт | `ВЕРДИКТ: …` последней строкой | то же, тот же разбор `verdict.ts` |

**Чек-лист методологии:** утечки, разбиения, метрики, бейзлайн, сиды и
разброс, обоснованность выводов. У каждого пункта — «свидетельство: …»
(откуда, например вызов Claude) или «пробел: …». Пробел оформляется просьбой к
Claude показать недостающее («выведи пересечение id train/test»); следующая
проверка видит вывод. Так рецензент только на чтение всё же опирается на
запуски.

**Факты** — API и версии библиотек, документация, статьи — с адресом страницы и
датой проверки. Без них факт не засчитывается: поиск без чтения страницы дал
в пробе устаревшую версию scikit-learn.

**Шаг без эксперимента и внешних фактов** — «принято» с одной строкой
пояснения. Полного второго взгляда на код нет: он дублировал бы Codex и тратил
квоту без вопроса.

Gemini не видит отзыва Codex: иначе пропадает независимость.

## Цикл: пара рецензентов

```
Claude закончил ─► снимок A ─┬─► Codex:  код                ─┐
                             └─► Gemini: методология, факты  ─┴─► сведение ─► принято / Claude / вы
```

- **Отправка.** Одна проверка — пара. Оба получают одинаковый материал
  (задача, заметки памяти, реплики и сырой вывод Claude в пределах
  `reviewEvidenceChars`) и один снимок версии, но разные инструкции. Счётчик
  проверок растёт на 1 за пару; `maxAutoRounds` считает пары. Удержание
  (предел проверок, предел токенов, автопересылка выключена) держит пару
  целиком; кнопка — «Отправить на проверку».
- **Ожидание.** Итог — когда ответили оба. Codex ждём как сейчас. Gemini —
  не дольше `agentPanel.geminiWaitMinutes` (10) после ответа Codex; не успел —
  «не проверял». Поздний ответ виден в ленте, в проверку не входит.
  *(Изменено 03.10 — срок зависит от вердикта Codex, поздний отзыв может
  войти в удержанные замечания; см. историю изменений.)*

**Исходы проверки Gemini:**

| Исход | Когда | Последствие |
|---|---|---|
| вердикт | «принято», «есть замечания», «нужно решение человека» | участвует в сведении |
| без вердикта | ответил, последней строки-вердикта нет | ждём человека, как у Codex |
| не проверял | процесс упал; ход не `SUCCESS`; **пустой ответ**; **прирост `denied_actions`**; регион или квота; не успел (изменено 03.10 — см. историю изменений); нет правил «только чтение» | итог по одному Codex, в ленте «Gemini не проверял: причина» |

`agy` не найден — исхода нет: пара не собирается, проверяет один Codex, как
до этой работы (см. «Какой `agy`»).

**Сведение** (строже побеждает):

1. Codex или Gemini — «нужно решение человека» или без вердикта → ждём человека.
2. Иначе замечания хотя бы у одного → Claude получает **одно** сообщение:
   блоки «Codex — код» и «Gemini — методология и факты»; принявший — одной
   строкой. Если файлы сдвинулись за проверку — отметка «замечания относятся к
   версии A, сейчас B» у каждого блока.
3. Иначе → принято. Дерево сдвинулось за проверку — строка в ленте «принята
   версия A, сейчас B» (сейчас такой нет).

- **Следующий круг** — снова оба; каждый помнит свою прошлую проверку
  (сессии сохраняются).
- **Сбой Codex** останавливает цикл, как сейчас.
- **Прервать, Остановить, новая задача** — и для Gemini. Поздние ответы
  отбрасываются по номеру цикла, как сейчас.
- **Расход.** У Gemini своя доля расхода задачи и квота из `/usage`.
  `agentPanel.taskTokenLimit` считает токены всех трёх агентов.

**Что меняется в координаторе** (`src/coordinator.ts`):

- `AgentId` — плюс `"gemini"`. `Route`: `"review" | "all" | "claude" | "codex" | "gemini"`;
  `"both"` переименован в `"all"` (сохранённый в webview режим `both` читается как `all`).
- Проверка пары — отдельная запись: цикл, номер проверки, снимок, кого ждём,
  исходы по рецензентам, срок ожидания Gemini. `#afterReview` разбирает один
  ответ и, когда пара полна (или Gemini выбыл), вызывает сведение.
- `RoomState`: `geminiBusy`; в `usage` — `gemini` и `limits.gemini`
  (неделя, окно 5 ч); `trail` — шаги пары (см. «Дорожка цикла»).
- `stopAll`, `interruptAll`, `newSession` — для трёх адаптеров.

## Адаптер Gemini (`src/adapters/gemini.ts`)

**Запуск** в папке комнаты, один процесс на много ходов:

```
agy -p="" --agent agent-panel-reviewer --input-format stream-json --output-format stream-json [--model M] [--conversation ID]
```

Ход — строка `{"event":"user","message":{"content":"…"}}` в stdin.

**Какой `agy`** (`src/geminiBinary.ts`, по образцу `codexBinary.ts`): явный
путь из `agentPanel.geminiCommand` → `%LOCALAPPDATA%\agy\bin\agy.exe` (уже
открытые VS Code и терминалы нового PATH не видят) → `agy` из PATH. Не найден —
Gemini в комнате выключен: проверяет один Codex, строка в диагностике.

**Роль** — агент `~/.gemini/config/agents/agent-panel-reviewer/agent.md`.
Файл принадлежит панели: она пишет его перед запуском Gemini, если текст
отличается от текста в коде. Роль — системная инструкция, переживает
продолжение разговора (как `developerInstructions` у Codex). В инструкции —
полосы, чек-лист, правило фактов, просьбы к Claude, формат вердикта, путь
папки проекта и запрет на поиск вне её.

**Только чтение** — правила в `~/.gemini/antigravity-cli/settings.json`:

```json
"permissions": { "allow": ["read_url(*)"], "deny": ["write_file(*)", "command(*)"] }
```

Проверено пробой: создание и правка файла, команда — явная ошибка, ход
продолжается; файлы и страницы читаются. `tools` в `agent.md` гарантией не
служит. Перед запуском процесса панель читает этот файл; правил нет (или
JSON не разбирается) — Gemini не запускается (исход «не проверял», цикл идёт
с Codex), над полем ввода плашка «Gemini нужен режим только чтения» и кнопка
**«Добавить правила»**: дописывает недостающие правила, сохраняя остальное
содержимое, без повторов. Без нажатия панель файл не меняет.

**Разбор потока** в общую модель событий (`src/adapters/types.ts`):

| `agy` | Событие панели |
|---|---|
| `init` | id разговора → журнал; модель и режим → диагностика |
| `step_update` `user_input` | `turn_started` |
| `agent_response` с `text_delta` | `text_delta`; на `DONE` — `message` с собранным текстом |
| `tool` `ACTIVE` | `tool_call` / `tool_running` |
| `tool` `DONE` / `ERROR` | `tool_result` (у Gemini — краткая сводка); `ERROR` с «permission check failed» — отказ |
| `result` | `turn_completed`: расход — разность накопительного `usage`; отказы — прирост `denied_actions`; `failed` при статусе не `SUCCESS` |
| пустой `response`, прирост `denied_actions` | отметка «проверка неполная» → исход «не проверял» |
| stderr `AGY_ERROR: {…}`, «Eligibility check failed», дневной предел | `error` с причиной словами |

- **Прервать** — остановка процесса деревом (`process.ts`); следующий ход —
  `--conversation`.
- **Смена модели** — перезапуск между ходами с `--model`.
- **Новая сессия** — команда «Agent Panel: новая сессия Gemini для комнаты»;
  привязка — поле `rooms.gemini_conversation` (перенос существующей базы через
  `ALTER TABLE`, как у `events`).
- **Модели** — `agy models`; только `gemini-*`. Семейство — строкой списка,
  уровень — узлами нити из суффиксов (`-low`, `-medium`, `-high`): у Flash три
  узла, у Pro два. «По умолчанию» — модель из настроек `agy`.
- **Квота** (`src/geminiUsage.ts`, по образцу `claudeUsage.ts`) —
  `agy -p "/usage" --output-format json` после ходов Gemini и при открытии,
  не чаще раза в 5 минут; без расхода. Новой доли нет — прежняя со временем
  сведения, нулём не становится.

**Проверить живьём при реализации.** С `excludeDefaultComponents: true`
встроенная часть ≈2 800 токенов на вызов вместо ≈12 000, но в пробе Flash без
неё искал файлы вне проекта и ловил мягкий отказ. Сначала — явный путь проекта
в роли; если не помогает — агент без `excludeDefaultComponents`. Итог — в
заметку пробы.

## Интерфейс

Язык нитей сохраняется (`docs/specs/2026-09-27-облик-язык-нитей.md`).

**Цвет Gemini** — фиолетовый: тёмная тема `#A78BFA`, светлая `#7652D6`
(`--gemini` рядом с `--claude`, `--codex`).

**«Эстафета» — вилка** (`docs/design/gemini/relay-status.html`, вариант A).
96×28: огонёк Claude слева (r 7), нить раздваивается кривыми на Codex (сверху,
r 5,5) и Gemini (снизу, r 5,5). Частицы бегут по ветке, где идёт работа.

| Состояние | Огоньки | Подпись |
|---|---|---|
| Claude работает | Claude горит, частицы к нему | «Claude работает» · вердикт прошлой проверки |
| проверяют оба | горят Codex и Gemini, частицы по обеим веткам | «Codex и Gemini проверяют» |
| один закончил | закончивший тускнеет с отметкой вердикта | «Gemini проверяет» · «Codex: принято» |
| принято | все горят, ветки окрашены от Claude к каждому, ✓ на стволе | «Работа принята» · «Codex и Gemini: принято» |
| ждём вас | белый огонёк на стволе, как сейчас | как сейчас |

Точки справа — проверки пары.

**Дорожка цикла — ромбы** (`docs/design/gemini/trail-branches.html`,
вариант A). После каждого хода Claude нить расходится на Codex (сверху) и
Gemini (снизу) и сходится в следующем ходе Claude. Отметки вердиктов (`!`, `?`,
`✓`, `–`) — у каждого рецензента. «Не проверял» — пунктирное кольцо цвета
Gemini, причина при наведении. Пустые ромбы — оставшиеся проверки. Строка
расхода: «Claude … · Codex … · Gemini …», лимиты — с «Gemini: неделя N%, окно
5 ч M%».

**Режимы — пять:** «Задача с рецензией» (значок — вилка: Claude → Codex и
Gemini), «Спросить всех» (белый огонёк → три), «Только Claude», «Только
Codex», «Только Gemini» (кольцо и огонёк фиолетовые). Подсказка «Задачи с
рецензией»: «Claude сделает, Codex и Gemini проверят — до вердикта».

**Лента.** Реплики Gemini подписаны его цветом: «Gemini · проверка N ·
методология и факты · версия …»; вердикт значком и словами, под ними исходная
строка. Действия Gemini — бусины его цвета. Строки панели: «Итог проверки N:
Codex — …, Gemini — …», «Gemini не проверял: причина. Итог — по вердикту
Codex».

**Плашки над полем ввода.** «Gemini нужен режим только чтения» с кнопкой
«Добавить правила» — вид как у «ждёт вашего решения», но цикл она не держит.
Удержанная пара — обычное «ждёт вашего решения» с кнопкой «Отправить на
проверку».

**Модели — одна карточка, строка на агента**
(`docs/design/gemini/models-compact.html`, вариант A). Строка: имя цветом
агента, модель пилюлей-списком, короткая нить уровня (≈128 px); название
уровня — при наведении на узел. Внизу карточки — «вернуть по умолчанию» и
«новая сессия…» (спрашивает, для какого агента). Пояснений вида «сколько
уровней» нет, квоты в карточке нет (она в строке расхода). Три агента — около
125 px в высоту, меньше нынешней карточки одного. Кнопка «Модели» — три
полоски.

**Команды:** «Agent Panel: новая сессия Gemini для комнаты»; «остановить
обоих» → «остановить всех».

## Настройки

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `agentPanel.geminiCommand` | `agy` | исполняемый файл `agy`; `agy` — `%LOCALAPPDATA%\agy\bin\agy.exe`, иначе из PATH; явный путь важнее |
| `agentPanel.geminiWaitMinutes` | `10` | сколько минут после ответа Codex ждать Gemini; не успел — «не проверял» (изменено 03.10: по умолчанию 20 и только при замечаниях Codex — см. историю изменений) |

`agentPanel.taskTokenLimit` — описание «всех агентов» вместо «обоих».

## Проверки

**`npm test`, без сети и квоты:**

- `fixtures/fake-agy.mjs` — поток из пробы: `init`, `step_update`, `result`,
  накопительные `usage` и `denied_actions`, `ERROR` при запрете, мягкий отказ
  с пустым ответом, `AGY_ERROR`, «Eligibility check failed». Адаптер: `-p=""`,
  `--conversation`, расход хода, «не проверял», «Прервать», смена модели.
- Координатор: вся таблица сведения (вердикт Codex × исход Gemini); срок
  ожидания на поддельных часах и поздний ответ; сбой Gemini / Codex; счётчик
  пар; удержанная пара; «Прервать», «Остановить», новая задача; сдвиг версии
  при замечаниях и при принятии; `taskTokenLimit` по трём.
- Модули: правила в `settings.json` (нет, частично, сломанный JSON) и
  «Добавить правила» (сохраняет содержимое, без повторов); запись `agent.md`
  идемпотентна; поиск `agy`; разбор `agy models` и `/usage`; перенос
  `rooms.gemini_conversation`.
- Интерфейс в безголовом браузере: ромбы и «не проверял», вилка во всех
  состояниях, пять режимов, карточка «Моделей» и её высота, светлая тема.
- Правило имён (AGENTS.md): новые имена английские, код в строках размечен.

**Живые пробы** (`scripts/*-probe.mjs`, тратят квоту):

- `live-probe.mjs` — каталог моделей Gemini, ход, продолжение, `/usage`.
- Только чтение в настоящей папке проекта: просьба записать файл и выполнить
  команду — явный отказ, снимок версии до и после совпадает.
- `excludeDefaultComponents` с явным путём и без — выбор по итогу.
- `e2e-probe.mjs --gemini` — полный цикл с настоящими Claude, Codex, Gemini на
  ML-задаче с подложенной утечкой (масштабирование до разбиения, общий `id` в
  train и test): Gemini находит её чек-листом, Claude исправляет, вторая
  проверка пары принимает, дорожка и расход верны.

**Документация:** README (требование `agy` со входом, настройки, проблемы
«регион» и «нет правил»), `docs/устройство.md` (словарь: пара, сведение, «не
проверял»; адаптер Gemini; проверенные основания), история изменений.

Запуск расширения в окне VS Code — за владельцем; до его проверки это
остаётся в ограничениях README.

## Вне рамок

- Gemini как исполнитель или второй пишущий агент.
- Модели Claude и GPT из каталога `agy` в карточке Gemini.
- API-ключ Gemini.
- Выключатель Gemini в комнате: нет `agy` — нет Gemini.
- Обход проверки региона.
