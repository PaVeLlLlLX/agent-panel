# Agent Panel

Общая комната для человека, Claude Code и Codex: один поток разговора,
действия обоих агентов и рецензирование с привязкой к версии файлов.

Инструмент самостоятельный. Он сделан для проекта Trading, но ни к нему, ни
к какой-либо предметной области не привязан.

## Зачем

До него взаимодействие выглядело так: человек читает ответ одного агента,
копирует его второму, читает ответ второго, копирует обратно. Кроме
неудобства это ещё и теряет главное — **сырой вывод инструментов**. Передавая
пересказ, человек невольно подменяет измерение мнением. В проекте Trading это
однажды привело к тому, что рецензент принял неверную величину, выведенную из
чужого пересказа, и ошибочный вердикт прожил двое суток.

## Как отправить сообщение

Под полем ввода выбирается, **как** отправить:

| Режим | Что происходит |
|---|---|
| **Задача с рецензией** | Claude выполняет, Codex проверяет — строго по очереди, пока рецензент не примет работу |
| **Спросить обоих** | оба отвечают независимо, друг другу ничего не передаётся |
| **Только Claude** / **Только Codex** | прямой вопрос одному, без пересылки |

Режимы разные по смыслу намеренно. В первой версии сообщение уходило обоим
сразу, ответы расходились по времени, и в живом прогоне Claude спорил с
замечанием, которое Codex уже отозвал за пять секунд до этого.

### Цикл рецензии

1. Claude получает задачу и работает.
2. Codex получает **задачу человека, реплики Claude и сырой вывод его
   инструментов** и заканчивает проверку строкой `ВЕРДИКТ: ПРИНЯТО` или
   `ВЕРДИКТ: ЕСТЬ ЗАМЕЧАНИЯ`.
3. «Принято» — цикл завершён. «Есть замечания» — работа возвращается Claude.

Цикл кончается **по итогу, а не по счёту**. Предел проверок
(`agentPanel.maxAutoRounds`) остаётся ограничителем расходов.

### Недоставленное удерживается, а не теряется

Пересылка не уходит, но и не пропадает, если:
- рецензент не вынес вердикт;
- достигнут предел проверок — работа Claude осталась непроверенной;
- выключены автораунды.

Вверху панели появляется причина и кнопка «Отправить». Решение за человеком.

Новая задача отменяет пересылки прежней, и панель говорит, сколько
устаревшего не доставлено.

## Что видно в панели

- **Строка состояния**: чей ход, сколько проверок из предела, вердикт,
  очередь, текущая задача.
- **Беседа** на всю ширину. Действия агента за ход — одна свёрнутая строка
  «Claude · 9 команд, 2 чтения, 3 записи в память», подробности и сырой вывод
  по клику. В первой версии отдельная колонка действий занимала пол-панели.
- **Сообщения панели** подписаны «Панель», а не «Вы».
- **Диагностика** внизу, свёрнута: логи процессов агентов, запуск и
  остановка. В первой версии служебный лог Codex показывался красной репликой
  с цветовыми кодами терминала.

Состояния вызова инструмента различаются цветом: `вызов сформирован`,
`выполняется`, `результат получен`, `отказано`. Завершение генерации
аргументов — ещё не выполнение.

## Как устроено

Панель **владеет** обеими сессиями: подписка на поток уже работающей вкладки
по идентификатору не гарантирована, а у истории должен быть один управляющий
процесс. Штатное расширение Claude остаётся для одиночной работы.

```
┌───────────────────────────────────────────────┐
│ Панель VS Code (webview)                      │
│   состояние · беседа · диагностика            │
├───────────────────────────────────────────────┤
│ Координатор                                   │
│   маршруты, цикл рецензии, вердикт,           │
│   удержание, очередь, снимки версий           │
├───────────────────┬───────────────────────────┤
│ Адаптер Claude    │ Адаптер Codex             │
│ CLI stream-json   │ app-server JSON-RPC       │
└───────────────────┴───────────────────────────┘
```

Журнал — SQLite через встроенный `node:sqlite`, нативная сборка не нужна.

**Агенты запускаются при первом сообщении**, а не при открытии панели. В
живом прогоне сессия Claude создавалась просто оттого, что панель открыли в
другой папке.

**Claude запускается без ваших пользовательских настроек**
(`--setting-sources project,local`). Иначе в его сессии срабатывают ваши
глобальные хуки: в тестовом прогоне Stop-хук памяти пришёл как реплика, и
панель записала две заметки в хранилище, о которых никто не просил.
Проверено запуском: с флагом событий хуков ноль, вход по подписке работает.
`--bare` не годится — он не читает OAuth.

### Каждый ход знает, зачем он

Цель хода — работа в цикле, проверка в цикле или прямой вопрос —
записывается при отправке и снимается при завершении. Иначе ответ на
мимоходный вопрос ушёл бы рецензенту как работа по задаче.

### Проверенные основания, а не предположения

| Что | Как установлено |
|---|---|
| Формат потока Claude | запуск `claude -p --output-format stream-json` и разбор наблюдённых записей |
| Многоходовость через stdin | две реплики подряд, вторая вспомнила число из первой |
| Протокол Codex | `codex app-server generate-json-schema --out DIR`; оттуда `thread.id`, `turn.status`, `agentMessage.text`, `item/agentMessage/delta` |
| Хуки в дочерней сессии | запуск с `--setting-sources project,local` и без |

### Привязка к версии файлов

Каждое событие помечается отпечатком рабочего дерева: коммит, хеш diff
отслеживаемых файлов и хеши **содержимого** неотслеживаемых. Снимок закреплён
за ходом агента, поэтому чужая реплика посреди проверки не переписывает
версию идущего хода.

## Разделение ролей: что обеспечено и что нет

**Запись файлов рецензенту запрещена, и это проверяемо.** Ветка Codex
создаётся с `sandbox: "read-only"` и `approvalPolicy: "never"`, а на любой
запрос одобрения панель отвечает отказом — это проверено тестом на
фальшивом сервере.

**Запрет запуска команд технически НЕ обеспечен.** Read-only сам по себе
выполнение не запрещает, а инструкция рецензенту — просьба, не гарантия.

## Запуск

**1. Один раз: поставить зависимости и собрать.**

```
cd C:\Users\21435\source\agent-panel
npm install
npm test
```

`npm test` собирает проект и гоняет 66 проверок без VS Code: правила
координатора на заглушках и **адаптеры на фальшивых процессах**, которые
воспроизводят записанный протокол Claude и схему Codex.

**2. Открыть в VS Code ИМЕННО папку `agent-panel`** — `launch.json` лежит там.

```
code C:\Users\21435\source\agent-panel
```

**3. Нажать F5.** Откроется **второе окно** с «Extension Development Host» в
заголовке; папка Trading в нём откроется сама.

**4. Во втором окне** `Ctrl+Shift+P` → **Agent Panel: открыть комнату**.

### Если не получилось

| Что видно | Причина |
|---|---|
| F5 запускает не то или ничего | открыта не папка `agent-panel` |
| в палитре нет «Agent Panel» | команда ищется в первом окне, а не во втором |
| «нужна открытая папка» | в окне расширения нет папки; откройте любую |
| «Claude не запустился» | `claude` не в PATH у VS Code; полный путь в `agentPanel.claudeCommand` |
| «Codex не запустился» | то же для `agentPanel.codexCommand` |
| действия Claude отклоняются | ожидаемо: канала согласования ещё нет |

Ошибки расширения — **Debug Console** в первом окне; ошибки панели —
«Developer: Open Webview Developer Tools» во втором; логи агентов — раздел
«Диагностика» внизу панели.

## Настройки

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `agentPanel.claudeCommand` | `claude` | исполняемый файл Claude Code |
| `agentPanel.codexCommand` | `codex` | исполняемый файл Codex |
| `agentPanel.maxAutoRounds` | `3` | предел проверок рецензентом на задачу; 0 — каждую пересылку отправляете вы |
| `agentPanel.claudeSettingSources` | `project,local` | какие настройки загружает Claude панели; пустая строка — все, включая ваши хуки |
| `agentPanel.claudePermissionMode` | `default` | режим разрешений Claude; при `default` действия, требующие одобрения, отклоняются |

## Чего ещё нет

**Канала согласования действий Claude.** Панель не показывает запросы
одобрения и не принимает на них ответы; при `claudePermissionMode = default`
такие действия отклоняются. Молча принимать правки за владельца нельзя.
Правильное решение — `canUseTool` или `--permission-prompt-tool` с кнопками.

**Живой проверки новой версии в окне.** Адаптеры проверены на фальшивых
процессах, координатор — на заглушках; прежняя версия проверена вживую
14 сентября. Новый порядок разговора в настоящем окне с настоящими агентами
ещё не прогонялся.

Кроме этого: одна комната на окно; сессия Codex, открытая в терминале, не
подхватывается — у неё блокировка писателя.

## История исправлений

### По разбору рецензента

| Дефект | Следствие | Как закрыт |
|---|---|---|
| `thread/start` возвращает `thread.id`, код читал `threadId` | первая отправка падала | имена из схемы; тест на фальшивом сервере |
| тип элемента `agentMessage`, код искал `agent_message` | ответ рецензента отбрасывался | имена из `ThreadItem` |
| не было обработчика `item/agentMessage/delta` | поток рецензента не показывался | обработчик дельт |
| один накопитель на двух агентов | подмена авторства реплик | накопители по агенту |
| очередь выгружалась с конца | обратный порядок сообщений | порядок поступления |
| «Прервать» выключало Claude насовсем | «адаптер не запущен» | перезапуск с `--resume` |
| новые файлы входили в отпечаток только именами | правка не меняла версию | хеши содержимого |
| `session_id` сохранялся до появления | старая история с новой сессией | обратные вызовы `onSessionId` |
| полный вывод терялся за обрезкой | окончание вывода недоступно | поле `raw` в журнале |
| `npm test` искал файлы другого расширения | заявленные тесты не запускались | штатное обнаружение |

### По живому прогону 14 сентября

Журнал комнаты сохранил 1 850 событий за 9 минут; всё ниже установлено по
нему и по транскрипту сессии, а не по впечатлению.

| Что увидели | Причина | Как закрыто |
|---|---|---|
| Claude спорил с уже отозванным замечанием | «Оба» + параллельные ходы + очередь | три маршрута, строгая очерёдность в рецензии |
| проверка посреди обмена осталась без ответа | цикл кончался только по счёту | вердикт рецензента, удержание недоставленного |
| «Предел раундов» подписан «Вы» | служебное от имени человека | автор `system`, подпись «Панель» |
| красная реплика с `[2m…[0m` | stderr Codex как ошибка беседы | диагностика, цветовые коды вычищаются |
| пол-панели под действиями | карточка на каждый вызов | одна строка на ход, подробности по клику |
| две заметки в хранилище, пробный файл в репозитории | глобальные хуки в сессии панели | `--setting-sources project,local` |
| сессия Claude от простого открытия панели | запуск при открытии | запуск при первом сообщении |
| «процесс завершился: SIGTERM» при закрытии | плановая остановка как авария | остановка — диагностика |

И найдено по ходу, до падения: без обработчиков `error` на процессе и stdin
ненайденная команда или запись в умерший процесс роняли хост расширений
VS Code целиком. Закрыто, есть тесты для обоих адаптеров.
