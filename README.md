# Agent Panel

Расширение VS Code для работы одновременно с Claude Code, Codex и Gemini. Все
три агента отвечают в одной ленте, их действия видны там же. Codex и Gemini
могут проверять работу Claude: Codex — код, по сырому выводу команд Claude и
сам читая репозиторий, Gemini — методологию эксперимента и факты вне
репозитория.

Панель не привязана к конкретному проекту или языку: агенты работают в папке,
открытой в окне VS Code.

## Возможности

- Пять режимов отправки: задача с рецензией, вопрос всем агентам, только
  Claude, только Codex, только Gemini.
- Цикл рецензии: Claude выполняет задачу, затем Codex и Gemini проверяют её
  параллельно и независимо — Codex проверяет код, Gemini — методологию
  эксперимента и факты вне репозитория; итог — строже из двух вердиктов. При
  замечаниях работа возвращается к Claude. Сбой Gemini не останавливает
  работу: итог тогда — по вердикту Codex. Число проверок ограничено.
- Codex и Gemini получают сырой вывод команд Claude в пределах бюджета
  проверки (`agentPanel.reviewEvidenceChars`). Длинный вывод передаётся
  началом и концом с пометкой «неполный»; полный остаётся в журнале панели.
  Каждое замечание помечено версией файлов, которую рецензент проверял.
- Рецензенты проверяют свои утверждения сами. Codex читает репозиторий
  командами. С включёнными проверками рецензентов Codex пишет и запускает
  свои скрипты в папке вне проекта, а скрипты Gemini выполняет панель. Выводы
  приходят Claude свидетельством. Пути с данными и секретами проекта
  рецензентам запрещены ролью, а команду Codex с таким путём останавливает
  стоп-сигнал.
- При «принято» итог проверки и отзывы рецензентов уходят Claude с вашим
  следующим сообщением.
- Запросы разрешений и вопросы Claude приходят в ленту карточками с кнопками.
- Модель и уровень рассуждения выбираются отдельно для каждого агента.
- Можно продолжить уже существующую сессию Claude Code. У рецензента Codex
  своя ветка на комнату.
- К сообщению можно автоматически прикладывать заметки из памяти проекта.
- Расход токенов по задаче и доля недельных лимитов агентов.
- Всё, что происходит в комнате, записывается в локальный журнал: в том числе
  ваши действия, полный материал рецензентам и расход каждого хода.

## Требования

- VS Code 1.90 или новее. Журнал хранится во встроенном модуле `node:sqlite`,
  поэтому среда расширений VS Code должна работать на Node.js 22.5 или новее.
  Проверено на VS Code 1.139.
- Node.js 22.5 или новее и npm — для сборки.
- Claude Code с выполненным входом: расширение Claude Code для VS Code или CLI
  `claude` в `PATH`.
- Codex с выполненным входом: расширение ChatGPT для VS Code или CLI `codex` в
  `PATH`.
- Antigravity CLI (`agy`) со входом аккаунтом Google — по желанию, для Gemini.
  Установка: `irm https://antigravity.google/cli/install.ps1 | iex`, затем
  `agy` и вход. Без него проверяет один Codex.
- Git желателен, но не обязателен: без него версия файлов считается по их
  содержимому.

Панель проверялась на Windows 10. На macOS и Linux она не запускалась.

## Установка

Если у вас уже есть собранный пакет `agent-panel.vsix`:

```
code --install-extension agent-panel.vsix
```

Сборка из исходников:

```
git clone https://github.com/PaVeLlLlLX/agent-panel.git
cd agent-panel
npm install
npm run package
code --install-extension agent-panel.vsix --force
```

После установки перезагрузите окно: `Ctrl+Shift+P` → «Developer: Reload Window».

Чтобы обновить панель, получите новую версию (`git pull`), снова выполните
`npm run package` и установку с `--force`, затем перезагрузите окно.

## Первый запуск

1. Откройте в VS Code папку проекта. Агенты работают в первой папке окна.
2. Нажмите `Ctrl+Shift+P` и выберите «Agent Panel: открыть комнату».
3. Напишите задачу и отправьте её. По умолчанию выбран режим «Задача с
   рецензией».

Агенты запускаются при первом сообщении, а не при открытии панели. Комната
привязана к папке: если открыть её снова, панель продолжит те же сессии агентов.

Какие программы запускаются:
- **Claude** — `claude` из расширения Claude Code, та же версия, что в вашем чате
  Claude Code; если расширения нет, `claude` из `PATH`.
- **Codex** — `codex` из расширения ChatGPT; если расширения нет, `codex` из
  `PATH`.
- **Gemini** — `agy` из `%LOCALAPPDATA%\agy\bin`, иначе из `PATH`. При первом
  открытии панель попросит добавить правила «только чтение» в настройки `agy`
  (плашка «Добавить правила»): они запрещают Gemini запись и команды и
  разрешают чтение страниц. Правила общие — действуют и в интерактивном `agy`.

Явный путь в настройках `agentPanel.claudeCommand`, `agentPanel.codexCommand` и
`agentPanel.geminiCommand` важнее остальных вариантов.

## Работа с панелью

### Режимы отправки

Режим выбирается переключателем в поле ввода.

| Режим | Что происходит |
|---|---|
| Задача с рецензией | Claude выполняет задачу, затем Codex и Gemini проверяют её параллельно, строго по очереди с Claude |
| Спросить всех | все агенты отвечают независимо, друг другу ничего не передаётся |
| Только Claude | вопрос одному Claude, без проверки |
| Только Codex | вопрос одному Codex |
| Только Gemini | вопрос одному Gemini; виден, когда найден `agy` |

Чтобы рецензенты проверили коммит или результат команды, используйте «Задачу
с рецензией». Codex читает репозиторий сам (`git show`, `rg`), но запусков
Claude не повторяет: о тестах и расчётах он судит по их сырому выводу. Gemini
команд не запускает и тоже видит вывод команд Claude; вдобавок он может
читать страницы в сети.

### Цикл рецензии

1. Claude получает задачу и выполняет её.
2. Codex и Gemini получают вашу задачу, ответы Claude и сырой вывод его команд
   и проверяют параллельно и независимо — одна проверка — пара: Codex код,
   Gemini методологию эксперимента и факты вне репозитория. Вывод передаётся в
   пределах бюджета `agentPanel.reviewEvidenceChars`: у каждого вывода в
   заголовке указано «полный» или «неполный» с числом показанных символов.
   Полный текст хранится в журнале (поле `raw` таблицы `events`); если он нужен
   рецензенту, тот просит об этом вас. Сколько ждать Gemini после ответа
   Codex, зависит от вердикта Codex. Codex нашёл замечания — Gemini ждут
   `agentPanel.geminiWaitMinutes` (по умолчанию 20) минут, потом Claude
   получает замечания одного Codex; живой Gemini по этому сроку не
   останавливается, и его поздний отзыв добавляется к замечаниям, если они
   ещё ждут вашего решения, иначе виден в ленте. Codex принял работу или
   просит решения — Gemini ждут, пока он работает, но не дольше 45 минут:
   тогда процесс останавливается. Оба срока считаются от ответа Codex, даже
   если материал дошёл до Gemini позже (ждал за вашим прямым вопросом). При
   любом вердикте Codex Gemini, 6 минут не подававший признаков жизни,
   считается зависшим, и процесс останавливается (при замечаниях Codex —
   раньше их срока). Предел в 45 минут после ответа Codex действует при
   любом вердикте, даже если `agentPanel.geminiWaitMinutes` больше него.
   Опоздавший Gemini, который проверяет после срока при замечаниях, тоже
   останавливается по 6 минутам молчания или через 45 минут после ответа
   Codex — без нового итога, чтобы не держать ваши вопросы к нему; сторож
   действует сразу, и пока итог ещё сводится. Остановленный Gemini — «не проверял», итог по вердикту
   Codex. Пока Gemini ждут, «Эстафета» показывает «срок ЧЧ:ММ».
3. Итог сводится по правилу «строже побеждает»:

   | Если | То |
   |---|---|
   | хоть один рецензент просит решения человека или не вынёс вердикт | панель ждёт вас |
   | иначе хоть у одного есть замечания | работа возвращается к Claude с обоими отзывами |
   | иначе | принято, цикл завершён |

При «принято» Claude отдельного сообщения не получает. Итог — строка
«Проверка N принята: …» и отзывы рецензентов как пометки без требования
исправлять — приходит в начале вашего следующего сообщения Claude (задачей,
«Только Claude» или «Спросить всех»), один раз. В ленте при этом строка «К
сообщению Claude приложен итог проверки N». Прямой вопрос Codex или Gemini
итог не забирает; «Остановить» и новая сессия Claude его сбрасывают.

Вердиктом каждого рецензента считается только последняя строка его ответа,
если она ровно одна из трёх: `ВЕРДИКТ: ПРИНЯТО`, `ВЕРДИКТ: ЕСТЬ ЗАМЕЧАНИЯ`,
`ВЕРДИКТ: НУЖНО РЕШЕНИЕ ЧЕЛОВЕКА`. Если вердикта нет, решение остаётся за вами.
Без `agy` пара не собирается — проверяет один Codex, как раньше. Если `agy`
закончил ход ошибкой, но ответ Gemini пришёл, отзыв входит в проверку с его
вердиктом, а ошибка видна уведомлением в беседе (и после перезапуска) и в
«Диагностике»; «не проверял» — только когда ответа нет.

Если ход проверки Gemini кончился сетевым сбоем (Bad Gateway, EOF, 502–504,
«unavailable», «connection reset», «timeout») без ответа, панель через минуту
один раз отдаёт ему тот же материал. Пока она ждёт повтора, Gemini считается
занятым этой проверкой: 6 минут молчания его не снимают, ваш прямой вопрос к
нему ждёт в очереди. Второй сбой — «не проверял … (повтор тоже не удался)».

Gemini проверяет по роли из `agent.md` панели. Правила проекта `agy` в режиме
панели сам не подаёт (проба 04.10), поэтому файл правил называет шапка каждого
сообщения панели: `[правила проекта: GEMINI.md]`, если он есть в корне папки
проекта, иначе `[правила проекта: AGENTS.md]`. Если в этом разговоре Gemini
ещё не открывал этот файл, он открывает его до ответа на любое сообщение — и
на проверку, и на ваш прямой вопрос. На прямой вопрос он отвечает без строки
вердикта. Методологию он проверяет чек-листом: утечки, разбиения, регистрация
(план до расчёта), метрики и статистика, бейзлайн, сиды и разброс,
обоснованность выводов. У каждого пункта — «свидетельство», «пробел» или «не
относится». Вывод «событий нет», который держится на поиске, — пробел, пока
разработчик не показал полноту поиска (источники, даты, все страницы выдачи,
цитата), даже при строгом коде проверок. Внешние факты Gemini подтверждает
открытой страницей первоисточника, дату проверки берёт из строки `[дата: …]` в
шапке сообщения панели; к вебу — не больше 15 обращений за проверку. Файлы он
читает только в папке проекта, секретов (`.env`, ключей) не открывает.
Правила, нужные только Gemini, кладите в `GEMINI.md`: Codex и Claude этот файл
не читают.

Число проверок на одну задачу задаёт `agentPanel.maxAutoRounds` (по умолчанию
5); проверка пары считается одной проверкой. Прогресс цикла виден в строке
статуса вверху; по щелчку раскрывается дорожка со всеми передачами и расходом
токенов.

### Когда панель ждёт вас

Панель не передаёт работу дальше, а показывает над полем ввода причину и
кнопку, если:

| Причина | Кнопка |
|---|---|
| Claude получил отказы в разрешениях, и работа не сделана | «Повторить Claude» |
| рецензент просит вашего решения или не вынес вердикт | «Отправить Claude» |
| достигнут предел проверок, работа осталась непроверенной | «Отправить на проверку» (без Gemini — «Отправить Codex») |
| автопересылка выключена | «Отправить» тому, кому предназначено |

Флажок «Автопересылка» под полем ввода управляет тем, передают ли агенты работу
друг другу сами.

Если решения просит один рецензент, причина называет и исход второго,
например «Gemini просит вашего решения; Codex решения не просит (вердикт:
принято)». Нажатие «Отправить…» и переключение автопересылки записываются в
журнал и видны в ленте строкой «Вы: …».

### Проверки рецензентов

Рецензенты проверяют свои утверждения сами, а не просят Claude
«пересчитать».

**Всегда.** Codex читает репозиторий командами: `rg`, `git log/show/diff`,
`python -c` над кодом. Его ветка работает в песочнице «только чтение», файлы он
не меняет. Роль запрещает ему сеть, долгие и фоновые процессы и пути из
настройки `agentPanel.reviewerForbidden` — данные и секреты проекта. Если
команда Codex в ходе проверки называет такой путь, панель прерывает его ход и
останавливает проверку: «Codex обратился к запрещённому пути «data/» —
проверка остановлена, решите, как продолжить». Gemini при этом не
останавливается: его отзыв виден в ленте, но в итог не идёт. В ответе на ваш
прямой вопрос такая команда даёт только строку-предупреждение.

**Скрипты — по выключателю.** Включите настройку `agentPanel.reviewerChecks`,
и под полем ввода рядом с «Автопересылкой» станет доступен переключатель
комнаты «Проверки рецензентов». С ним, со следующего хода:
- Codex пишет и запускает свои скрипты в папке проверок
  `%LOCALAPPDATA%\agent-panel\review\<папка проекта>-<хеш>\codex\`; ссылка
  «Папка проверок» открывает её. Запись в проект ему закрыта песочницей
  Codex, проект он читает по абсолютным путям.
- Gemini подкрепляет утверждение, которое проверяется вычислением, блоком
  «проверка» — скриптом на Python, не больше трёх в ответе. Панель выполняет
  каждый в песочнице Codex, в соседней папке `…\gemini\`, не дольше
  `agentPanel.reviewerCheckSeconds` секунд, и тем же разговором отдаёт Gemini
  вывод. Итог Gemini в паре — вердикт его ответа на вывод. Скрипт с
  запрещённым путём не запускается. Круг один: новые блоки во втором ответе не
  выполняются.

Команды и выводы рецензентов видны в ленте и журнале. Claude получает их
вместе с замечаниями блоком «Проверки рецензента …» с пометкой «скрипты
рецензента — свидетельство; не запускай их»: каждый вывод — до 4000
символов, весь блок — до 20 000.

Перед каждым запуском процесса Codex и перед каждым скриптом Gemini панель
проверяет песочницу: запись в папку проверок должна пройти, запись в проект —
быть отклонена. Не прошла или Codex не принял профиль прав — Codex проверяет
в режиме «только чтение», скрипты Gemini не выполняются, а в ленте строка с
причиной. Самопроверке Codex нужен `python` в `PATH`; скрипты Gemini идут на
Python из `.venv` проекта, если он есть, иначе тоже на `python` из `PATH`.

Папка проверок хранится между проверками, панель её не чистит. Если она
больше 500 МБ, при запуске Codex в ленте строка; старые скрипты удаляйте сами.

Чтение и сеть песочница Codex на обычной установке не закрывает — см.
«Ограничения».

### Разрешения Claude

По умолчанию Claude работает без вопросов. Кнопка со щитом в поле ввода
переключает режим на «спрашивать»; выбор запоминается для папки. В этом режиме
действия, которым нужно ваше согласие, приходят в ленту карточками:

| Кнопка | Что происходит |
|---|---|
| Разрешить | этот вызов, один раз |
| В этой сессии | этот вызов и такая же команда до остановки Claude; в файлы настроек ничего не пишется |
| Больше не спрашивать | этот вызов и режим «без вопросов» для папки |
| Отклонить | отказ; Claude узнаёт, что отказал человек |

Вопрос Claude (инструмент `AskUserQuestion`) приходит карточкой «Claude
спрашивает» и в режиме «без вопросов». В ней варианты ответа (если можно
выбрать несколько — флажками) и поле «Свой ответ»: свой текст важнее
выбранных вариантов. «Ответить» становится доступна, когда есть ответ на
каждый вопрос; «Не отвечать» сообщает Claude, что вы не стали отвечать. Пока
вопрос открыт, «Эстафета» показывает «Ждёт ответа на вопрос»; «Прервать» и
«Остановить» закрывают карточку. Другие запросы, которые Claude отдаёт только
человеку, режим «без вопросов» тоже не разрешает — они приходят обычной
карточкой.

Codex файлы проекта не меняет: его ветка работает в песочнице «только
чтение», а с проверками рецензентов Codex пишет только в свою папку проверок.
Gemini подчиняется правилам «только чтение» в настройках `agy`: запись файлов
и команды ему запрещены.

### Модели и уровни рассуждения

Кнопка «Модели» в поле ввода открывает одну карточку: строка на агента (Claude,
Codex и, если найден `agy`, Gemini). Модель выбирается из списка, который
сообщает сам агент, уровень рассуждения — узлом на короткой нити строки;
название уровня видно при наведении на узел. Выбор действует со следующего
ответа и запоминается для папки; контекст сессии при этом сохраняется.

### Сессии агентов

Каждая комната помнит свою сессию Claude, ветку рецензента Codex и разговор
Gemini — поля `claude_session`, `codex_review_thread` и `gemini_conversation`
таблицы `rooms` журнала. Команды «Agent Panel: новая сессия Claude для
комнаты», «… Codex для комнаты» и «… Gemini для комнаты» начинают новую
сессию, а старая остаётся в истории агента; если прежней не было, панель так
и пишет. Лента панели при этом сохраняется. Ссылка «новая сессия…» в карточке
«Модели» делает то же самое и сама спрашивает, для какого агента.

Панель может продолжить и вашу собственную сессию Claude Code: её
идентификатор записывается в поле `claude_session`. Саму сессию нужно
закрыть: у одной сессии не должно быть двух пишущих сторон одновременно.

Ваш чат Codex панель с 05.10 не продолжает: у рецензента своя ветка на
комнату. Прежняя привязка к вашему чату (`codex_thread`) остаётся в журнале
историей; «новая сессия Codex» забывает и её, и ветку рецензента.

### Память проекта

Если задана команда `agentPanel.memorySearchCommand`, панель передаёт ей текст
каждого вашего сообщения и прикладывает найденные заметки агентам.
Протокол такой же, как у хука `UserPromptSubmit` Claude Code:
- на вход — JSON `{cwd, prompt}`;
- на выход — `hookSpecificOutput.additionalContext`.

В ленте видно, какие заметки приложены. Если поиск не уложился в 10 секунд или
упал, сообщение уходит без них.

Claude в панели запускается без ваших пользовательских настроек, поэтому ваших
MCP-серверов у него нет. Нужные серверы передайте файлом
`agentPanel.claudeMcpConfig` в формате `claude --mcp-config`.

### Прервать и остановить

«Прервать» останавливает текущие ответы и цикл рецензии; сессии сохраняются, и
следующее сообщение их продолжит. Сообщения, ждавшие в очереди, не отправляются.
«Остановить» вдобавок завершает процессы всех агентов вместе с запущенными ими
командами.

## Настройки

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `agentPanel.claudeCommand` | `claude` | исполняемый файл Claude Code; `claude` — взять из расширения Claude Code, иначе из `PATH` |
| `agentPanel.codexCommand` | `codex` | исполняемый файл Codex; `codex` — взять из расширения ChatGPT, иначе из `PATH` |
| `agentPanel.geminiCommand` | `agy` | исполняемый файл Antigravity CLI; `agy` — взять `%LOCALAPPDATA%\agy\bin\agy.exe`, иначе из `PATH`. Не найден — Gemini в комнате нет, проверяет один Codex |
| `agentPanel.geminiWaitMinutes` | `20` | сколько минут после ответа Codex ждать Gemini, если Codex нашёл замечания (Claude простаивает); живой Gemini по этому сроку не останавливается, но и опоздавшего снимают 6 минут молчания или 45 минут после ответа Codex. При принятии или просьбе решения Gemini ждут, пока он работает, до 45 минут — затем процесс останавливается. При любом вердикте Codex 6 минут молчания Gemini — процесс останавливается. Сроки — от ответа Codex |
| `agentPanel.maxAutoRounds` | `5` | сколько проверок разрешено на одну задачу; проверка пары Codex и Gemini считается одной; `0` — каждую передачу подтверждаете вы |
| `agentPanel.reviewEvidenceChars` | `240000` | сколько символов вывода команд уходит рецензентам за одну проверку; длинный вывод передаётся началом и концом с пометкой «неполный», полный остаётся в журнале |
| `agentPanel.reviewerForbidden` | `[".env"]` | части путей, которые рецензенты не открывают, — данные и секреты проекта; задаётся для папки проекта, например `["data/", "data\\", ".env"]`. Регистр и вид косой черты не важны, сравнение по границам имён: `data/` не ловит `metadata/`, `.env` не ловит `process.env`. Вписывается в роль Codex; команда Codex с таким путём в ходе проверки останавливает проверку, скрипт Gemini с таким путём не запускается |
| `agentPanel.reviewerChecks` | `false` | открывает переключатель комнаты «Проверки рецензентов»: с ним Codex пишет и запускает скрипты в своей папке проверок, а скрипты Gemini выполняет панель. Выключено — Codex только читает |
| `agentPanel.reviewerCheckSeconds` | `60` | сколько секунд даётся одному скрипту Gemini (не меньше 5); дольше — процесс снимается, Gemini получает «превышено время» |
| `agentPanel.taskTokenLimit` | `0` | предел токенов на задачу для всех агентов; при достижении передача ждёт вас; `0` — без предела |
| `agentPanel.memorySearchCommand` | пусто | команда поиска по памяти проекта |
| `agentPanel.claudeMcpConfig` | пусто | путь к JSON с MCP-серверами для Claude |
| `agentPanel.claudeSettingSources` | `project,local` | какие настройки загружает Claude; пустая строка — все, включая ваши пользовательские хуки |
| `agentPanel.claudePermissionMode` | `bypassPermissions` | режим разрешений Claude по умолчанию; `default` — спрашивать карточками |
| `agentPanel.claudeWeeklyUsage` | `true` | показывать долю недельного лимита Claude (панель спрашивает `claude -p /usage` не чаще раза в 5 минут) |

Настройки можно задать для пользователя или только для папки проекта
(`.vscode/settings.json`).

## Где хранятся данные

Журнал комнат — файл SQLite `agent-panel.sqlite` в хранилище расширения VS Code. На
Windows это `%APPDATA%\Code\User\globalStorage\local.agent-panel\`. Кроме реплик
и действий агентов журнал хранит ваши действия в панели, полный материал,
ушедший каждому рецензенту, и расход каждого хода. Сессии Claude и
ветки Codex хранят сами агенты: в `~/.claude` и `~/.codex`. Разговоры Gemini —
в `~/.gemini/antigravity-cli`; роль рецензента — файл панели
`~/.gemini/config/agents/agent-panel-reviewer/agent.md`.

Скрипты рецензентов лежат в папках проверок вне проекта:
`%LOCALAPPDATA%\agent-panel\review\<папка проекта>-<хеш>\codex\` и `…\gemini\`.
Панель их не чистит.

## Как это устроено

Панель сама запускает агентов и владеет их сессиями:
- Claude — CLI в режиме `stream-json` через стандартные ввод и вывод;
- Codex — `codex app-server` по JSON-RPC;
- Gemini — `agy` в режиме потока (`stream-json`), один процесс на много ходов.

Между ними координатор: маршруты сообщений, цикл рецензии, разбор вердикта,
очередь, отпечаток версии файлов. Интерфейс — webview в VS Code; разметка и формулы
(markdown-it, KaTeX) собраны в пакет и работают без интернета.

Подробнее — в [docs/устройство.md](docs/устройство.md). Что и почему менялось —
в [docs/история-изменений.md](docs/история-изменений.md).

## Разработка

```
npm install
npm test          # сборка и все проверки
npm run watch     # пересборка при изменениях
```

`npm test` собирает проект и запускает проверки без VS Code:
- координатор;
- разбор вердикта;
- адаптеры на поддельных процессах агентов;
- отрисовку разметки;
- интерфейс в безголовом Edge или Chrome.

Проверки интерфейса пропускаются, если браузер недоступен.

Для отладки откройте папку `agent-panel` в VS Code и нажмите F5: запустится второе
окно с расширением из исходников.

Скрипты `scripts/*-probe.mjs` запускают настоящих агентов вне VS Code: проверяют
каталоги моделей, разрешения, фоновые команды и полный цикл рецензии. Они тратят
токены ваших аккаунтов.

Код:

| Путь | Что там |
|---|---|
| `src/extension.ts` | точка входа, комната, связь с webview |
| `src/coordinator.ts` | маршруты, цикл рецензии, очередь |
| `src/adapters/` | запуск и протоколы Claude, Codex и Gemini, остановка процессов |
| `src/verdict.ts` | разбор вердикта рецензента |
| `src/journal.ts` | журнал SQLite |
| `src/snapshot.ts` | отпечаток версии файлов |
| `src/codexOptions.ts`, `src/reviewFolder.ts`, `src/checkBlocks.ts`, `src/checkRunner.ts` | проверки рецензентов: ветка Codex комнаты, папки проверок, блоки «проверка» Gemini и их запуск |
| `media/` | интерфейс панели |
| `test/` | проверки |

## Решение проблем

| Что видно | Что сделать |
|---|---|
| в палитре команд нет «Agent Panel» | установите пакет и перезагрузите окно |
| «нужна открытая папка» | откройте папку проекта |
| «Claude не запустился» | установите расширение Claude Code или укажите полный путь в `agentPanel.claudeCommand` |
| «Codex не запустился» | установите расширение ChatGPT или укажите полный путь в `agentPanel.codexCommand` |
| «Gemini не подключён» | установите `agy` или укажите путь в `agentPanel.geminiCommand` |
| «Gemini не проверял: … Eligibility check failed» | Antigravity отказал по региону; проверка идёт с одним Codex |
| плашка «Gemini нужен режим только чтения» | нажмите «Добавить правила»; если настройки `agy` не разбираются — исправьте `~/.gemini/antigravity-cli/settings.json` вручную |
| ответ падает с «does not support this model» | CLI агента старее модели сессии; используйте CLI из расширения (значения настроек по умолчанию) или обновите CLI |
| «ждёт вашего решения» с отказами | режим разрешений не позволяет спросить вас (например, `dontAsk`); переключите его на «спрашивать» |
| переключатель «Проверки рецензентов» недоступен | включите настройку `agentPanel.reviewerChecks` |
| «Песочница Codex не прошла проверку (…)» | Codex проверяет в режиме «только чтение», скрипты не пишет; подробности — в «Диагностике». Если причина — запись в папку проверок, проверьте, что `python` есть в `PATH` |
| «Codex обратился к запрещённому пути …» | проверка остановлена; решите, продолжать ли, — например, отправьте задачу снова. Список путей — `agentPanel.reviewerForbidden` |
| «Проверки Gemini недоступны: …» | скрипты Gemini не выполнились, он выносит вердикт без них. Причина — в той же строке: например, Codex не запустился или песочница не прошла самопроверку |
| «Папка проверок Codex занимает … МБ» | удалите старые скрипты из папки (ссылка «Папка проверок») |

Ошибки самого расширения видны в «Developer: Toggle Developer Tools», служебные
логи агентов — в разделе «Диагностика» внизу панели.

## Ограничения

- Одна комната на окно VS Code.
- Codex: команды чтения ему разрешены ролью. Песочница Codex на обычной
  установке («unelevated») запрещает только запись: чтение не ограничено
  (рецензент может прочитать `.env`), а сырой сокет выходит в сеть. Запрещённые
  пути закрыты правилом роли и стоп-сигналом; путь, который прочитал код
  проекта, а не сама команда (например, через импорт), стоп-сигнал не видит.
  Усиленная песочница Codex («elevated») не проверялась.
- Стоп-сигнал смотрит текст команды, а не то, что она открывает: поиск строки
  `data/` в коде (`rg "data/" src`) тоже останавливает проверку, а скрипт
  Gemini, где `data/` упомянут хотя бы в комментарии, не запускается.
- Фоновый процесс, который Codex оставил после своей команды, переживает и
  ход, и остановку Codex; панель его не ищет. После скриптов Gemini панель
  снимает процессы, в командной строке которых есть путь папки проверок;
  процесс без этого пути так не найти.
- Проверки рецензентов (переключатель комнаты) живьём в панели не
  запускались. Профиль прав, самопроверка и ответы `command/exec` проверены
  пробой 05.10 вне панели (`docs/research/2026-10-05-проба-песочницы-codex.md`);
  запуск файла скрипта Gemini, его окружение и возврат ветки Codex к «только
  чтению» на настоящем Codex не проверены.
- Ответ на вопрос Claude уходит в форме из документации Agent SDK
  (`answers`); живьём с настоящим CLI эта форма не проверялась.
- «В этой сессии» не всегда снимает повторный вопрос: команды с
  перенаправлением вывода в файл Claude Code спрашивает снова.
- Доля недельного лимита Claude берётся из текста ответа `/usage`. Если Claude
  Code изменит формулировку, доля пропадёт, но не станет нулём.
- Остановка процессов на macOS и Linux написана, но не проверялась.
- Вывод инструментов Gemini в поток почти не попадает: в ленте видны только
  имя и параметры вызова.
- Расход Gemini берётся из `usage` шагов `agy`; что `input_tokens` включает
  чтение кеша — допущение, не проверенный факт.
- Правила «только чтение» запрещают только `write_file(*)` и `command(*)`;
  MCP-инструменты, которые подключены к `agy` отдельно (правило `mcp` в тех же
  настройках), ими не охвачены — если такие сервера настроены, запись через
  них не запрещена.
- Правило `deny` само блокирующим живьём под собственной настройкой агента
  панели не наблюдалось: и рецензент, и пробный агент с теми же `tools` сами
  не доходят до вызова `write_to_file`/`run_command` (подробности —
  `docs/research/2026-10-02-проба-agy.md`, раздел I4). Отказ на самом правиле
  показан только на `agy` без агента панели.
- Окно VS Code с подключённым Gemini живьём не проверялось — до проверки
  владельцем.
- Срок молчания Gemini (6 минут) стоит на одном прогоне на модель (04.10):
  наибольшее молчание — 34,6 с у Flash high и 23,4 с у Pro high. Долгий
  ответ без инструментов (ваш прямой вопрос) не замерялся. Ход, снятый
  панелью, `agy` сохраняет в разговоре вместе с его запросом, поэтому
  следующее сообщение Gemini прямо говорит, что прошлый ход прерван и
  устарел.
- Роль Gemini проверена живьём одним повтором проверки Trading (04.10,
  `scripts/gemini-probe.mjs --timing`, вне панели). Flash high и Pro high
  первым делом открыли `GEMINI.md`, но полноты отрицательного поиска не
  потребовала ни одна модель. После этого роль поправлена; повтор с
  поправленной ролью не делался. Чек-лист оценки — в
  `docs/research/2026-10-02-проба-agy.md`.
