# Agent Panel

Общая комната для человека, Claude Code и Codex: один поток разговора,
действия обоих агентов и рецензирование с привязкой к версии файлов.

Инструмент самостоятельный. Он сделан для проекта Trading, но ни к нему, ни
к какой-либо предметной области не привязан.

## Зачем

До него взаимодействие выглядело так: человек читает ответ одного агента,
копирует его второму, читает ответ второго, копирует обратно. Кроме
неудобства это ещё и теряет главное — **сырой вывод инструментов**. Передавая
пересказ, человек невольно подменяет измерение мнением. В проекте Trading это
однажды привело к тому, что рецензент принял неверную величину, выведенную из
чужого пересказа, и ошибочный вердикт прожил двое суток.

## Как устроено

Панель **владеет** обеими сессиями. Это решение, а не случайность: подписка на
поток уже работающей вкладки по идентификатору сессии документально не
гарантирована, а у одной истории должен быть один управляющий процесс. Штатное
расширение Claude остаётся для одиночной работы.

```
┌───────────────────────────────────────────────┐
│ Панель VS Code (webview)                      │
│   беседа  |  действия обоих агентов           │
├───────────────────────────────────────────────┤
│ Координатор                                   │
│   маршрутизация, предел раундов, снимки версий│
├───────────────────┬───────────────────────────┤
│ Адаптер Claude    │ Адаптер Codex             │
│ CLI stream-json   │ app-server JSON-RPC       │
└───────────────────┴───────────────────────────┘
          │                    │
   claude -p --input-format    codex app-server
   stream-json …               (sandbox read-only)
```

Журнал — SQLite через встроенный `node:sqlite`, нативная сборка не нужна.

### Проверенные основания, а не предположения

| Что | Как установлено |
|---|---|
| Формат потока Claude | запуск `claude -p --output-format stream-json --include-partial-messages` и разбор наблюдённых записей |
| Многоходовость через stdin | две реплики подряд, вторая вспомнила число из первой; `session_id` один |
| Протокол Codex | `codex app-server generate-json-schema --out DIR`, формы запросов взяты из схемы |
| Песочница и одобрения | `SandboxMode = read-only \| workspace-write \| danger-full-access`, `AskForApproval = untrusted \| on-request \| never` |

### Три правила координатора

**Передаётся законченное, показывается всё.** Человек видит генерацию по мере
поступления; второму агенту уходят только законченные реплики, вызовы
инструментов и их сырые результаты. Пересылка дельт означала бы, что каждая
новая буква запускает очередной ответ.

**Сырой вывод, а не пересказ.** Рецензенту передаётся вывод инструмента
целиком, с пометкой «СЫРОЙ вывод». Это и есть причина существования панели.

**Раунды считаются и кончаются.** `agentPanel.maxAutoRounds` ограничивает
автоматический обмен; ноль означает «только вручную». Сообщение человека
сбрасывает счётчик: это новая задача.

### Различимые состояния

Завершение генерации аргументов вызова — это не выполнение инструмента.
Панель различает четыре состояния и показывает их цветом, а не только
словом: `вызов сформирован`, `выполняется`, `результат получен`, `отказано`.

### Привязка к версии файлов

Каждое событие помечается отпечатком состояния рабочего дерева: коммит, хеш
от diff отслеживаемых файлов и хеши **содержимого** неотслеживаемых. Снимок
закреплён за ходом агента, а не за комнатой, поэтому чужая реплика посреди
проверки не переписывает версию идущего хода. Если разработчик продолжил
правки после начала проверки, замечание относится к прежнему снимку, и это
видно. Без этого два агента спорят о разных состояниях кода, и спор выглядит
как разногласие по существу.

## Разделение ролей: что обеспечено и что нет

**Запись файлов рецензенту запрещена, и это проверяемо.** Ветка Codex
создаётся с `sandbox: "read-only"` и `approvalPolicy: "never"`. Плюс панель
отказывает на любой незнакомый запрос одобрения: неизвестное не разрешено.

**Запрет запуска команд технически НЕ обеспечен.** Режим read-only сам по себе
выполнение команд не запрещает, а инструкция в `developerInstructions` — это
просьба, а не ограничение. Пока не найден ключ конфигурации, отключающий
инструмент оболочки, ограничение остаётся незакрытым. Выдавать просьбу за
гарантию нельзя, поэтому оно здесь и написано.

## Запуск

```
npm install
npm test        # собирает и гоняет 23 проверки, без VS Code и без агентов
```

Затем **F5** в VS Code. Откроется отдельное окно Extension Development Host —
команду **Agent Panel: открыть комнату** надо выполнять **в нём**, а не в
исходном окне. Конфигурация запуска лежит в `.vscode/launch.json`, сборка
делается задачей `npm: build` перед запуском.

Нужна открытая папка: агенты запускаются в её каталоге.

`npm install` и `npm run build` сами по себе расширение в VS Code **не
устанавливают** — это только зависимости и компиляция.

## Настройки

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `agentPanel.claudeCommand` | `claude` | исполняемый файл Claude Code |
| `agentPanel.codexCommand` | `codex` | исполняемый файл Codex |
| `agentPanel.maxAutoRounds` | `3` | предел автоматических раундов; 0 отключает |
| `agentPanel.claudePermissionMode` | `default` | режим разрешений Claude; при `default` действия, требующие одобрения, отклоняются |
| `agentPanel.reviewerReadOnly` | `true` | отказывать рецензенту в записи |

## Чего ещё нет

**Канала согласования действий Claude — это главное незакрытое место.**
Claude запускается в режиме print, а панель не показывает запросы одобрения и
не принимает на них ответы. При `agentPanel.claudePermissionMode = default`
действия, требующие согласования, будут отклонены. Настройка позволяет задать
другой режим, но выбор осознанно оставлен человеку: молча принимать правки за
владельца нельзя. Правильное решение — реализовать `canUseTool` или
`--permission-prompt-tool` и показать кнопки в панели.

Кроме этого:

- Нескольких комнат: одна комната на окно.
- Подхвата сессии Codex, открытой в терминале. У неё стоит блокировка
  писателя, и вмешательство её сломало бы; панель создаёт свою ветку.
  Прочитать чужую историю можно через `thread/read` — он не возобновляет и не
  подписывает.
- **Живой сквозной проверки.** Проверено: протокол по схеме, форматы запуском
  CLI, правила маршрутизации 23 тестами на заглушках. НЕ проверено: что окно
  расширения открывается и оба агента отвечают; что ответ доходит в обе
  стороны на живых процессах; что перезапуск восстанавливает обе сессии.
  Пока это не сделано, панель — не рабочий MVP, а собранный и протестированный
  по частям прототип.

## История исправлений по отзыву рецензента

Первая версия была разобрана Codex, и разбор нашёл семь дефектов, из которых
четыре блокировали основной сценарий. Все исправлены, каждый закрыт проверкой.

| Дефект | Следствие | Как закрыт |
|---|---|---|
| `thread/start` возвращает `thread.id`, а код читал `threadId` | первая же отправка падала: «ветка Codex не создана» | имена взяты из схемы; то же для `turn.id` в `turn/started` |
| тип элемента `agentMessage`, а код искал `agent_message` | законченный ответ рецензента отбрасывался | имена типов из схемы `ThreadItem` |
| не было обработчика `item/agentMessage/delta` | поток рецензента не показывался | добавлены дельты сообщения и рассуждений |
| один накопитель на двух агентов | Codex мог получить свой же комментарий с подписью «от разработчика Claude» | накопители по агенту, тест на подмену авторства |
| очередь выгружалась с конца | отложенные сообщения приходили в обратном порядке | выгрузка в порядке поступления, тест на порядок |
| «Прервать ход» останавливало процесс без возможности продолжить | следующее сообщение получало «адаптер не запущен» | перезапуск с `--resume` по запомненной сессии |
| неотслеживаемые файлы входили в отпечаток только именами | правка нового файла не меняла версию | хеши содержимого, тест на правку нового файла |
| `session_id` сохранялся один раз после `start()` | после перезапуска старая история с новой сессией | обратный вызов `onSessionId` |
| полный вывод не хранился, текст обрезан до 64 000 | окончание большого вывода терялось | поле `raw` в журнале плюс `rawOf()` |
| отклонённый `turn/start` оставлял агента занятым | очередь вставала молча | снятие занятости при ошибке |
| выход процесса не отклонял ожидающие RPC | ожидание ответа от мёртвого процесса | отклонение всех ожиданий по `exit` |
| позднее событие обращалось к закрытой базе | падение при закрытии комнаты | журнал после закрытия молчит |
| `npm test` искал `test/*.test.ts`, а файл `.mjs` | заявление «тесты проходят» не проверялось этой командой | штатное обнаружение `node --test` |
| README предлагал F5 без `launch.json` | запуск не работал | добавлены `launch.json` и `tasks.json` |
